## 1. Decisions

### 1.1 Dependency: `gsap` 3.15.0 (exact)

- `npm install --save-exact gsap@3.15.0` (the current `latest`). ScrollTrigger ships in the same package (`gsap/ScrollTrigger`), so there is nothing else to add.
- The M2.2 §1.1 findings hold for this install: **no install script and no dependencies** (`npm approve-scripts --allow-scripts-pending` → "No packages with unreviewed install scripts"), so **`allowScripts` needs no entry** (it lists only packages with install scripts). `npm audit` stays at the baseline of **20** (4 moderate, 16 high, all pre-existing). Licence: "Standard 'no charge' license: https://gsap.com/standard-license", which covers commercial sites.
- Diff: `package.json` gains `"gsap": "3.15.0"` in `dependencies`, and `package-lock.json` gains the root entry and `node_modules/gsap` (7 lines, §2.2).
- GSAP is imported **only** by `components/home/home-reveals.ts`, which is loaded by a dynamic `import()` (§1.7). Nothing in the root layout or a shared component imports it.

### 1.2 Data flow, caching and tags

- `app/(site)/page.tsx` (a Server Component, static ○) calls **`getCollections()`** (M1.6, `lib/firebase/repositories/catalog.ts`): one cached query, `collections where status == "published" orderBy sortOrder`, served by the existing `collections (status, sortOrder)` composite index (`firestore.indexes.json`; `tests/unit/repository-indexes.test.ts` already covers the query). **No new query, no new index, no N+1:** one read for the whole band, and the images come from `/public`, not Storage (home.md §13, §14: `moodImage.src` is `/images/collections/…`).
- **Caching:** `getCollections` is `unstable_cache` with tag `collections` and `revalidate: false`, wrapped in React `cache()`. The page has no `searchParams`, cookies, headers or `export const revalidate`, so it prerenders at build and inherits the `collections` tag: M7's `updateTag("collections")` / `revalidateTag("collections", "max")` refreshes `/`. On-demand revalidation failure keeps the last good page (home.md §4.6). The page reads nothing else (the footer's "Our collections" group is still behind `features["collection-pages"]`, M3.7).
- **Projection:** `featuredCollections()` (`components/home/featured-collections.ts`, pure) caps the list at **6** in repository order (sortOrder, Gift Sets included, home.md §4.1) and keeps only the fields a card renders (`slug`, `name`, `tagline`, `isLimited`, `moodImage`; home.md §13). Unit-tested (§1.10).
- **Empty state (§4.6):** with no published collection the page renders no `#collections` section and passes `collections: false` to the hero, so "Explore collections" isn't rendered (the M2.2 `heroActions` rule, already unit-tested for that case).
- **UI never imports Firestore:** the page imports the cached repository; the components take plain `FeaturedCollection` data. The ESLint `no-restricted-imports` rule (M1.6) is unchanged and passes.
- The seed already writes the six collections with `moodImage { src, alt, 1744, 2336 }` (M1.8 §1.4); the `staticImage` schema only accepts `/images/…` paths, so `next/image` never sees a remote URL here.

### 1.3 Markup and layout (home.md §4.2–§4.4)

- **Band:** `components/home/FeaturedCollections.tsx` renders `<section id="collections" data-band="plain" data-reveal-section aria-labelledby="collections-heading">` → `Container` → the heading block (`<div data-reveal-head>` around `SectionHeading`) → `<ul class="collection-grid">`. It is a **direct child of `main`, a later sibling of the hero** (the M2.2 caveat 2): the page returns a fragment `<HomeHero/> <FeaturedCollections/> <HomeMotion/>`, and `HomeMotion` renders no element, so `main > [data-band]` is `#hero, #collections`.
- **Heading** (`SectionHeading`, unchanged): eyebrow "Our collections", h2 "Choose your kind of night" (`id="collections-heading"`), intro "Each collection gathers the scents of one place, from a moonlit terrace to a quiet lake." The copy is verbatim from home.md §4.2 / §11.1. The **section link** "See all collections" → `/collections` is passed only when the registry's `collections` row is live (`liveRoute("collections")`, a new 6-line helper in `site-routes.ts`); in M2 it is absent.
- **Card** (`components/catalog/CollectionCard.tsx`, a Server Component in `components/catalog/` so M3.7's collection index can reuse it): `<li data-reveal-item>` → the arch frame (`relative aspect-3/4 overflow-hidden rounded-arch bg-bg-raised`, i.e. `9999px 9999px 0 0`) holding the `<img>` (`fill`, `object-cover object-[50%_100%]`) and a decorative outline `<span aria-hidden data-decorative class="absolute inset-0 rounded-[inherit] border border-gold-400/40">` (the 1px gold-400 inset outline at 40%, over the image; `data-decorative` removes it in forced colors and print) → the text block (`mt-4`: 16px): the Limited badge (`mb-2`, 8px), `<h3 class="type-h4 text-text-primary">`, `<p class="mt-1 type-body text-pretty text-text-secondary">` (4px). That is exactly home.md §4.4's "span 2 of 4", `grid-cols-3`, "span 4 of 12" and "span 2 of 12" with the same gaps, so the card widths are the spec's: **167 / 218.7 / 298.7 / 186.7**. Short rows pack from the start.

With the e2e browser's 15px classic scrollbar gutter a 1440 window lays out in 1425px, so its cards are 184.2px wide (the test derives the width from the grid's own width).

### 1.4 Images: `getImageProps()` and a plain `<img>` (no client Image component)

- `CollectionCard` calls `getImageProps({ src: moodImage.src, alt, fill: true, sizes })` and renders `<img {...props}>`, as the hero already does. The `next/image` `<Image>` component is a client component: using it put its runtime in `/`'s page chunk: the first prototype build, with `<Image>`, had a 5,917 B gz page chunk and **196,422 B gz** of first-load JS on `/`; with `getImageProps` the page chunk is the 488 B `HomeMotion` island and the total 191,017 B, **5,405 B less**. `getImageProps` gives the same optimized `srcset`, `sizes`, `loading="lazy"`, `decoding="async"` and the `fill` style (`position:absolute; inset:0; width/height:100%; color:transparent`), with no JS. The only lint exception in the task is the `@next/next/no-img-element` disable on that line, with its reason (the rule ignores `<img>` only inside `<picture>`).
- `sizes` is home.md §4.4's string verbatim: `(min-width: 90rem) 187px, (min-width: 64rem) calc((100vw - 128px) / 3), (min-width: 48rem) calc((100vw - 112px) / 3), calc(50vw - 28px)`.
- **Lazy, never priority:** the hero stays the only eager / high-priority image (M2.2 e2e 4 still asserts exactly one). Served (warm optimizer, webp q75): **390 at DPR 3 → `w=640`** (needs 501px); **1440 at DPR 1 → `w=256`** (needs 184–187px). The e2e test asserts that the chosen candidate is the smallest `srcset` width covering the rendered width × DPR.
- **No blur placeholder:** the frame's bg-raised is the loading state (home.md §4.6), and a static-import map from data-driven slugs would break when M7 adds a collection. `moodImage.width/height` stay unused (`fill`).
- Alt text is `moodImage.alt` from the data (shot-list.json via the seed; home.md §10.4, §11.3); e2e checks all six strings.

### 1.5 Links: the M2 state (home.md §4.5)

- The cards render as content: no `<a>`, no `button`, no `tabindex`, no hover rule, cursor `auto`. e2e asserts all of it, and that a pointer hover changes neither the image's `scale`/`transform` nor the name's underline.
- **Decision: the M3.7 link variant is not built now.** home.md §14 suggests an `interactive` prop driven by `features["collection-pages"]`. That flag is a literal `false` (`as const`) until M3.7, and the `/collections/{slug}` routes don't exist, so the link branch would be dead code that no test can render without 404 prefetches (the M1.20 fixture fails on them). M3.7 adds the stretched link (`next/link` in the `<h3>`, `::after` covering the card, the ring on the pseudo-element, the 1.03 zoom under `--motion-scale-hover`, the underline) together with the routes and their tests. Nothing in the card's markup has to move for it: the `<h3>` takes the link and the frame is already `relative overflow-hidden`. Not a design deviation: home.md §4.5's M2 behaviour is exactly what ships.

### 1.6 Build preflight (the M1.8 hand-off)

- `/` is the first page that reads a repository at build, so **`prebuild` becomes `node scripts/build-preflight.mjs && node scripts/clear-data-cache.mjs`**, and `scripts/build-preflight.mjs` is added: the file in `design/tech/M1.8-seed.md` §2.3, with only its header comment updated to say it is live since M2.3.
- Verified in the scratch copy: with `.env.local` and no emulators, `npm run build` fails in under a second with "The Firestore emulator is not reachable on 127.0.0.1:6104. Start `npm run emulators` (and `npm run seed` once) in another terminal, then build again." Under `firebase emulators:exec --only firestore,storage "npm run seed && npm run build"` it passes, and `/` is ○ static with the six collections in its HTML.
- `npm run test:e2e` is unaffected (scripts/e2e.ts seeds, clears the data cache and runs `next build` itself, bypassing `prebuild`).
- **Consequence for the orchestrator's dev server and for plain builds:** a plain `npm run build` now needs `.env.local` plus `npm run emulators` + `npm run seed` (the CLAUDE.md note already says so from this task on). `next dev` on 3001 renders `/` only if it can reach a seeded Firestore emulator; without one the page's read fails (Next's dev error overlay), which is the expected M2.3 behaviour.

### 1.8 Motion: `HomeMotion` and the section reveals (home.md §9, motion.md §5, §6)

Three new modules, so the timing rules are unit-testable and GSAP stays out of the first-load JS:

- **`components/home/HomeMotion.tsx`** (`"use client"`, renders `null`): after the `load` event plus `requestIdleCallback` (2 s timeout; a 1.5 s `setTimeout` where it is missing, as the starfield loader does) it runs `import("./home-reveals")` and calls `startHomeReveals()`. Unmounting cancels a pending start or calls the returned stop function. It is the page's only client island and never touches the hero.
- **`components/home/home-reveals.ts`** (the lazy chunk; imports `gsap` and `gsap/ScrollTrigger`, `registerPlugin` once at module level):
  - `gsap.matchMedia()` with two branches. **`(prefers-reduced-motion: no-preference)`:** for each `[data-reveal-section]`, `arm()` it. **`(prefers-reduced-motion: reduce)`:** mark each section `static` and set nothing (motion.md §6.2: instant, no pre-hidden state).
  - `arm(section)`: under `html[data-motion="off"]` (M8.8b) → `static`, nothing set. If the section's top edge is already at or above 85% of the viewport (`needsReveal(top, innerHeight)` is false: in view at load, a reload mid-page, a fragment jump, an early scroll) → `skipped`, nothing set. Otherwise a paused timeline: `from()` the `[data-reveal-head]` block at 0 and the `[data-reveal-item]`s at **0.1 s**, both `opacity: 0, y: 16` (`DISTANCE.md`), `duration: 0.7` (`DURATION.slower`), `ease: "power3.out"` (`EASE.enter`), the items with `stagger: { amount: revealStagger(n) }` (60 ms apart, capped at 400 ms; `amount` only, never with `each`, motion.md §4), and `clearProps: "opacity,transform"`. The `from()` tweens render their start state at once: **that is the only pre-hide, and it happens only here.** Then `ScrollTrigger.create({ trigger: section, start: "top 85%", once: true, onEnter: play })` and the section is marked `pending`; the timeline's `onComplete` marks it `done`.
  - Everything is created inside the matchMedia context, so **a preference change mid-session or an unmount reverts it**: GSAP removes the inline styles it set and kills the triggers, and nothing stays hidden (e2e: switching to reduced motion while `pending` leaves every target at opacity 1 with no style).
  - `data-reveal-state` (`pending | done | skipped | static`) on each section carries no style. It tells the tests and the screenshot helper where a section stands, and that the lazy code has set up.
  - No scroll listeners of its own (ScrollTrigger's), no `will-change`, no `scrub` / `pin`, no hover zoom (M3.7). One trigger in M2.3; M2.4 and M2.5 add theirs by marking their sections (`data-reveal-section` / `-head` / `-item`); M2.5's opacity-only illustration will need one more marker, M2.5's call.
- **`components/home/reveal-plan.ts`** (pure, imports only `lib/motion/tokens`): `REVEAL_START = "top 85%"`, `ITEMS_OFFSET = 0.1`, `needsReveal(top, vh)` (`top > 0.85 × vh`) and `revealStagger(n)` (`min(0.4, (n − 1) × 0.06)`, rounded to ms). Unit-tested.
- **What a visitor sees:** at 390 × 664 the band starts below the fold (top ≈ 805px), so it is `pending` and plays when its top crosses 564px. At **1440 × 900 the band's top is at 731px, above the 765px line, so it is `skipped`**: its heading peeks in under the hero and is visible from the first paint, as motion.md §5 requires for content already on screen. Measured reveal order at 390: the cards start 83, 149, 216, 265, 332 and 399 ms after the heading block (expected 100 + 0…300 ms, at frame granularity).
- **CLS:** reveals move only `opacity` and `transform`, from the final layout position; every image box has an aspect ratio; e2e measures CLS 0 at rest and < 0.05 across the scrolled reveal (0 in practice).

**Test infrastructure (two fixes M2.3 needs; tech-owned files):**

1. **Image optimizer warm-up (`tests/e2e/global-setup.ts`, `globalSetup` in `playwright.config.ts`).** The first full run had one 30 s `page.goto("/")` timeout: two static chunks never answered. Cause, measured on `next start`: a cold `/_next/image` request runs sharp on libuv's small thread pool, which also serves static file reads, so **a static chunk took 3,864 ms next to 54 cold collection-image requests, 2,039 ms with `UV_THREADPOOL_SIZE=16`, and 34–48 ms once the images were cached.** Every worker loading `/` (the hero plus six 1744 × 2336 JPEGs) produced exactly that. #### `components/home/HomeMotion.tsx` (new)

```tsx
"use client";

import { useEffect } from "react";

/**
 * The home page's one motion island (home.md §9): renders nothing. After the
 * `load` event plus an idle callback (2s timeout; a 1.5s timer where there is
 * none), it imports the section reveals (home-reveals.ts, which brings GSAP and
 * ScrollTrigger in its own chunk) and starts them. So GSAP never competes with
 * the hero image and is never part of the route's first-load JS. Unmounting
 * (a navigation away) cancels a pending start or reverts the reveals. It never
 * touches the hero, whose entrance is CSS only (motion.md §5.1).
 */
export function HomeMotion() {
  useEffect(() => {
    let live = true;
    let idle = 0;
    let timer = 0;
    let stop: (() => void) | undefined;
    const start = () => {
      void import("./home-reveals").then(({ startHomeReveals }) => {
        if (live) stop = startHomeReveals();
      });
    };
    const afterLoad = () => {
      if (typeof requestIdleCallback === "function") {
        idle = requestIdleCallback(start, { timeout: 2000 });
      } else {
        timer = window.setTimeout(start, 1500);
      }
    };
    if (document.readyState === "complete") afterLoad();
    else window.addEventListener("load", afterLoad, { once: true });
    return () => {
      live = false;
      window.removeEventListener("load", afterLoad);
      if (idle) cancelIdleCallback(idle);
      clearTimeout(timer);
      stop?.();
    };
  }, []);

  return null;
}
```

#### `components/home/home-reveals.ts` (new)

```ts
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";

import { DISTANCE, DURATION, EASE } from "@/lib/motion/tokens";

import {
  ITEMS_OFFSET,
  needsReveal,
  REVEAL_START,
  revealStagger,
} from "./reveal-plan";

/**
 * The home section reveals (home.md §9, motion.md §5, §6): a separate chunk
 * that HomeMotion imports after `load` plus idle, so GSAP is never part of the
 * first-load JS. Registered once, here.
 *
 * Each `[data-reveal-section]` gets one ScrollTrigger (`top 85%`, once):
 * the `[data-reveal-head]` block, then its `[data-reveal-item]`s 0.1s later,
 * from opacity 0 and y 16px, 700ms power3.out, the items staggered 60ms
 * apart within 400ms. Pre-hidden states are set only in the no-preference
 * branch of gsap.matchMedia(), only for sections still below their start line
 * at setup, and never under html[data-motion="off"] (M8.8b). The hero is never
 * touched. When a reveal ends, GSAP clears the inline styles it set.
 *
 * `data-reveal-state` on each section (pending, done, skipped, static) tells
 * the e2e tests and screenshots where it stands; it carries no styles.
 */
gsap.registerPlugin(ScrollTrigger);

export type RevealState = "pending" | "done" | "skipped" | "static";

const NO_PREFERENCE = "(prefers-reduced-motion: no-preference)";
const REDUCE = "(prefers-reduced-motion: reduce)";

const sections = (): HTMLElement[] => [
  ...document.querySelectorAll<HTMLElement>("[data-reveal-section]"),
];

function mark(section: HTMLElement, state: RevealState): void {
  section.dataset.revealState = state;
}

function arm(section: HTMLElement): void {
  if (document.documentElement.dataset.motion === "off") {
    mark(section, "static");
    return;
  }
  if (!needsReveal(section.getBoundingClientRect().top, window.innerHeight)) {
    mark(section, "skipped");
    return;
  }
  const items = section.querySelectorAll("[data-reveal-item]");
  const from = {
    opacity: 0,
    y: DISTANCE.md,
    duration: DURATION.slower,
    ease: EASE.enter,
    clearProps: "opacity,transform",
  };
  // from() tweens render their start state at once: this is the pre-hide.
  const timeline = gsap
    .timeline({ paused: true, onComplete: () => mark(section, "done") })
    .from(section.querySelectorAll("[data-reveal-head]"), from, 0)
    .from(
      items,
      { ...from, stagger: { amount: revealStagger(items.length) } },
      ITEMS_OFFSET,
    );
  mark(section, "pending");
  ScrollTrigger.create({
    trigger: section,
    start: REVEAL_START,
    once: true,
    onEnter: () => {
      timeline.play();
    },
  });
}

/** Sets up every reveal on the page; the returned function undoes all of it. */
export function startHomeReveals(): () => void {
  const media = gsap.matchMedia();
  // Reverted (inline styles removed, triggers killed) when the preference
  // changes or on unmount, so nothing can stay hidden.
  media.add(NO_PREFERENCE, () => {
    for (const section of sections()) arm(section);
  });
  // Reduced motion: no pre-hidden state, no trigger; content is simply there.
  media.add(REDUCE, () => {
    for (const section of sections()) mark(section, "static");
  });
  return () => media.revert();
}
```

#### `components/home/reveal-plan.ts` (new)

```ts
import { STAGGER } from "@/lib/motion/tokens";

/**
 * The section-reveal rules (motion.md §4, §5; home.md §9) as plain values and
 * pure functions, so they are unit-tested in Node without GSAP or a browser.
 */

/** ScrollTrigger's start: the section's top edge at 85% of the viewport height. */
export const REVEAL_START = "top 85%";
const START_RATIO = 0.85;

/** The cards start this long after the heading block (seconds). */
export const ITEMS_OFFSET = 0.1;

/**
 * Whether a section gets a reveal when the reveal code sets up: only if its
 * start line is still ahead, that is its top edge is below 85% of the viewport.
 * A section already past it (in view at load, a reload mid-page, a fragment
 * jump, an early scroll) is left visible and gets no trigger.
 */
export function needsReveal(
  sectionTop: number,
  viewportHeight: number,
): boolean {
  return sectionTop > viewportHeight * START_RATIO;
}

/**
 * The cards' total stagger spread in seconds: stagger-base (60ms) between
 * cards, capped at stagger-max-total (400ms) for the whole group. Pass it as
 * GSAP's `stagger: { amount }` (never with `each`).
 */
export function revealStagger(count: number): number {
  const spread = Math.max(0, count - 1) * STAGGER.base;
  return Math.min(STAGGER.maxTotal, Math.round(spread * 1000) / 1000);
}
```

```ts
import { expect, type Page } from "@playwright/test";

/**
 * Resolves once HomeMotion's reveal code has set up (home-reveals.ts): every
 * `[data-reveal-section]` carries `data-reveal-state` (pending, done, skipped
 * or static). That happens after `load` plus idle (at most about 2 s later). A
 * page without reveal sections resolves at once. A readiness wait, not a budget.
 */
export async function revealsReady(
  page: Page,
  timeout = 15_000,
): Promise<void> {
  await page.waitForFunction(
    () =>
      [...document.querySelectorAll("[data-reveal-section]")].every((section) =>
        section.hasAttribute("data-reveal-state"),
      ),
    undefined,
    { timeout },
  );
}

/**
 * Plays every pending reveal: scrolls each pending section to the top of the
 * viewport (past its `top 85%` start line) and waits until it is done, then
 * scrolls back to the top and waits for the header to be at rest. For
 * full-page screenshots, which would otherwise show pre-hidden sections.
 */
export async function revealAll(page: Page): Promise<void> {
  await revealsReady(page);
  const ids = await page
    .locator('[data-reveal-state="pending"]')
    .evaluateAll((els) => els.map((el) => el.id));
  if (ids.length === 0) return;
  for (const id of ids) {
    const section = page.locator(`[id="${id}"]`);
    await section.evaluate((el) => el.scrollIntoView({ block: "start" }));
    await expect(section).toHaveAttribute("data-reveal-state", "done");
  }
  await page.evaluate(() => window.scrollTo(0, 0));
  await expect(page.locator("body > header")).not.toHaveAttribute(
    "data-scrolled",
  );
}
```

```ts
// 48 ms once they were cached. Playwright starts the webServer before this
// runs; the optimized files persist in .next/cache/images, so the second
// (@perf) pass finds them warm. Add a route here when it shows many images.
const ROUTES = ["/"];
/** Chromium's image Accept header: the optimizer caches per output format. */
const ACCEPT = "image/avif,image/webp,image/apng,image/*,*/*;q=0.8";
const PARALLEL = 4;

export default async function globalSetup(config: FullConfig): Promise<void> {
  const base = config.projects[0]?.use.baseURL;
  if (!base) throw new Error("[e2e] global setup: no baseURL");
  const urls = new Set<string>();
  for (const route of ROUTES) {
    const response = await fetch(new URL(route, base));
    if (!response.ok) {
      throw new Error(
        `[e2e] global setup: ${route} answered ${response.status}`,
      );
    }
    const html = await response.text();
    // Every candidate of every src / srcset attribute in the server HTML.
    for (const [, value] of html.matchAll(/\s(?:src|srcset)="([^"]+)"/gi)) {
      for (const candidate of value!.replaceAll("&amp;", "&").split(", ")) {
        const url = candidate.trim().split(" ")[0]!;
        if (url.startsWith("/_next/image?")) urls.add(url);
      }
    }
  }
  const queue = [...urls];
  const warm = async (): Promise<void> => {
    for (let url = queue.shift(); url; url = queue.shift()) {
      const image = await fetch(new URL(url, base), {
        headers: { accept: ACCEPT },
      });
      await image.arrayBuffer();
      if (!image.ok) {
        throw new Error(`[e2e] global setup: ${url} answered ${image.status}`);
      }
    }
  };
  const started = performance.now();
  await Promise.all(Array.from({ length: PARALLEL }, warm));

      (performance.now() - started) /
```
