## 1. Decisions

**Layout and purity.** `lib/types/` holds types and `as const` enums only. `lib/domain/` (new) holds pure logic: the parser kit, guards, `deriveProductFields`, the order state machine and email hashing. `lib/firebase/` holds converters, typed collection references, paths and the Storage URL helper. A new ESLint block (§5) stops `lib/types` and `lib/domain` from importing Firebase, `lib/firebase`, `server-only`, `client-only`, `next`, `react` or any Node builtin, bare or prefixed (`crypto`, `node:crypto`, `fs`, `fs/promises`, `path`…, generated from `module.builtinModules`). So they stay usable in the browser, on the Next server, in the seed and in tests. Email hashing uses Web Crypto (`globalThis.crypto.subtle`), which is isomorphic, so it needs no builtin. The prototype's probe file tripped all 12 bans, and a relative `./email` import in the same file stayed allowed.

**Functions can't use these files yet (deferred to M6.1).** Today nothing under `/functions` may import `lib/types`, `lib/domain` or `lib/firebase`:
- `functions/tsconfig.json` has `rootDir: "src"` and `include: ["src"]`, so `import "../../lib/domain/…"` fails with TS6059.
- A deploy uploads only `functions/` (`firebase.json` `source: "functions"`, which also ignores `src`), so `../lib` doesn't exist at runtime.
- `lib/firebase/converters.admin.ts` imports `server-only`, which throws in plain Node (it resolves to an empty module only under the `react-server` condition that Next and our tsx scripts set).

**M6.1 decides the sharing mechanism. Intended approach:** a `functions` prebuild step (a small cross-platform Node script using `fs.cpSync`, run by `npm --prefix functions run build` and so by the existing `predeploy`) copies `lib/types` and `lib/domain` into a generated, git-ignored `functions/src/shared/`. `rootDir` stays `src`, `main` stays `lib/index.js`, and the deploy ships the compiled copy. The alternatives are tsc project references, or `rootDir: ".."` with explicit includes (this moves the output to `lib/functions/src/index.js`, so `main` changes). A bundler such as esbuild would be a new dependency and needs user approval. Functions get their own Admin converter (`functions/src/converters.ts`, no `server-only`) built on the shared guards; `lib/firebase/converters.admin.ts` stays Next-only. Constraints that M1.4 keeps for this:
- `lib/types` and `lib/domain` stay free of `server-only`, Firebase, Next, React and Node builtins (the ESLint block). They use only relative imports (no `@/` alias), and only globals that both the DOM lib and `@types/node` declare (`globalThis.crypto`, `TextEncoder`).
- Checked in the prototype: `lib/types` + `lib/domain` pass `tsc` under the Functions compiler options (`module`/`moduleResolution: NodeNext` as CommonJS, `lib: ["ES2023"]`, `types: ["node"]`, strict).

**Branded IDs** (`ProductSlug`, `CollectionSlug`, `Sku`, `UserId`, `OrderId`, `EmailHash`) are worth it. Slugs, SKUs and uids are all strings that flow through the same functions (cart lines, gift-set contents, rules mirrors). In the prototype the compiler caught two real `sku === slug` comparisons (TS2367), now fixed through `skuBelongsTo()`. They cost nothing at runtime. Brands are minted only in `lib/domain/ids.ts`, after validation, and that file holds the only `as` casts. Route params and fixtures use `asProductSlug()` and its siblings.

**Money:** `{ amount, currency }` with `amount` an integer in minor units (cents). `CurrencyCode = "USD"` (the `CURRENCIES` tuple), and `DEFAULT_CURRENCY` stays a placeholder until the user confirms (catalog.md §8 q1). A product's variants must share one currency (a guard checks this). An order's amounts must all use `order.currency`.

**Documents.** Every timestamp is a Firestore Timestamp in storage and a `Date` in the domain.

| Path | ID | Shape (type) | Writers |
|---|---|---|---|
| `products/{slug}` | the slug | `Product` = `ProductInput` + `ProductDerived` + `{createdAt, updatedAt, publishedAt}` | seed (M1.8), admin server code (M7), Admin SDK only |
| `collections/{slug}` | the slug | `Collection` = `CollectionInput` + `{createdAt, updatedAt}` | seed, admin, Admin SDK only |
| `users/{uid}` | Auth uid (not stored) | `UserProfile` `{displayName, defaultShippingAddress, createdAt, updatedAt}` | the owner (rules-validated) |
| `users/{uid}/cart/{sku}` | the SKU | `CartLine` `{productSlug, sku, quantity, addedAt, updatedAt}` | the owner (rules-validated) |
| `orders/{orderId}` | auto ID (not stored) | `Order` (§4 `order.ts`) | Cloud Functions only |
| `newsletterSignups/{emailHash}` | SHA-256 hex (not stored) | `NewsletterSignup` `{email, source, consentVersion, createdAt}` | anonymous client create (rules-validated) |

- **The slug is the document ID**, so Firestore itself enforces uniqueness. The admin create uses `doc(slug).create()`, which fails if the slug exists. Slugs are immutable after creation. To rename a product, M7 creates a new document and archives the old one. Orders keep line snapshots, and cart lines for the archived product are dropped at the next validation. **SKUs** must equal the slug or start with `slug-` (a guard checks this), so they are globally unique whenever slugs are. `catalogProblems()` re-checks the whole catalog in the seed.
- **Status:** one `status: "draft" | "published" | "archived"` field instead of separate `published`/`archived` booleans. It allows no contradictory combinations, and public queries need one equality filter. Archived means soft-deleted (M7) and is never shown. `publishedAt` drives the "newest" sort.
- **Cart: one document per line**, not one cart document. The rules can't loop over an array, but they can fully validate a single line document, including `sku in get(/products/$(productSlug)).data.skus`. Only real SKUs can be written, so a cart is bounded by the catalog. A sign-in merge (M5.5) costs one batched write. `CART_LIMITS` (20 lines, 10 per line) is enforced in the client and at checkout. It also bounds a merge batch: at most 20 distinct product `get()`s, which is **exactly** the rules' limit of 20 document accesses per batched write (repeat `get()`s of one document count once). So there is no headroom:
  - The cart rules (create, update and delete) make **no other `get()`/`exists()` calls**. The "product published" check reads the same `get(/products/$(productSlug))` document.
  - A merge batch holds only cart-line writes (no profile write or other access-checked document in the same batch).
  - **M1.5 must add a rules test** for a 20-line merge batch over 20 distinct products (allowed).
- **Orders:** `userId` is null for guests, and `email` is always set. `accessTokenHash` is the SHA-256 of a 32-byte random token that appears only in the confirmation link and the email. The server route compares the hashes with `timingSafeEqual` and reads with the Admin SDK. Guests never read Firestore directly. The guards check that the line totals and the order total add up, and that `statusHistory` is a valid path through the state machine (below).
  - **Guest token, for M6.1:** decide the token's expiry and rotation (for example, valid for N days, with a fresh link on request by email). Serve the confirmation page with `Referrer-Policy: no-referrer`, or move the token out of the URL after the first load (exchange it for a short-lived httpOnly cookie, then redirect to a token-free URL). Never log query strings that carry the token (route handlers, analytics, hosting logs).
- **Order state machine** (`ORDER_TRANSITIONS`): `pending_payment → paid → processing → shipped → delivered`. `pending_payment → cancelled` covers payments that fail, expire or are abandoned. `paid | processing | shipped | delivered → refunded` covers a full refund. `cancelled` and `refunded` are terminal. I replaced "fulfilled" with `processing`, because "fulfilled" usually means "shipped" and would be ambiguous next to it.
  - **History guard:** `parseOrder` checks that `statusHistory[0]` is `null → pending_payment`, that each later step's `from` equals the previous step's `to` and `canTransition(from, to)` is true, and that the last `to` equals `status` (tests in `schemas.test.ts`).
  - **Named M6.1 decisions:** (1) **Partial refunds** (and returns): for example a `refunds[]` list of `{ amount, at, reference }` plus `amountRefunded: Money`, where the status stays put until the full amount is refunded, or a new `partially_refunded` status. Either way the type, guard and machine change in M6.1. (2) **A payment that arrives after cancellation** (the session expired, then the provider confirms payment): the machine refuses `cancelled → paid`. M6.1 picks automatic refund, or a provider-confirmed `cancelled → paid` edge, and logs the event either way.
- **Newsletter:** the client computes `emailHash(email)` (Web Crypto) as the document ID. The rules recompute `hashing.sha256(email).toHexString().lower()` and refuse a mismatch (verified in the emulator, §6.2). So no Function is needed, and a client can't bypass dedupe with random IDs. A duplicate arrives as an update, which the rules deny. The UI must show the same success message for that error (M2.6/M2.7), so the form doesn't reveal who is subscribed. Accepted risks for M2 (a Function plus App Check is the upgrade path if M2.7 wants it):
  - The raw API can still tell "exists" from "new": a low-value leak.
  - **NFC isn't enforced by the rules.** The rules language can't Unicode-normalise, so it checks only trim and lowercase. Our client sends the NFC form, but a raw-API caller can store the NFD form of the same address as a second document with a different hash (QA reproduced this in the emulator). The cost is a possible duplicate mail to one mailbox, which the sender (M2.7 or later) can dedupe by NFC-normalising before sending.
- **Profile:** email and providers stay in Firebase Auth, and roles stay in custom claims only. `Customer` is `UserProfile`; there is no second type.

**Derived fields** (`ProductDerived`) are computed only by `deriveProductFields(input, lookup)`, which the seed and M7 call on every write. When any product changes, M7 re-derives all gift sets (≤200 documents). The fields are `priceFrom`/`priceTo`/`currency`, `sizeKeys[]` (`220g`, `380g`, `120g`, `7x10`, `7x15`, `6-cubes`, `set`), `collectionSlugs[]` (collection + alsoIn), `scentFamilies[]` (a gift set gets the union of its contents' families, in §2.1 order), `skus[]`, `inStock`, `cardImage` and `giftSetValue` ("Worth $68.00 if bought separately"). There is **no `bestsellerRank`**: the catalog has only the `bestseller` badge, so bestsellers are `badges array-contains "bestseller"` ordered by `sortOrder`. A sales-based rank comes once orders exist. `sortOrder` is the sort rank.

**M3 query plan.** The Firestore limits below were verified in the emulator with the installed Admin SDK:
- Only one `array-contains`/`array-contains-any` clause is allowed per query: two of them fail with `FAILED_PRECONDITION: Only a single array-contains clause is allowed`.
- `array-contains` combined with `in`, or with a range, works.
- Inequality filters on two fields (`priceFrom >=` together with `sortOrder <=`) are accepted by the emulator and by `@google-cloud/firestore` 9.3.1 (Firestore has supported this since 2024). Each such query still needs its own composite index in production, and the emulator doesn't enforce indexes.

So "collection X **and** scent family Y" can't be one query, and multi-select facets (OR within a facet) plus facet counts don't map onto Firestore anyway. The plan:

| Surface | Firestore | In memory |
|---|---|---|
| Shop `/shop` (M3.5) | `status == "published"` `orderBy sortOrder`. One query for the whole catalog: 17 products now, ≤200 planned, about 3–4 KB each. Cached server-side and revalidated on admin writes (M1.6/M3 choose the cache API), so it's 200 reads per revalidation, not per visit. | All 5 filters: scent family (`scentFamilies`), type, size (`sizeKeys`), collection (`collectionSlugs`), and price (overlap with `[priceFrom, priceTo]`). OR within a facet, AND across facets. Also facet counts, the sort (featured = `sortOrder`, price = `priceFrom`, newest = `publishedAt`), pagination and URL params (M3.4), and `toProductCard()` so only card fields reach the client. |
| Collection page (M3.7), related (M4.5) | `collectionSlugs array-contains <slug>` + `status ==` + `orderBy sortOrder` (`limit` for related) | exclude the current product |
| Bestsellers (M2.4) | `badges array-contains "bestseller"` + `status ==` + `orderBy sortOrder` + `limit` | — |
| Collections: nav, home, collection list (M1.6 `getCollections`, M2/M3) | `collections` `status == "published"` `orderBy sortOrder`: 6 documents, cached like the shop list. Needs the `collections (status, sortOrder)` composite index below. | — |
| Single collection by slug (M1.6 `getCollectionBySlug`, M3.7 header) | `doc(slug).get()`: a document read, no query and no index. The repository returns null (→ `notFound()`) unless `status == "published"`. | — |
| Order history (M5.7) | `userId == uid` `orderBy createdAt desc` (client SDK, rules-checked) | — |

**Scale-out trigger:** more than about 500 published products, or a list payload above about 1 MB. Then move the most selective single facet into Firestore (collection via `array-contains`, or type via `in`, plus a `priceFrom` range), keep the rest in memory, and add the matching index.

**Composite indexes for `firestore.indexes.json` (M1.5):**

```json
{
  "indexes": [
    { "collectionGroup": "products", "queryScope": "COLLECTION", "fields": [
      { "fieldPath": "status", "order": "ASCENDING" }, { "fieldPath": "sortOrder", "order": "ASCENDING" } ] },
    { "collectionGroup": "products", "queryScope": "COLLECTION", "fields": [
      { "fieldPath": "collectionSlugs", "arrayConfig": "CONTAINS" }, { "fieldPath": "status", "order": "ASCENDING" }, { "fieldPath": "sortOrder", "order": "ASCENDING" } ] },
    { "collectionGroup": "products", "queryScope": "COLLECTION", "fields": [
      { "fieldPath": "badges", "arrayConfig": "CONTAINS" }, { "fieldPath": "status", "order": "ASCENDING" }, { "fieldPath": "sortOrder", "order": "ASCENDING" } ] },
    { "collectionGroup": "collections", "queryScope": "COLLECTION", "fields": [
      { "fieldPath": "status", "order": "ASCENDING" }, { "fieldPath": "sortOrder", "order": "ASCENDING" } ] },
    { "collectionGroup": "orders", "queryScope": "COLLECTION", "fields": [
      { "fieldPath": "userId", "order": "ASCENDING" }, { "fieldPath": "createdAt", "order": "DESCENDING" } ] }
  ],
  "fieldOverrides": []
}
```

**Why an index for `collections` rather than an in-memory sort:** `getCollections` filters `status ==` and orders by `sortOrder` (a different field), and production Firestore refuses that query without a composite index (the emulator doesn't enforce indexes, so only a production deploy would show it). Sorting 6 documents in memory would also work, but adding the index is simpler: the query reads the same in every repository, the ordering stays in Firestore, and the index costs almost nothing on 6 documents. M1.5 adds all five indexes above.

M7 adds `orders (status ASC, createdAt DESC)` when the admin status filter is written. Optional for M1.5: single-field index exemptions (`"indexes": []`) for fields that are never queried and are large or deep (`products.longDescription`, `variants`, `images`, `cardImage`, `scentNotes`; `orders.lines`, `statusHistory`, `shippingAddress`), to save index writes.

**Converters and validation.** I hand-rolled a parser kit (`lib/domain/validate.ts`, about 150 lines: `str/int/num/bool/oneOf/nullable/arrayOf/object/date/refine`) and **did not propose zod**. The shapes are few and stable, the kit reports the path of the bad field (`variants[0].price.currency: …`), and it adds nothing to the client bundles that import guards (cart, newsletter).
- `object()` drops unknown keys, so reads stay forward-compatible. Client writes get exact key sets from the rules.
- `date` accepts a `Date` or anything with `toDate()`, which covers both SDKs' Timestamps, so `lib/domain` never imports an SDK.
- `encodeDoc` turns Dates into the SDK's Timestamp, passes FieldValue sentinels through (`serverTimestamp()` is typed by `WithFieldValue<T>`), drops `undefined`, and leaves the ID field (`id`/`uid`/`emailHash`) unstored.
- The client converter reads with `serverTimestamps: "estimate"`, so a pending local write decodes to a Date and doesn't fail the guard.
- A bad document throws `DocumentValidationError` (with its document path). Policy for M1.6: list repositories log and skip the document; detail pages log and call `notFound()`.
- Write recipe (M1.8/M7): `parseProductInput(raw)` → `deriveProductFields(input, lookup)` → `adminCollections(db).products.doc(slug).create({...input, ...derived, createdAt: FieldValue.serverTimestamp(), updatedAt: …, publishedAt: …})`. The seed may use `set` so that re-seeding is idempotent.
- Dates pass from Server to Client Components as they are (React's RSC serialisation supports `Date`).

**Images.**
- **Product images:** a product stores Storage **paths**, never URLs. Each image is `{ id, storagePath: "products/<slug>/<id>.png", alt (from shot-list.json, ≤150 characters), role, width, height }`, with the catalog image first. `lif-comet-season` uses the path under each product's own slug.
- **Image sizes are read, never hardcoded.** The fixture (and the M1.8 seed after it) takes `width`/`height` from `assets/images/manifest.json` for the generated originals: 17 `cat-*` PNGs at 1792 × 2240, 6 `col-*` PNGs at 1744 × 2336. A derived `lif-*` crop (shot-list `derived`, "full width; remove the top 6.25% of the height") keeps its `from` original's width, and its height is `round(2336 × 0.9375)`, so 1744 × 2190. The fixture refuses a derived shot whose crop text isn't the 6.25% one.
- **M1.8 (seed) owns the image files:** it makes each `lif-*` crop from its `col-*` original and uploads it to Storage, exports the 6 `col-*` mood images to `/public/images/collections/*.jpg` at the original size, and uploads the `cat-*` PNGs. It then reads each delivered file's real size from its header, with no dependency: PNG IHDR (width and height as big-endian uint32 at bytes 16–23), and JPEG SOF0/SOF2 (scan the markers; height then width as big-endian uint16 at bytes 3–6 after the marker). It fails if a size differs from the manifest-derived one.
- **URLs:** repositories (M1.6) resolve URLs on the server with `storageObjectUrl(path)`, which builds the URL from `NEXT_PUBLIC_STORAGE_EMULATOR_HOST` and the bucket (no hardcoded emulator host). The production form (`firebasestorage.googleapis.com`) arrives with the production web config.
- **Collection mood images:** collections store `moodImage { src: servedUrl, alt, width, height }` (static `/public` JPEG, art §9.2). `width`/`height` are the original's manifest size (1744 × 2336), checked by M1.8 against the exported JPEG's SOF header.
- **M1.8 decision (recommended): keep the optimizer on in dev.** In `next.config.ts`, add a `remotePatterns` entry built from env (`http`, the emulator host and port, `pathname: "/v0/b/<bucket>/o/**"`, `search: "?alt=media"`). Set `images.dangerouslyAllowLocalIP: true` only when the project ID is `demo-*` **and** `NEXT_PUBLIC_USE_FIREBASE_EMULATORS === "true"`, so a production config (non-demo) can never carry it. I rejected `unoptimized`, because then the screenshots and performance checks wouldn't reflect production.
- Originals are about 4.5 MB per PNG, so the Storage rules size cap should be 10 MB.
- Whether a card repeats the alt (or uses `alt=""`) is M3.1's call; the data always holds the full alt.

## 3. Security implications for M1.5

| Path | Client read | Client write | What the rules validate |
|---|---|---|---|
| `products`, `collections` | anyone, if `status == "published"`; drafts too with `admin == true` | **none**, not even admins: derived fields need `deriveProductFields`, so M7 writes from server code that checks the claim, then uses the Admin SDK | — |
| `users/{uid}` | owner | owner create/update; no delete | `keys().hasOnly([displayName, defaultShippingAddress, createdAt, updatedAt])`; `displayName` null or 1–80 characters; address fields at the `addressParser` sizes, `country` matching `^[A-Z]{2}$`; `createdAt == request.time` on create and unchanged after; `updatedAt == request.time`; no `role`/`admin` field possible |
| `users/{uid}/cart/{sku}` | owner | owner create/update/delete | `hasOnly([productSlug, sku, quantity, addedAt, updatedAt])`; `sku == {sku}`; `quantity` an int from 1 to 10; `sku in get(/products/$(productSlug)).data.skus` and that product published (one `get()` of one document; **no other `get()`/`exists()`** in any cart rule, delete included: §1 Cart); `addedAt` as for `createdAt`; `updatedAt == request.time`. M1.5 test: a 20-line batch over 20 distinct products is allowed |
| `orders/{orderId}` | signed-in owner (`resource.data.userId == request.auth.uid`; list queries must filter on `userId`) | **none**: Functions only | — |
| `newsletterSignups/{hash}` | **none** | anonymous **create** only | `hasOnly([email, source, consentVersion, createdAt])`; `email` a string of ≤254 characters, `== email.trim().lower()`, matching the pattern; `{hash} == hashing.sha256(email).toHexString().lower()`; `source in ["home","footer"]`; `consentVersion` 1–40 characters; `createdAt == request.time`. **Not enforced: NFC** (the rules can't normalise Unicode), so a raw-API NFD duplicate of an address is possible: an accepted risk, like the exists-vs-new leak (§1 Newsletter) |
| Storage `products/**` | public get (no list; M1.5 §1) | admin claim only (or the Admin SDK seed) | `contentType` matches `image/(png|jpeg|webp|avif)`; size < 10 MB |

Never client-written: order contents, status, totals and prices (the checkout Function re-reads prices); product prices and every derived field; the `admin` claim. Admin SDK reads bypass the rules, so **M1.6 repositories must always filter `status == "published"`** on public pages (with a test).

## 4. Exact file contents

Create these files exactly as shown; they are Prettier-clean. Delete `lib/types/.gitkeep`.

**lib/types/brand.ts**
```ts
/**
 * Nominal ("branded") string types. A ProductSlug can't be passed where a Sku or a UserId is
 * expected, although all three are strings at runtime. Values are minted only by the guards in
 * lib/domain (ids.ts, schemas.ts), so a branded value has always been validated once.
 */
declare const brand: unique symbol;

export type Brand<T, B extends string> = T & { readonly [brand]: B };

/** Product document ID and URL segment, e.g. "moonrise". */
export type ProductSlug = Brand<string, "ProductSlug">;
/** Collection document ID and URL segment, e.g. "moonlit-terrace". */
export type CollectionSlug = Brand<string, "CollectionSlug">;
/** Variant SKU: the product slug, or the slug plus "-<size>", e.g. "moonrise-220". */
export type Sku = Brand<string, "Sku">;
/** Firebase Auth uid. */
export type UserId = Brand<string, "UserId">;
/** Firestore auto ID of an orders/{orderId} document. */
export type OrderId = Brand<string, "OrderId">;
/** Lowercase hex SHA-256 of a normalised email; newsletterSignups/{emailHash}. */
export type EmailHash = Brand<string, "EmailHash">;
```

**lib/types/money.ts**
```ts
/** ISO 4217 codes the store accepts. USD is a placeholder until the user confirms (catalog.md §8 q1). */
export const CURRENCIES = ["USD"] as const;
export type CurrencyCode = (typeof CURRENCIES)[number];

export const DEFAULT_CURRENCY: CurrencyCode = "USD";

/** An amount in integer minor units (cents for USD): 3400 is $34.00. Never a float. */
export type Money = {
  readonly amount: number;
  readonly currency: CurrencyCode;
```

**lib/domain/validate.ts**
```ts
/**
 * A tiny parser kit for runtime validation of untrusted data (Firestore documents, JSON
 * fixtures, client payloads), with no dependency. A Parser either returns a value of its type
 * or throws ValidationError with the path of the first bad field.
 * `object()` keeps only the keys in its shape, so unknown fields are dropped (forward-compatible
 * reads). Client writes are held to an exact key set by the security rules instead.
 */

export class ValidationError extends Error {
  override name = "ValidationError";
  constructor(
    readonly path: string,
    readonly reason: string,
  ) {
    super(`${path || "(root)"}: ${reason}`);
  }
}

export type Parser<T> = (value: unknown, path: string) => T;

export function fail(path: string, reason: string): never {
  throw new ValidationError(path, reason);
}

function describe(value: unknown): string {
  if (value === null) return "null";
  if (Array.isArray(value)) return "array";
  return typeof value;
}

function child(path: string, key: string | number): string {
  if (typeof key === "number") return `${path}[${key}]`;
  return path ? `${path}.${key}` : key;
}

export function str(
  opts: { min?: number; max?: number; pattern?: RegExp } = {},
): Parser<string> {
  const { min = 1, max = 2000, pattern } = opts;
  return (value, path) => {
    if (typeof value !== "string") {
      fail(path, `expected string, got ${describe(value)}`);
    }
    if (value.length < min || value.length > max) {
      fail(path, `length ${value.length} is outside ${min}..${max}`);
    }
    if (pattern && !pattern.test(value)) {
      fail(path, `"${value}" does not match ${String(pattern)}`);
    }
    return value;
  };
}

export function num(opts: { min?: number; max?: number } = {}): Parser<number> {
  const { min = -Infinity, max = Infinity } = opts;
  return (value, path) => {
    if (typeof value !== "number" || !Number.isFinite(value)) {
      fail(path, `expected a finite number, got ${describe(value)}`);
    }
    if (value < min || value > max) {
      fail(path, `${value} is outside ${min}..${max}`);
    }
    return value;
  };
}

export function int(opts: { min?: number; max?: number } = {}): Parser<number> {
  const base = num(opts);
  return (value, path) => {
    const n = base(value, path);
    if (!Number.isSafeInteger(n)) fail(path, `expected an integer, got ${n}`);
    return n;
  };
}

export const bool: Parser<boolean> = (value, path) => {
  if (typeof value !== "boolean") {
    fail(path, `expected boolean, got ${describe(value)}`);
  }
  return value;
};

export function oneOf<const T extends readonly string[]>(
  values: T,
): Parser<T[number]> {
  return (value, path) => {
    if (typeof value !== "string" || !values.includes(value)) {
      fail(path, `expected one of ${values.join(", ")}, got ${String(value)}`);
    }
    return value;
  };
}

export function literal<const T extends string>(expected: T): Parser<T> {
  return oneOf([expected]);
}

export function nullable<T>(parser: Parser<T>): Parser<T | null> {
  return (value, path) => (value === null ? null : parser(value, path));
}

export function arrayOf<T>(
  parser: Parser<T>,
  opts: { min?: number; max?: number; unique?: boolean } = {},
): Parser<readonly T[]> {
  const { min = 0, max = 100, unique = false } = opts;
  return (value, path) => {
    if (!Array.isArray(value)) {
      fail(path, `expected array, got ${describe(value)}`);
    }
    if (value.length < min || value.length > max) {
      fail(path, `${value.length} items is outside ${min}..${max}`);
    }
    const out = value.map((item: unknown, i) => parser(item, child(path, i)));
    if (unique && new Set(out).size !== out.length) {
      fail(path, "items must be unique");
    }
    return out;
  };
}

type Shape = Record<string, Parser<unknown>>;
export type Infer<S extends Shape> = {
  readonly [K in keyof S]: S[K] extends Parser<infer T> ? T : never;
};

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}

export function object<S extends Shape>(shape: S): Parser<Infer<S>> {
  const keys = Object.keys(shape);
  return (value, path) => {
    if (!isRecord(value)) fail(path, `expected object, got ${describe(value)}`);
    const out: Record<string, unknown> = {};
    for (const key of keys) {
      const parse = shape[key];
      if (parse) out[key] = parse(value[key], child(path, key));
    }
    // Safe: every key of the shape was parsed by its own parser above.
    return out as Infer<S>;
  };
}

/**
 * A Firestore Timestamp (Admin or client SDK: both have toDate()) or a Date. Always returns a
 * Date, so the domain never sees SDK classes.
 */
export const date: Parser<Date> = (value, path) => {
  const d =
    value instanceof Date
      ? value
      : isRecord(value) && typeof value.toDate === "function"
        ? (value.toDate as () => unknown)()
        : undefined;
  if (!(d instanceof Date) || Number.isNaN(d.getTime())) {
    fail(path, `expected a timestamp, got ${describe(value)}`);
  }
  return d;
};

export function map<T, U>(parser: Parser<T>, fn: (value: T) => U): Parser<U> {
  return (value, path) => fn(parser(value, path));
}

/** Adds a cross-field check. `check` returns an error message, or null when the value is fine. */
export function refine<T>(
  parser: Parser<T>,
  check: (value: T) => string | null,
): Parser<T> {
  return (value, path) => {
    const parsed = parser(value, path);
    const problem = check(parsed);
    if (problem !== null) fail(path, problem);
    return parsed;
  };
}
```

```ts
import type { EmailHash } from "../types";

/** Deliberately loose: one "@", no spaces, a dot in the domain. Real validation is the confirmation email. */
export const EMAIL_PATTERN = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
export const EMAIL_MAX_LENGTH = 254;

/**
 * NFC, trimmed, lowercase. No provider-specific rules (Gmail dots or "+tags"), which would be
 * wrong for other providers. The newsletter rules (M1.5) re-check trim and lowercase.
 */
export function normaliseEmail(raw: string): string {
  return raw.normalize("NFC").trim().toLowerCase();
}

export function isEmail(value: string): boolean {
  return value.length <= EMAIL_MAX_LENGTH && EMAIL_PATTERN.test(value);
}

/**
 * Lowercase hex SHA-256 of the normalised email: the newsletterSignups document ID. Uses Web
 * Crypto, which exists in browsers (secure contexts, including localhost) and in Node 24.
 * The rules recompute it with hashing.sha256(), so a client can't pick its own ID.
 */
export async function emailHash(email: string): Promise<EmailHash> {
  const bytes = new TextEncoder().encode(normaliseEmail(email));
  const digest = await globalThis.crypto.subtle.digest("SHA-256", bytes);
  const hex = Array.from(new Uint8Array(digest), (b) =>
    b.toString(16).padStart(2, "0"),
  ).join("");
  // Safe: a SHA-256 digest is always 64 lowercase hex characters.
  return hex as EmailHash;
}
```

```ts
const CANDLE_TYPES: readonly string[] = ["jar", "pillar", "tin"];

/** Cross-field rules for a product. Returns the first problem, or null. */
export function productInputProblem(p: ProductInput): string | null {
  const skus = p.variants.map((v) => v.sku);
  if (new Set(skus).size !== skus.length) return "variants: duplicate sku";
  for (const s of skus) {
    // Keeps SKUs globally unique as long as slugs are (they are document IDs).
    if (!skuBelongsTo(s, p.slug)) {
      return `variants: sku "${s}" must be "${p.slug}" or start with "${p.slug}-"`;
    }
  }
  if (new Set(p.variants.map((v) => v.price.currency)).size !== 1) {
    return "variants: all prices must use one currency";
  }
  const isGiftSet = p.type === "gift-set";
  if (isGiftSet !== (p.giftSetContents !== null)) {
    return "giftSetContents is required for gift sets and must be null otherwise";
  }
  if (isGiftSet !== (p.scentFamily === null)) {
    return "scentFamily must be null for gift sets and set otherwise";
  }
  if (isGiftSet !== (p.scentNotes === null)) {
    return "scentNotes must be null for gift sets and set otherwise";
  }
  const isMelt = p.type === "wax-melt";
  const isCandle = CANDLE_TYPES.includes(p.type);
  for (const v of p.variants) {
    if (isMelt !== (v.pieces !== null && v.warmTimeHoursPerPiece !== null)) {
      return `variant ${v.sku}: pieces and warmTimeHoursPerPiece are for wax melts only`;
    }
    if (isCandle !== (v.burnTimeHours !== null)) {
      return `variant ${v.sku}: burnTimeHours is required for candles and must be null otherwise`;
    }
    if (isCandle && v.dimensionsCm === null) {
      return `variant ${v.sku}: candles need dimensionsCm`;
    }
  }
  if (p.alsoIn.includes(p.collection)) return "alsoIn repeats collection";
  if (p.images[0]?.role !== "catalog")
    return "images[0] must be the catalog image";
  if (p.images.filter((i) => i.role === "catalog").length !== 1) {
    return "images: exactly one catalog image";
  }
  if (new Set(p.images.map((i) => i.id)).size !== p.images.length) {
    return "images: duplicate id";
  }
  const folder = `products/${p.slug}/`;
  const stray = p.images.find((i) => !i.storagePath.startsWith(folder));
  if (stray) return `images: ${stray.id} must live under ${folder}`;
  return null;
}
```

```ts
import {
  SCENT_FAMILIES,
  type CollectionSlug,
  type Money,
  type Product,
  type ProductCard,

  type ProductInput,

export class DeriveError extends Error {
  override name = "DeriveError";
}

/**
 * The size filter key of a variant: "220g", "380g", "120g", "7x10", "7x15", "6-cubes", "set"
 * (catalog.md §6.1). Stable, URL-safe, and the same across products of one size.
 */
export function sizeKeyOf(type: ProductType, variant: Variant): string {
  if (type === "gift-set") return "set";
  if (variant.pieces !== null) return `${variant.pieces}-cubes`;
  if (type === "pillar" && variant.dimensionsCm !== null) {
    const { diameter, height } = variant.dimensionsCm;
    return `${diameter}x${height}`;
  }
  return `${variant.weightGrams}g`;
}

/** Looks up another product's authored fields, for gift-set contents. */
export type ProductLookup = (slug: ProductSlug) => ProductInput | undefined;

function unique<T>(values: readonly T[]): T[] {
  return [...new Set(values)];
}

/**
 * Computes every denormalised field of a product. The only writer of ProductDerived: the seed
 * (M1.8) and admin writes (M7) call it on each write. When any product changes, M7 re-derives
 * every gift set too (their families and value depend on their contents; ≤200 docs).
 * Throws DeriveError when gift-set contents can't be resolved.
 */
export function deriveProductFields(
  product: ProductInput,
  lookup: ProductLookup,
): ProductDerived {
  const amounts = product.variants.map((v) => v.price.amount);
  const first = product.variants[0];
  const cardImage = product.images.find((i) => i.role === "catalog");
  if (!first || !cardImage) {
    throw new DeriveError(
      `${product.slug}: needs a variant and a catalog image`,
    );
  }

  let scentFamilies: ScentFamily[];
  let giftSetValue: Money | null = null;
  if (product.giftSetContents === null) {
    if (product.scentFamily === null) {
      throw new DeriveError(`${product.slug}: scentFamily is missing`);
    }
    scentFamilies = [product.scentFamily];
  } else {
    const families = new Set<ScentFamily>();
    let value = 0;
    for (const item of product.giftSetContents) {
      const content = lookup(item.productSlug);
      const contentVariant = content?.variants.find((v) => v.sku === item.sku);
      if (!content || !contentVariant) {
        throw new DeriveError(
          `${product.slug}: contents ${item.productSlug} / ${item.sku} not found`,
        );
      }
      if (content.scentFamily === null) {
        throw new DeriveError(
          `${product.slug}: contents ${item.productSlug} has no scent family (nested gift set?)`,
        );
      }
      if (contentVariant.price.currency !== first.price.currency) {
        throw new DeriveError(`${product.slug}: contents use another currency`);
      }
      families.add(content.scentFamily);
      value += contentVariant.price.amount * item.quantity;
    }
    // Fixed order (catalog.md §2.1), so equal inputs always give equal arrays.
    scentFamilies = SCENT_FAMILIES.filter((f) => families.has(f));
    giftSetValue = { amount: value, currency: first.price.currency };
  }

  return {
    priceFrom: Math.min(...amounts),
    priceTo: Math.max(...amounts),
    currency: first.price.currency,
    sizeKeys: unique(product.variants.map((v) => sizeKeyOf(product.type, v))),
    collectionSlugs: unique<CollectionSlug>([
      product.collection,
      ...product.alsoIn,
    ]),
    scentFamilies,
    skus: product.variants.map((v) => v.sku),
    inStock: product.variants.some((v) => v.available),
    cardImage,
    giftSetValue,
  };
}

/** Derives a whole catalog at once (seed): every product may reference any other. */
export function deriveCatalog(
  products: readonly ProductInput[],
): (ProductInput & ProductDerived)[] {
  const bySlug = new Map(products.map((p) => [p.slug, p]));
  return products.map((p) => ({
    ...p,
    ...deriveProductFields(p, (slug) => bySlug.get(slug)),
  }));
}

/**
 * Whole-catalog checks a single document can't make: unique slugs and SKUs, known
 * collections, and gift-set contents that exist. Returns every problem found.
 */
export function catalogProblems(
  products: readonly ProductInput[],
  collectionSlugs: readonly CollectionSlug[],
): string[] {
  const problems: string[] = [];
  const known = new Set(collectionSlugs);
  const slugs = new Set<string>();
  const skus = new Map<string, ProductInput>();
  for (const p of products) {
    if (slugs.has(p.slug)) problems.push(`duplicate slug ${p.slug}`);
    slugs.add(p.slug);
    for (const v of p.variants) {
      if (skus.has(v.sku)) problems.push(`duplicate sku ${v.sku}`);
      skus.set(v.sku, p);
    }
    for (const c of [p.collection, ...p.alsoIn]) {
      if (!known.has(c)) problems.push(`${p.slug}: unknown collection ${c}`);
    }
  }
  for (const p of products) {
    for (const item of p.giftSetContents ?? []) {
      const owner = skus.get(item.sku);
      if (!owner || owner.slug !== item.productSlug) {
        problems.push(
          `${p.slug}: contents ${item.productSlug} / ${item.sku} not found`,
        );
      } else if (owner.type === "gift-set") {
        problems.push(
          `${p.slug}: contents ${item.productSlug} is itself a gift set`,
        );
      }
    }
  }
  return problems;
}
```

```ts
import type { OrderStatus } from "../types";

/**
 * The order state machine. The M6 Functions (the only writers of orders) must enforce it; how
 * they get this file is an M6.1 decision (spec §1). parseOrder checks that statusHistory follows
 * it. cancelled = never paid (payment failed, expired or abandoned). refunded = paid, then the
 * full amount was returned. Named M6.1 decisions: partial refunds (refunds[] / amountRefunded)
 * and a payment that arrives after cancellation (cancelled → paid is refused here).
 *
 *   pending_payment ──► paid ──► processing ──► shipped ──► delivered
 *         │              └──────────┴──────────────┴───────────┴──► refunded
 *         └──► cancelled
 */
export const ORDER_TRANSITIONS: {
  readonly [S in OrderStatus]: readonly OrderStatus[];
} = {
  pending_payment: ["paid", "cancelled"],
  paid: ["processing", "refunded"],
  processing: ["shipped", "refunded"],
  shipped: ["delivered", "refunded"],
  delivered: ["refunded"],
  cancelled: [],
  refunded: [],
};

export function canTransition(from: OrderStatus, to: OrderStatus): boolean {
  return ORDER_TRANSITIONS[from].includes(to);
}

export function isTerminal(status: OrderStatus): boolean {
  return ORDER_TRANSITIONS[status].length === 0;
}

/** Statuses a customer sees as "paid for" (order history, M5.7). */
export function isPaid(status: OrderStatus): boolean {
  return (
    status === "paid" ||
    status === "processing" ||
    status === "shipped" ||
    status === "delivered"
  );
}
```

```ts
import { ValidationError } from "../domain/validate";

/**
 * SDK-neutral helpers shared by converters.admin.ts and converters.client.ts. The two SDKs
 * have different Timestamp classes, so each converter passes its own factory.
 */

/** A stored document failed its guard. Carries the document path for logs. */
export class DocumentValidationError extends Error {
  override name = "DocumentValidationError";
  constructor(
    readonly docPath: string,
    cause: ValidationError,
  ) {
    super(`Invalid document ${docPath}: ${cause.message}`, { cause });
  }
}

function isPlainObject(value: unknown): value is Record<string, unknown> {
  if (typeof value !== "object" || value === null) return false;
  const proto: unknown = Object.getPrototypeOf(value);
  return proto === Object.prototype || proto === null;
}

/**
 * Domain object → Firestore data. Dates become SDK Timestamps; arrays and plain objects are
 * walked; anything else (FieldValue sentinels such as serverTimestamp(), Timestamps) passes
 * through. `undefined` fields are dropped. `idField` (e.g. Order.id) is not stored: it is the
 * document ID.
 */
export function encodeDoc(
  model: object,
  idField: string | undefined,
  toTimestamp: (date: Date) => unknown,
): Record<string, unknown> {
  const encode = (value: unknown): unknown => {
    if (value instanceof Date) return toTimestamp(value);
    if (Array.isArray(value)) return value.map(encode);
    if (isPlainObject(value)) {
      const out: Record<string, unknown> = {};
      for (const [key, v] of Object.entries(value)) {
        if (v !== undefined) out[key] = encode(v);
      }
      return out;
    }
    return value;
  };
  const out: Record<string, unknown> = {};
  for (const [key, v] of Object.entries(model)) {
    if (key !== idField && v !== undefined) out[key] = encode(v);
  }
  return out;
}

/** Firestore data → domain object, through the entity's guard. */
export function decodeDoc<T>(
  parse: (raw: unknown, id: string) => T,
  docPath: string,
  id: string,
  data: unknown,
): T {
  try {
    return parse(data, id);
  } catch (error) {
    if (error instanceof ValidationError) {
      throw new DocumentValidationError(docPath, error);
    }
    throw error;
  }
}
```

```ts
    toFirestore(
      model: WithFieldValue<T> | PartialWithFieldValue<T>,
    ): DocumentData {
      return encodeDoc(model, idField, (d) => Timestamp.fromDate(d));
    },
    fromFirestore(
      snapshot: QueryDocumentSnapshot,
      options?: SnapshotOptions,
    ): T {
      const data = snapshot.data({ ...options, serverTimestamps: "estimate" });
      return decodeDoc(parse, snapshot.ref.path, snapshot.id, data);
    },
  };
}
```

```ts
import { readPublicFirebaseEnv, type PublicFirebaseEnv } from "./env.public";

/**
 * Public URL of a Storage object, e.g. a ProductImage.storagePath. Documents store the path,
 * never a URL, so one data set works against the emulator and, later, production.
 * Both forms use the Storage REST API with public read rules (M1.5), so no download token:
 *   emulator:   http://<NEXT_PUBLIC_STORAGE_EMULATOR_HOST>/v0/b/<bucket>/o/<path>?alt=media
 *   production: https://firebasestorage.googleapis.com/v0/b/<bucket>/o/<path>?alt=media
 * The production branch arrives with the production web config: readPublicFirebaseEnv() only
 * accepts demo projects (emulators) until the user approves a real one.
 */
export function storageObjectUrl(
  storagePath: string,
  env: PublicFirebaseEnv = readPublicFirebaseEnv(),
): string {
  const { host, port } = env.emulators.storage;
  const bucket = encodeURIComponent(env.storageBucket);
  const object = encodeURIComponent(storagePath);
  return `http://${host}:${port}/v0/b/${bucket}/o/${object}?alt=media`;
}
```

```ts
const LIFESTYLE_CROP_TOP = 0.0625;

function readJson(file: string): Json {
  return JSON.parse(
    readFileSync(path.join(process.cwd(), file), "utf8"),
  ) as Json;
}

function records(value: unknown): Json[] {
  if (!Array.isArray(value)) throw new Error("expected an array");
  return value as Json[];
}

export function loadCatalogJson() {
  const catalog = readJson("design/copy/catalog.json");
  const shotList = readJson("design/art/shot-list.json");
  const manifest = readJson("assets/images/manifest.json");
  const shots = new Map<string, Json>();
  for (const s of [...records(shotList.shots), ...records(shotList.derived)]) {
    shots.set(String(s.id), s);
  }
  /** Pixel sizes of the generated originals (cat-*, col-*), keyed by shot ID. */
  const sizes = new Map<string, ImageSize>();
  for (const [id, m] of Object.entries(
    manifest.shots as Record<string, Json>,
  )) {
    if (typeof m.width === "number" && typeof m.height === "number") {
      sizes.set(id, { width: m.width, height: m.height });
    }
  }
  return {
    products: records(catalog.products),
    collections: records(catalog.collections),
    scentFamilies: records(catalog.scentFamilies),
    shots,
    sizes,
  };
}

export type CatalogJson = ReturnType<typeof loadCatalogJson>;

function shot(shots: Map<string, Json>, id: unknown): Json {
  const s = shots.get(String(id));
  if (!s) throw new Error(`shot-list.json has no ${String(id)}`);
  return s;
}

/**
 * Pixel size of a delivered image, never a constant. Originals (cat-* PNGs; col-* mood images,
 * which M1.8 exports to /public as JPEG at the original size) come from manifest.json. A derived
 * lif-* crop (made by M1.8) keeps its `from` original's width and loses the top 6.25% of the
 * height: 1744 × 2336 → 1744 × 2190. M1.8 reads each delivered file's header (PNG IHDR, JPEG
 * SOF) and fails if it differs from this.
 */
export function imageSize(json: CatalogJson, id: string): ImageSize {
  const original = json.sizes.get(id);
  if (original) return original;
  const s = shot(json.shots, id);
  const from = json.sizes.get(String(s.from));
  if (!from || !String(s.crop).includes("top 6.25%")) {
    throw new Error(`no size for ${id}: unknown original or crop`);
  }
  return {
    width: from.width,
    height: Math.round(from.height * (1 - LIFESTYLE_CROP_TOP)),
  };
}

/** shot-list deliveredPath is a string, or one path per product (lif-comet-season). */
function storagePathFor(s: Json, slug: string): unknown {
  const paths = Array.isArray(s.deliveredPath)
    ? s.deliveredPath
    : [s.deliveredPath];
  return paths.find(
    (p): p is string =>
      typeof p === "string" && p.startsWith(`products/${slug}/`),
  );
}

export function toProductInputRaw(raw: Json, json: CatalogJson): unknown {
  const images = raw.images as { catalog: unknown; lifestyle: unknown[] };
  const slug = String(raw.slug);
  const image = (id: unknown, role: "catalog" | "lifestyle") => {
    const s = shot(json.shots, id);
    return {
      id,
      storagePath: storagePathFor(s, slug),
      alt: s.alt,
      role,
      ...imageSize(json, String(id)),
    };
  };
  return {
    slug: raw.slug,
    name: raw.name,
    type: raw.type,
    collection: raw.collection,
    alsoIn: raw.alsoIn,
    shortDescription: raw.shortDescription,
    longDescription: raw.longDescription,
    scentFamily: raw.scentFamily,
    scentNotes: raw.scentNotes,
    variants: records(raw.variants).map((v) => ({ ...v, available: true })),
    badges: raw.badges,
    careKey: String(raw.careNotesRef).replace(/^care\./, ""),
    giftSetContents: raw.giftSetContents,
    images: [
      image(images.catalog, "catalog"),
      ...images.lifestyle.map((id) => image(id, "lifestyle")),
    ],
    sortOrder: raw.sortOrder,
    status: "published",
  };
}

export function toCollectionInputRaw(raw: Json, json: CatalogJson): unknown {
  const id = String((raw.images as { mood: unknown }).mood);
  const s = shot(json.shots, id);
  return {
    slug: raw.slug,
    name: raw.name,
    tagline: raw.tagline,
    description: raw.description,
    // moodNote is an art brief, never rendered (catalog.md §6): not stored.
    isLimited: raw.isLimited,
    sortOrder: raw.sortOrder,
    moodImage: { src: s.servedUrl, alt: s.alt, ...imageSize(json, id) },
    status: "published",
  };
}

export function catalogProductInputs(): ProductInput[] {

}

export function catalogCollectionInputs(): CollectionInput[] {
```
