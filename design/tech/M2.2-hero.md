## 1. Decisions

### 1.1 Dependency: `gsap` 3.15.0

- `npm install gsap@3.15.0 --save-exact` → `"gsap": "3.15.0"` in `dependencies` (runtime: the hero island imports it). The lock gains the root entry and `node_modules/gsap` only.

### 1.3 Markup and layout (home.md §3.1, §3.2)

- `components/home/HomeHero.tsx` (Server Component): `<section id="hero" data-band="solid" data-flush-end aria-labelledby="hero-heading" class="pt-6 md:pt-8 lg:pt-0">` → `.hero-grid` → the text column (`page-container`, reset at lg with `lg:col-start-2 lg:mx-0 lg:max-w-none lg:px-0`) and `.hero-media`.
  - Text column: `hgroup` (eyebrow `type-eyebrow text-text-accent` + `h1#hero-heading type-display-1 max-w-measure-heading`, gap 12), then the subcopy (`mt-4 max-w-measure-intro type-body-lg text-pretty text-text-secondary`), then the CTA group, only when it has a primary CTA (`mt-6 flex flex-wrap items-center gap-8`).
  - `data-hero-reveal` sits only on the eyebrow, the subcopy and the CTA group. It is never on the `hgroup`, the h1, the image or the glow.
- Copy (eyebrow, h1, subcopy, alt) is used verbatim from home.md §11.1 and §11.3. The CTA labels live in `hero-actions.ts`.
- **lg+ grid** (`.hero-grid`, globals.css): four tracks: `[container start offset] [columns 1–5] [--grid-gap] [minmax(0, 1fr)]`, with `align-items: center`. The column maths uses `100%` (the band's width), exactly as `page-container` does:
  - `--hero-content: min(100% − inline paddings, 80rem)`, `--hero-col: (content − 11 × gap) / 12`.
  - Track 1 = `(100% − paddings − content) / 2 + padding-start`; track 2 = `5 × col + 4 × gap`.
  - `.hero-media` sits in track 4 (`justify-self: start; max-inline-size: 60rem; aspect-ratio: 5 / 4`).
  - The band's height is the taller of the box and the text, so the text-spacing override grows the band and never clips.
- Below lg: the text stays in the page container, and `.hero-media` is full bleed (`width: 100%` of the band, not `100vw`), 1:1 at base and 4:3 at md, 32px under the text.

### 1.4 The image (home.md §3.9)

- Both JPEGs are statically imported (`@/public/images/hero/hero-{mobile,desktop}.jpg`), so width and height are known. The build copies them to `/_next/static/media/`.
- There are two `getImageProps()` calls. The desktop call is used only for its `srcSet`, on `<source media="(min-width: 48rem)" sizes="(min-width: 64rem) 81vw, 134vw">`. The mobile call supplies the `<img>` (`sizes="100vw"`, `loading="eager"`, `fetchPriority="high"`, `decoding="async"` by default), with `class="size-full object-cover"`. The alt is restated on the `<img>` so `jsx-a11y/alt-text` sees it (no lint suppression).
- **No preload.** The Next 16.4 docs (`node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md`, `preload`) say not to preload when two images could be the LCP element depending on the viewport, nor together with `fetchPriority` / `loading`. In most cases `loading="eager"` or `fetchPriority="high"` should be used instead. `priority` is deprecated in 16. The `<picture>` sits early in the server HTML, so the preload scanner finds it anyway: on slow 4G it is requested about 0.66 s in, right after the HTML.
- Crop by CSS: `object-position: 50% 80%` at base, `100% 50%` from md. The image is the only eager, high-priority image on the page (e2e 4).
- Formats: Next's default `image/webp`. AVIF isn't enabled: it encodes slower on a cold cache, and a config change belongs to its own task if wanted.

### 1.5 Feather and glow (home.md §3.3, §3.4)

- **Feather.** `.hero-image` (bg-raised until the photo decodes, `width/height: 100%`) carries a static `mask-image`:
  - base/md: one vertical gradient (transparent 0 → #000 8% … #000 84% → transparent 100%).
  - lg+: the vertical gradient plus a horizontal one (0 → 24% … 92% → 100%), with `mask-composite: intersect`.
  - The gradients are custom properties. Lightning CSS adds the `-webkit-mask-image` / `-webkit-mask-composite: source-in` prefixes by itself, so the source writes only the standard properties. Because the values are `var()`, the output repeats the identical prefixed line three times, which is harmless.
  - `picture { display: contents }` keeps the `<img>` filling the box. The mask is never animated (e2e 7: no animations on `.hero-image`).
- **Glow.** `.hero-glow` is `aria-hidden`, `data-decorative` (gone in forced colors and print), `display: none` below md.
  - From md: `position: absolute; z-index: -1` inside `.hero-media`. `.hero-media` is `position: relative` and creates no stacking context, so the glow paints in the band's own isolated context, above the band's bg-page and under the masked image.
  - Size: `width: 60%` of the box, `aspect-ratio: 1`, `background-image: var(--gradient-candle-glow)` (a closest-side circle, so r = 30% of the box).
  - Position: `inset-inline-start: 46.7%` (md) / `43.1%` (lg+), `inset-block-start: 57%`, with a static `translate: -50% -50%`. This is sized from home.md §3.4, not shot-list.json's superseded `glowPlacement`.
  - No breathing loop and no box-shadow on the image. At 1440 the glow starts more than 100px clear of the text column (e2e 6 asserts at least 100 at 1440).

### 1.6 CTA recipe (tokens.md §2.3, rule 9; motion.md §5)

- `components/ui/button.ts`: `primaryButtonClasses({ glow = true })` returns a class string, so a plain `<a>`, a `<Link>` or a `<button>` can wear it.
- The recipe: ember-400 fill, text-inverse, pill, `type-button`, `px-6 py-3`, `min-h-12`, a transparent 1px border, `hover:bg-cta-bg-hover`, `active:bg-cta-bg-active`, `active:scale-(--motion-scale-press)` (1 under reduced motion), and `transition-[background-color,scale]` at duration-fast / ease-standard.
- The glow is an `::after` (`-inset-px` = the border box, `rounded-[inherit]`, `shadow-glow-candle`, opacity 0 → 1 on `hover` / `focus-visible`, opacity transition at duration-fast; kept under reduced motion, motion.md §6.2). Its footprint is the border box plus 26px.
- `glow: false` is the rule-9 no-glow variant (no `::after` at all). The hero uses the default.
- The hero's primary CTA is `w-full md:w-auto`. The text link is `type-nav text-link underline decoration-1 underline-offset-[0.2em] hover:text-link-hover inline-flex min-h-(--size-touch) gap-2`, followed by the 16px `ArrowRightIcon`.
  - `ArrowRightIcon` is new in `components/icons/glyphs.tsx`, and `SectionHeading`'s inline copy of the same SVG now uses it. That is the only change to SectionHeading.
- Both CTAs are plain `<a>` (in-page fragments, never prefetched).

### 1.7 Entrance motion (motion.md §5.1, home.md §3.6, §9)

- `components/home/HomeMotion.tsx`: a `"use client"` island that renders `null`. It is rendered by the home page (and `/dev/hero`) only, never by a layout or a shared component, so `gsap` loads on those routes only (verified: the gsap chunk is in `/`'s scripts and not in `/_not-found`'s).
- In one `useEffect`:
  1. `html[data-motion="off"]` (the M8.8b hook) → remove `hero-pending`, stop.
  2. `gsap.matchMedia()` with two branches.
     - `(prefers-reduced-motion: no-preference)`: if `hero-pending` is already gone (the 2500 ms fallback won), do nothing. Otherwise: `gsap.set(targets, { opacity: 0, y: DISTANCE.lg })`, remove `hero-pending`, then `gsap.to(targets, { opacity: 1, y: 0, duration: DURATION.slower, ease: EASE.enter, stagger: { amount: min(STAGGER.maxTotal, (n − 1) × STAGGER.loose) }, clearProps: "opacity,transform" })`.
       - The targets are `#hero [data-hero-reveal]` in DOM order: 3 on `/dev/hero` (a spread of 0.2 s), 2 on `/` in M2.2.
       - Values come from `lib/motion/tokens.ts`, never `getComputedStyle`.
     - `(prefers-reduced-motion: reduce)`: remove the class if present.
  3. Cleanup: `mm.revert()`, which restores the elements' original (empty) inline styles on unmount or when the preference changes. So nothing can stay hidden.
- After the tween, `clearProps` leaves no inline opacity or transform (e2e checks it).
- **gsap core only.** `import { gsap } from "gsap"` (index.js = core + CSSPlugin, which `opacity`/`y` on DOM nodes need). **ScrollTrigger is not imported in M2.2.** No section reveals exist yet. M2.3 adds it with a dynamic `import("gsap/ScrollTrigger")` after the entrance has started (or after load + idle with no entrance), as home.md §9 says, registered once in the same island.
- Not `@gsap/react`'s `useGSAP`: it isn't in the stack, and `matchMedia().revert()` gives the same cleanup.
- React Strict Mode (dev only) mounts the effect twice. The first cleanup reverts, the second run finds the class gone and skips. So in `next dev` the hero simply appears. Production runs once.
- **CLS 0:** only opacity and transform move, and all space is reserved by layout. **LCP:** the image is never pre-hidden.

### 1.8 Bands: the flush end and the collapse fix (layout-shell §5.1 as amended; home.md §2.3)

The fix is in `app/globals.css`, `@layer components`:

```css
[data-band][data-flush-end] { padding-block-end: 0; }
[data-band][data-flush-end]:not(:has(~ [data-band])) { padding-block-end: var(--section-y); }
:is([data-band="plain"], [data-band="solid"]):not([data-flush-end])
  + :is([data-band="plain"], [data-band="solid"]),
[data-band="sunken"]:not([data-flush-end]) + [data-band="sunken"] { padding-block-start: 0; }
```

- `data-flush-end` = "this band ends at 0". The band after it is left out of the collapse, so it keeps its `--section-y`. Measured on `/dev/hero`: hero `24px / 0` (390), `0 / 0` (1440); `#collections` top 64 / 128; `#bestsellers` top 0 (collapsed after a plain band).
- A band directly after a band that is not flush-ending still collapses as before, whether or not the second band is itself flush-ending.
- **Deviation, logged as PUSHBACK 1 (§1.11):** home.md §3.2/§14 say the hero's bottom is 0 "at every breakpoint". layout-shell §5.1 also says "The last section before the footer keeps its bottom padding". In M2.2 the hero *is* the last band. The second rule above gives it `--section-y` there (64 / 128px between the feathered image and the footer), instead of the feather ending flush on the footer's hard bg-sunken edge.
  - The rule switches itself off as soon as M2.3 puts a band after the hero, so home.md's 0 then holds with no code change.
  - `:has(~ …)` is in every browser Tailwind 4 targets (Safari 16.4+, Chrome 111+, Firefox 128+).
- The shell's band-collapse e2e test now builds its bands in a wrapper of its own, so the page's hero takes no part. It gains the flush cases: solid → solid+flush collapses; plain after a flush-ending band keeps `--section-y`; a flush-ending band's bottom is 0, or `--section-y` when it is the last band. The M1.13 tech spec blocks are resynced (§2.4).

### 1.11 PUSHBACK and notes

- **PUSHBACK 1 (design-agent, small; build proceeds as specified here unless design-agent objects).** home.md §3.2/§14 give the hero `padding-block-end: 0` "at every breakpoint", but in M2.2 the hero is the last band, and layout-shell §5.1 says the last section before the footer keeps its bottom padding. - **Note for design-agent (motion.md §5.1, not blocking).** Under a Lighthouse-like slow-4G profile (150 ms RTT, 1.6 Mbps, 4× CPU, cold cache, warm optimizer), the island takes over at 2.71–2.89 s. The head script set its timer at about 0.66 s, so the fallback would fire at about 3.2 s; GSAP wins every run, about 0.3–0.5 s ahead of it. The eyebrow and subcopy, and from M2.3/M2.4 the CTA group, so stay hidden until about 2.8 s and finish entering at about 3.7 s, while the image (LCP) paints at about 1.7 s. On fast 4G (60 ms, 9 Mbps, 2× CPU) the entrance starts at about 0.8 s, and on desktop at about 0.2 s. gsap's 27 KB gz is roughly 140 ms of that at 1.6 Mbps. If that wait is too long for the Instagram/Pinterest phone audience, the levers are design calls: leave the CTA group visible (no `data-hero-reveal`) below md, or shorten the fallback.

```ts
/**
 * The hero's calls to action (design/pages/home.md §3.7, §3.8, §11.1). Both are
 * in-page anchors, so a CTA is rendered only when the section it jumps to is on
 * the page: there is never a dead fragment link.
 *
 * - both sections: "Shop favorites" (primary) → #bestsellers, then the text link
 *   "Explore collections" → #collections;
 * - no bestsellers section: "Explore collections" becomes the primary CTA and the
 *   text link is not rendered;
 * - no collections section: the primary CTA only;
 * - neither (M2.2, before M2.3/M2.4 add the sections): no CTAs at all.
 *
 * Plain data and a pure function with no imports (unit-tested in Node).
 */

export type HeroAction = {
  kind: "primary" | "link";
  label: string;
  href: `#${string}`;
};

/** Which home sections are rendered on the page (home.md §4.6, §5.1). */
export type HomeSections = {
  collections: boolean;
  bestsellers: boolean;
};

export const SHOP_FAVORITES = "Shop favorites";
export const EXPLORE_COLLECTIONS = "Explore collections";

export function heroActions(sections: HomeSections): HeroAction[] {
  const actions: HeroAction[] = [];
  if (sections.bestsellers) {
    actions.push({
      kind: "primary",
      label: SHOP_FAVORITES,
      href: "#bestsellers",
    });
  }
  if (sections.collections) {
    actions.push({
      kind: sections.bestsellers ? "link" : "primary",
      label: EXPLORE_COLLECTIONS,
      href: "#collections",
    });
  }
  return actions;
}
```

```tsx
"use client";

import { gsap } from "gsap";
import { useEffect } from "react";

import { DISTANCE, DURATION, EASE, STAGGER } from "@/lib/motion/tokens";

const PENDING = "hero-pending";
const NO_PREFERENCE = "(prefers-reduced-motion: no-preference)";
const REDUCE = "(prefers-reduced-motion: reduce)";

/**
 * The home page's one motion island (design/pages/home.md §9). Renders nothing.
 * M2.2: the hero entrance (motion.md §5.1 step 3, home.md §3.6). The head script
 * (app/hero-pending.ts) has already hidden `[data-hero-reveal]` with the
 * `hero-pending` class when motion is allowed; this takes over on hydration.
 *
 * - no-preference: if `hero-pending` is gone (its 2500 ms fallback fired on a
 *   slow device), skip: the hero is visible and is never hidden again.
 *   Otherwise hold the hidden state in GSAP's inline styles, drop the class, and
 *   bring the eyebrow, subcopy and CTA group in (opacity and transform only;
 *   their space is reserved by normal layout, so nothing shifts).
 * - reduce, or `html[data-motion="off"]` (the M8.8b hook): no entrance; the
 *   class is removed if it is somehow present.
 *
 * gsap core only (it includes CSSPlugin). ScrollTrigger is for the section
 * reveals and arrives with them (M2.3), loaded with a dynamic import after the
 * entrance has started, never in this chunk. matchMedia reverts the inline
 * styles on unmount and when the preference changes, so nothing stays hidden.
 */
export function HomeMotion() {
  useEffect(() => {
    const root = document.documentElement;
    const reveal = () => root.classList.remove(PENDING);
    if (root.dataset.motion === "off") {
      reveal();
      return;
    }
    const mm = gsap.matchMedia();
    mm.add(NO_PREFERENCE, () => {
      if (!root.classList.contains(PENDING)) return;
      const targets = gsap.utils.toArray<HTMLElement>(
        "#hero [data-hero-reveal]",
      );
      gsap.set(targets, { opacity: 0, y: DISTANCE.lg });
      reveal();
      gsap.to(targets, {
        opacity: 1,
        y: 0,
        duration: DURATION.slower,
        ease: EASE.enter,
        // stagger-loose, the spread capped at stagger-max-total (motion.md
        // §4): 3 targets spread over 0.2 s.
        stagger: {
          amount: Math.min(
            STAGGER.maxTotal,
            (targets.length - 1) * STAGGER.loose,
          ),
        },
        clearProps: "opacity,transform",
      });
    });
    mm.add(REDUCE, reveal);
    return () => {
      mm.revert();
    };
  }, []);

  return null;
}
```

```ts
/**
 * The primary (ember) CTA recipe (tokens.md §2.3, §2.5 rule 9, §6.2; motion.md
 * §5): ember-400 fill, text-inverse, pill, type-button, padding 12 / 24, min
 * height 48, a transparent 1px border (it shows in forced colors). Hover: the
 * ember-300 fill. Active: ember-500 and the press scale (1 under reduced motion,
 * via --motion-scale-press). The glow is an ::after that already carries
 * shadow-glow-candle at opacity 0 and fades in on hover and focus-visible
 * (opacity only, duration-fast; kept under reduced motion, motion.md §6.2).
 *
 * `glow: false` is the no-glow variant: over a haze gradient, or with another
 * control inside the glow's 26px footprint (rule 9). It has no ::after at all.
 *

 * <button> can all wear it. Width is the caller's (the hero: full width at base).
 */
export function primaryButtonClasses({
  glow = true,
}: { glow?: boolean } = {}): string {
  const base =
    "relative inline-flex min-h-12 items-center justify-center rounded-pill border border-transparent bg-cta-bg px-6 py-3 text-center type-button text-text-inverse transition-[background-color,scale] duration-(--duration-fast) ease-standard hover:bg-cta-bg-hover active:scale-(--motion-scale-press) active:bg-cta-bg-active";
  if (!glow) return base;
  return `${base} after:pointer-events-none after:absolute after:-inset-px after:rounded-[inherit] after:opacity-0 after:shadow-glow-candle after:transition-opacity after:duration-(--duration-fast) after:ease-standard after:content-[''] hover:after:opacity-100 focus-visible:after:opacity-100`;
```

```ts
  // while `hero-pending` is set and which inline styles GSAP writes.

    const seen: string[] = [];
    const w = window as Window & {
      __hero?: { seen: string[]; pending: boolean[]; h1: string[] };
    };
    w.__hero = { seen, pending: [], h1: [] };
    // Push the head script's 2500ms fallback out of the way, so the island is
    // the only thing that can reveal the hero (a readiness question, not timing).

    window.setTimeout = ((
      handler: TimerHandler,
      delay?: number,

      if (delay === 2500) w.__hero!.pending.push(true);
      return setTimeoutOriginal(
        handler,
        delay === 2500 ? 60_000 : delay,
        ...rest,
      );
    }) as typeof window.setTimeout;
    new MutationObserver((records) => {
      for (const record of records) {
        const el = record.target as Element;
        if (
          record.attributeName === "style" &&
          el.hasAttribute("data-hero-reveal")
        ) {
          seen.push(el.getAttribute("style") ?? "");

      attributes: true,
      subtree: true,
      attributeFilter: ["style"],
    });

      const h1 = document.querySelector("#hero h1");
      const img = document.querySelector("#hero img");
      w.__hero!.h1.push(
        `${h1 && getComputedStyle(h1).opacity} ${img && getComputedStyle(img).opacity}`,
      );
    });
  });

  await heroSettled(page);
  const record = await page.evaluate(
```

```ts
import type { Page } from "@playwright/test";

/** The dev page with both hero CTAs and stand-in target sections (M2.2). */
export const HERO_PREVIEW = "/dev/hero";

/**
 * Resolves once the hero entrance is over (motion.md §5.1): `hero-pending` is
 * gone and every `[data-hero-reveal]` element is at opacity 1 with no
 * transform. A readiness wait (the entrance takes about 0.9 s; the fallback
 * fires at 2.5 s), not a budget. Pages without a hero resolve at once.
 */
export async function heroSettled(page: Page, timeout = 10_000): Promise<void> {
  await page.waitForFunction(
    () =>
      !document.documentElement.classList.contains("hero-pending") &&
      [...document.querySelectorAll("[data-hero-reveal]")].every((el) => {
        const style = getComputedStyle(el);
        return style.opacity === "1" && style.transform === "none";
      }),
    undefined,
    { timeout },
  );
}
```
