## 1. Decisions

### 1.1 Dependencies: none

- No package is added. The first draft's `gsap` 3.15.0 is removed from the prototype (`npm uninstall gsap`); `package.json` and `package-lock.json` are then byte-identical to the repo's, and `node_modules/gsap` is gone.
- For M2.3, which adds gsap with the section reveals (home.md §14), the first draft's findings carry over: gsap 3.15.0 has no install script and no dependencies (`npm approve-scripts --allow-scripts-pending` → nothing pending), it leaves `npm audit` at the M1 baseline of 20, and its "Standard 'no charge' license" (https://gsap.com/standard-license) covers commercial sites. ScrollTrigger ships in the same package.

### 1.2 The M2.2 state of `/`: the hero, with no CTAs yet

- `#collections` (M2.3) and `#bestsellers` (M2.4) don't exist yet. home.md §3.7 says: when the bestsellers section is omitted, the primary CTA becomes "Explore collections" → `#collections` and the text link is dropped; **"If both sections are omitted, the hero shows no CTAs (the h1 and subcopy remain)."** That applies to M2.2. So `/` renders the hero with no `<a>` at all, and no in-page link can point at a missing fragment.
- The rule is one pure function, `heroActions({ collections, bestsellers })` (`components/home/hero-actions.ts`, unit-tested for all four cases). The page passes the flags: M2.2 passes `{ collections: false, bestsellers: false }`. M2.3 passes `collections.length > 0`, and M2.4 passes "the selection holds a bestseller" (§4.6, §5.1).
- **`/dev/hero`** (dev-only, `requireDevPages()`, inside `SiteShell`) renders the same `HomeHero` with both CTAs, followed by two `plain` stand-in sections, `#collections` and `#bestsellers`. Each has an h2 and one line of dev copy, with 900px of empty scroll room. The CTA checks (home.md §14 e2e 5, 11 and 12, focus order, glow), the hero → plain band junction (e2e 13) and the `dev-hero-*` screenshots run there. From M2.4, when `/` has both sections, those checks can move to `/`, and the dev page can be kept or deleted (M2.4's call).
- Below the hero on `/` comes the footer only. The page holds nothing else, and has no placeholder copy.

### 1.3 Markup and layout (home.md §3.1, §3.2)

- `components/home/HomeHero.tsx` (Server Component): `<section id="hero" data-band="solid" data-flush-end aria-labelledby="hero-heading" class="pt-6 md:pt-8 lg:pt-0">` → `.hero-grid` → the text column (`page-container`, reset at lg with `lg:col-start-2 lg:mx-0 lg:max-w-none lg:px-0`) and `.hero-media`.
  - Text column: `hgroup` (eyebrow `type-eyebrow text-text-accent` + `h1#hero-heading type-display-1 max-w-measure-heading`, gap 12), then the subcopy (`mt-4 max-w-measure-intro type-body-lg text-pretty text-text-secondary`), then the CTA group, only when it has a primary CTA (`mt-6 flex flex-wrap items-center gap-8`).
  - `data-hero-reveal` sits only on the eyebrow, the subcopy and the CTA group. It is never on the `hgroup`, the h1, the image or the glow.
  - Each target carries its reveal order (home.md §3.6) as a Tailwind arbitrary-property class, in DOM order: `[--reveal-order:0]` (eyebrow), `[--reveal-order:1]` (subcopy), `[--reveal-order:2]` (CTA group). Classes rather than inline styles, so the targets have no `style` attribute at any point (e2e 14). On `/` in M2.2 the orders are 0 and 1.
- Copy (eyebrow, h1, subcopy, alt) is used verbatim from home.md §11.1 and §11.3. The CTA labels live in `hero-actions.ts`.
- **lg+ grid** (`.hero-grid`, globals.css): four tracks: `[container start offset] [columns 1–5] [--grid-gap] [minmax(0, 1fr)]`, with `align-items: center`. The column maths uses `100%` (the band's width), exactly as `page-container` does:

  - `.hero-media` sits in track 4 (`justify-self: start; max-inline-size: 60rem; aspect-ratio: 5 / 4`).

- Below lg: the text stays in the page container, and `.hero-media` is full bleed (`width: 100%` of the band, not `100vw`), 1:1 at base and 4:3 at md, 32px under the text.

### 1.4 The image (home.md §3.9)

- Both JPEGs are statically imported (`@/public/images/hero/hero-{mobile,desktop}.jpg`), so width and height are known. The build copies them to `/_next/static/media/`.
- There are two `getImageProps()` calls. The desktop call is used only for its `srcSet`, on `<source media="(min-width: 48rem)" sizes="(min-width: 64rem) 81vw, 133.3vw">`. The mobile call supplies the `<img>` (`sizes="100vw"`, `loading="eager"`, `fetchPriority="high"`, `decoding="async"` by default), with `class="size-full object-cover"`. The alt is restated on the `<img>` so `jsx-a11y/alt-text` sees it (no lint suppression).
- **No preload.** The Next 16.4 docs (`node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md`, `preload`) say not to preload when two images could be the LCP element depending on the viewport, nor together with `fetchPriority` / `loading`. In most cases `loading="eager"` or `fetchPriority="high"` should be used instead. `priority` is deprecated in 16. The `<picture>` sits early in the server HTML, so the preload scanner finds it anyway.
- Crop by CSS: `object-position: 50% 80%` at base, `100% 50%` from md. The image is the only eager, high-priority image on the page (e2e 4).
- Formats: Next's default `image/webp`. AVIF isn't enabled: it encodes slower on a cold cache, and a config change belongs to its own task if wanted.
- **Served** (q75 webp, warm optimizer; e2e 4 and the probe, §1.12):

| Viewport | Needed | Source chosen | Bytes |
|---|---|---|---|
| 390 at DPR 3 | 100vw × 3 = 1170px | `hero-mobile` `w=1200` | 66,962 B |
| 768 at DPR 2 (QA minor 3; e2e 4b) | 133.3vw × 2 = 2047.5px ≤ 2048 | `hero-desktop` `w=2048` | **66,846 B** (was `w=3840`, 100,466 B, with `134vw`) |
| 1440 at DPR 1 | 81vw = 1166px | `hero-desktop` `w=1200` | 30,246 B |
| 1920 at DPR 1 | 81vw = 1555px | `hero-desktop` `w=1920` | 60,804 B (the over-fetch home.md accepts) |

- **The md `sizes` is `133.3vw`** (home.md §3.9, spec-review minor 1; was `134vw`). 133.3vw is 1024 / 768, so at exactly 768 the hint is 1023.7px and DPR 2 asks for 2047.5px: the `w=2048` bucket, 33,620 B (33%) less than `w=3840`. The rendered image is 0.3px wider than the hint, which is invisible. Every md width from 769 to 1023 at DPR 2 needs more than 2048px with either value and takes `w=3840`; at DPR 1 the two values pick the same bucket everywhere in md.

### 1.5 Feather and glow (home.md §3.3, §3.4)

- **Feather.** `.hero-image` (bg-raised until the photo decodes, `width/height: 100%`) carries a static `mask-image`:
  - base/md: one vertical gradient (transparent 0 → #000 8% … #000 84% → transparent 100%).
  - lg+: the vertical gradient plus a horizontal one (0 → 24% … 92% → 100%), with `mask-composite: intersect`.
  - The gradients are custom properties. Lightning CSS adds the `-webkit-mask-image` / `-webkit-mask-composite: source-in` prefixes by itself, so the source writes only the standard properties. Because the values are `var()`, the output repeats the identical prefixed line three times, which is harmless.
  - `picture { display: contents }` keeps the `<img>` filling the box. The mask is never animated (the "feather mask" e2e check: no animations on `.hero-image`).
- **Glow.** `.hero-glow` is `aria-hidden`, `data-decorative` (gone in forced colors and print), `display: none` below md.
  - From md: `position: absolute; z-index: -1` inside `.hero-media`. `.hero-media` is `position: relative` and creates no stacking context, so the glow paints in the band's own isolated context, above the band's bg-page and under the masked image.
  - Size: `width: 60%` of the box, `aspect-ratio: 1`, `background-image: var(--gradient-candle-glow)` (a closest-side circle, so r = 30% of the box).
  - Position: `inset-inline-start: 46.7%` (md) / `43.1%` (lg+), `inset-block-start: 57%`, with a static `translate: -50% -50%`. This is sized from home.md §3.4, not shot-list.json's superseded `glowPlacement`.
  - No breathing loop and no box-shadow on the image. At 1440 the glow starts more than 100px clear of the text column (e2e 6 asserts at least 100 at 1440).

### 1.6 CTA recipe (tokens.md §2.3, rule 9; motion.md §5)

- `components/ui/button.ts`: `primaryButtonClasses({ glow = true })` returns a class string, so a plain `<a>`, a `<Link>` or a `<button>` can wear it.
- The recipe: ember-400 fill, text-inverse, pill, `type-button`, `px-6 py-3`, `min-h-12`, a transparent 1px border, `hover:bg-cta-bg-hover`, `active:bg-cta-bg-active`, `active:scale-(--motion-scale-press)` (1 under reduced motion), and `transition-[background-color,scale]` at duration-fast / ease-standard.
- The glow is an `::after` (`-inset-px` = the border box, `rounded-[inherit]`, `shadow-glow-candle`, opacity 0 → 1 on `hover` / `focus-visible`, opacity transition at duration-fast; kept under reduced motion, motion.md §6.2). Its footprint is the border box plus 26px.
- `glow: false` is the rule-9 no-glow variant (no `::after` at all). The hero uses the default.
- The hero's primary CTA is `w-full md:w-auto`. The text link is `type-nav text-link underline decoration-1 underline-offset-[0.2em] hover:text-link-hover inline-flex min-h-(--size-touch) gap-2`, followed by the 16px `ArrowRightIcon`.
  - `ArrowRightIcon` is new in `components/icons/glyphs.tsx`, and `SectionHeading`'s inline copy of the same SVG now uses it. That is the only change to SectionHeading.
- Both CTAs are plain `<a>` (in-page fragments, never prefetched).


### 1.7 Entrance motion (motion.md §5.1, home.md §3.6, §9): CSS only

- **In `app/globals.css`**, inside the hero's `@layer components` block (render-blocking, so it applies at first paint), exactly motion.md §5.1's CSS:
  - `@media (prefers-reduced-motion: no-preference) { html:not([data-motion="off"]) [data-hero-reveal] { animation: hero-reveal var(--duration-slower) var(--ease-enter) backwards; animation-delay: calc(var(--reveal-order, 0) * var(--stagger-loose)); } }`
  - `@keyframes hero-reveal { from { opacity: 0; transform: translateY(var(--motion-distance-lg)); } }`, at the top level after the block. Only a `from` keyframe, so it runs to the element's own style.
  - Compiled (Lightning CSS), checked in the build output: `animation:hero-reveal var(--duration-slower) var(--ease-enter) backwards;animation-delay:calc(var(--reveal-order,0) * var(--stagger-loose))` and `@keyframes hero-reveal{0%{opacity:0;transform:translateY(var(--motion-distance-lg))}}`.
- Values: 24px, 700ms, `cubic-bezier(0.165, 0.84, 0.44, 1)`, delays 0 / 100 / 200ms (`--reveal-order` 0/1/2, §1.3), fill `backwards`. The whole entrance ends 0.9 s after the hero's first paint (0.8 s on `/` in M2.2, with two targets).
- **No JS touches the hero.** `HomeHero` stays a Server Component with deterministic markup (motion.md §5.1 step 2: a hydration mismatch would re-create the DOM and replay the entrance). No island, no `will-change`, no inline style at any point.
- **Reduced motion:** nothing is declared, so `animation-name` is `none` (e2e 7). **`html[data-motion="off"]`** (M8.8b) set before first paint: excluded by the selector (e2e 16).
- **No JS:** the same as with JS; the animation ends visible on its own (e2e 15, parallel pass: with every chunk aborted, every target's `animationend` fires and ends at opacity 1. e2e 15b, `@perf`, serial pass: the last `animationend` is within 1.5 s of DOMContentLoaded; 818–1,057 ms in the prototype's parallel run).
- **Retired** (motion.md §5.1 step 8): `app/hero-pending.ts` (deleted), the `<head>` script in `app/layout.tsx`, the `.hero-pending [data-hero-reveal]` rule in globals.css's base layer, and tokens.spec's "the head script marks hero-pending only when motion is allowed". `suppressHydrationWarning` goes too: nothing else changes `<html>` before hydration (the starfield only reads `data-motion`). The layout comment says M8.8b's `data-motion` head script will need it back.
- **CLS 0:** only opacity and transform move, and all space is reserved by layout. **LCP:** the h1 and the image are never animated (e2e 14 records both at opacity 1 with no animations at DOMContentLoaded).

### 1.8 Bands: the flush end and the collapse fix (layout-shell §5.1 as amended; home.md §2.3)

The fix is in `app/globals.css`, `@layer components`:

```css
[data-band][data-flush-end] { padding-block-end: 0; }
[data-band][data-flush-end]:not(:has(~ [data-band])) { padding-block-end: var(--section-y); }
:is([data-band="plain"], [data-band="solid"]):not([data-flush-end])
  + :is([data-band="plain"], [data-band="solid"]),
[data-band="sunken"]:not([data-flush-end]) + [data-band="sunken"] { padding-block-start: 0; }
```

- `data-flush-end` = "this band ends at 0". The band after it is left out of the collapse, so it keeps its `--section-y`. Measured on `/dev/hero`: hero `24px / 0` (390), `0 / 0` (1440); `#collections` top 64 / 128; `#bestsellers` top 0 (collapsed after a plain band).
- A band directly after a band that is not flush-ending still collapses as before, whether or not the second band is itself flush-ending.
- **While the hero is the last band** (M2.2 on `/`), the second rule gives it `--section-y` at the bottom (64 / 128px between the feathered image and the footer). This was PUSHBACK 1 of the first draft; design-agent approved it (home.md, "Hero follow-ups from M2.2" item 1, §2.3, §3.2, §14 e2e 13).
  - The rule switches itself off as soon as M2.3 puts a band after the hero (see the M2.3 caveats in §1.11).
  - `:has(~ …)` is in every browser Tailwind 4 targets (Safari 16.4+, Chrome 111+, Firefox 128+).
- The shell's band-collapse e2e test now builds its bands in a wrapper of its own, so the page's hero takes no part. It gains the flush cases: solid → solid+flush collapses; plain after a flush-ending band keeps `--section-y`; a flush-ending band's bottom is 0, or `--section-y` when it is the last band. The M1.13 tech spec blocks are resynced (§2.3).

```ts
/**
 * The hero's calls to action (design/pages/home.md §3.7, §3.8, §11.1). Both are
 * in-page anchors, so a CTA is rendered only when the section it jumps to is on
 * the page: there is never a dead fragment link.
 *
 * - both sections: "Shop favorites" (primary) → #bestsellers, then the text link
 *   "Explore collections" → #collections;
 * - no bestsellers section: "Explore collections" becomes the primary CTA and the
 *   text link is not rendered;
 * - no collections section: the primary CTA only;
 * - neither (M2.2, before M2.3/M2.4 add the sections): no CTAs at all.
 *
 * Plain data and a pure function with no imports (unit-tested in Node).
 */

export type HeroAction = {
  kind: "primary" | "link";
  label: string;
  href: `#${string}`;
};

/** Which home sections are rendered on the page (home.md §4.6, §5.1). */
export type HomeSections = {
  collections: boolean;
  bestsellers: boolean;
};

export const SHOP_FAVORITES = "Shop favorites";
export const EXPLORE_COLLECTIONS = "Explore collections";

export function heroActions(sections: HomeSections): HeroAction[] {
  const actions: HeroAction[] = [];
  if (sections.bestsellers) {
    actions.push({
      kind: "primary",
      label: SHOP_FAVORITES,
      href: "#bestsellers",
    });
  }
  if (sections.collections) {
    actions.push({
      kind: sections.bestsellers ? "link" : "primary",
      label: EXPLORE_COLLECTIONS,
      href: "#collections",
    });
  }
  return actions;
}
```

```ts
 * The primary (ember) CTA recipe (tokens.md §2.3, §2.5 rule 9, §6.2; motion.md
```

```ts
/** The computed animation of each `[data-hero-reveal]`, in DOM order. */
async function revealAnimations(page: Page) {
  return page.locator("[data-hero-reveal]").evaluateAll((els) =>
    els.map((el) => {
      const s = getComputedStyle(el);
      return {
        name: s.animationName,
        duration: s.animationDuration,
        easing: s.animationTimingFunction,
        fill: s.animationFillMode,
        delay: s.animationDelay,
        running: el.getAnimations().length,
      };
    }),
  );
}

test.describe("without the app JS", () => {
  test.use({ expectedIssues: [/\/_next\/static\/chunks\//] });

  type NoJsRun = {
    route: string;
    targets: number;
    ends: number;
    /** The last hero-reveal animationend, in ms after DOMContentLoaded. */
    last: number;
    opacities: string[];
  };

  /**
   * Loads "/" and /dev/hero with every JS chunk aborted and records, per
   * route, the hero-reveal animationend events (page time) and the targets'
   * final opacity. Returns the runs and how many chunk requests were aborted.
   */
  async function withoutJs(
    page: Page,
  ): Promise<{ runs: NoJsRun[]; aborted: number }> {
    let aborted = 0;
    await page.route("**/_next/static/chunks/*.js", (route) => {
      aborted += 1;
      return route.abort();
    });
    await page.addInitScript(() => {
      const w = window as Window & { __t?: { dcl: number; ends: number[] } };
      const t = { dcl: -1, ends: [] as number[] };
      w.__t = t;
      document.addEventListener("DOMContentLoaded", () => {
        t.dcl = performance.now();
      });
      document.addEventListener(
        "animationend",
        (event) => {
          if (event.animationName === "hero-reveal") {
            t.ends.push(performance.now());
          }
        },
        true,
      );
    });
    const runs: NoJsRun[] = [];
    for (const route of ["/", HERO_PREVIEW]) {
      await page.goto(route, { waitUntil: "domcontentloaded" });
      const targets = await page.locator("[data-hero-reveal]").count();
      await expect
        .poll(
          () =>
            page.evaluate(
              () =>
                (window as Window & { __t?: { ends: number[] } }).__t!.ends
                  .length,
            ),
          { message: route },
        )
        .toBe(targets);
      const t = await page.evaluate(
        () =>
          (window as Window & { __t?: { dcl: number; ends: number[] } }).__t!,
      );
      const opacities = await page
        .locator("[data-hero-reveal]")
        .evaluateAll((els) => els.map((el) => getComputedStyle(el).opacity));
      runs.push({
        route,
        targets,
        ends: t.ends.length,
        last: Math.max(...t.ends) - t.dcl,
        opacities,
      });
    }
    return { runs, aborted };
  }

  test("15. the entrance ends visible with every JS chunk aborted", async ({
    page,
  }, testInfo) => {
    test.skip(
      testInfo.project.name.endsWith("-reduced-motion"),
      "no-preference only",
    );
    const { runs, aborted } = await withoutJs(page);
    for (const run of runs) {
      expect(run.targets, run.route).toBeGreaterThan(0);
      expect(run.ends, run.route).toBe(run.targets);
      expect(run.opacities, run.route).toEqual(Array(run.targets).fill("1"));
    }
    expect(aborted).toBeGreaterThan(0);
  });

  // The wall-clock bound runs in the serial @perf pass only: under parallel
  // load the animationend dispatch can lag without anything being wrong.
  test(
    "15b. without JS the last animationend is within 1.5 s of DOMContentLoaded",
    { tag: "@perf" },
    async ({ page }, testInfo) => {
      test.skip(
        testInfo.project.name.endsWith("-reduced-motion"),
        "no-preference only",
      );
      const { runs, aborted } = await withoutJs(page);
      expect(aborted).toBeGreaterThan(0);
      for (const run of runs) {
```

```ts
import type { Page } from "@playwright/test";

/** The dev page with both hero CTAs and stand-in target sections (M2.2). */
export const HERO_PREVIEW = "/dev/hero";

/**
 * Resolves once the hero entrance is over (motion.md §5.1): every animation on
 * the `[data-hero-reveal]` elements has finished (the CSS `hero-reveal`
 * keyframes, at most 0.9 s from the hero's first paint), and each is at
 * opacity 1 with no transform. A readiness wait, not a budget. Pages without a
 * hero, and reduced motion (no animation declared), resolve at once.
 */
export async function heroSettled(page: Page, timeout = 10_000): Promise<void> {
  // Bounded, so a paused animation fails the check below instead of hanging.
  await page.evaluate(async (ms) => {
    const targets = [...document.querySelectorAll("[data-hero-reveal]")];
    await Promise.race([
      Promise.all(
        targets
          .flatMap((el) => el.getAnimations())
          .map((animation) => animation.finished.catch(() => undefined)),
      ),
      new Promise((resolve) => setTimeout(resolve, ms)),
    ]);
  }, timeout);
  await page.waitForFunction(
    () =>
      [...document.querySelectorAll("[data-hero-reveal]")].every((el) => {
        const style = getComputedStyle(el);
        return style.opacity === "1" && style.transform === "none";
      }),
    undefined,
    { timeout },
  );
}
```
