## 1. Decisions

- **Two Playwright passes in one `firebase emulators:exec`, driven by `scripts/e2e.ts` (QA fix 1).** `npm run test:e2e` runs `scripts/e2e.ts` inside one `emulators:exec` (auth, firestore, storage, as before), started through `scripts/emulators-exec.ts` (§1.1). The script:
  1. builds once (`next build` with `ENABLE_DEV_PAGES=true`, the same build the webServer made);
  2. runs the **parallel pass**: `playwright test --grep-invert @perf` (workers as configured: the default, half the logical CPUs);
  3. runs the **@perf pass**: `playwright test --grep @perf --workers=1 --output=test-results/perf`, with `PLAYWRIGHT_HTML_OUTPUT_DIR=playwright-report/perf`;
  4. always runs both passes, prints one summary line, and exits with the parallel pass's code if it failed, else the @perf pass's. `scripts/emulators-exec.ts` exits with that recorded code (§1.1; verified, §3).
  - **Why a Node script, not a chained npm string.** The inner command of `emulators:exec` goes through `cmd.exe` on Windows (M1.2/M1.20 lesson: only escaped double quotes work, and `&&` / `;` chains differ between shells, and a `&&` chain would skip pass 2 when pass 1 fails). The script spawns `process.execPath` with the resolved CLI files (`@playwright/test/cli`, `next/dist/bin/next`) and an argument array: **no shell, so no quoting** on any platform. The package.json line has no inner quoting at all: `tsx scripts/emulators-exec.ts --only auth,firestore,storage -- scripts/e2e.ts`.
  - **Why not Playwright `dependencies` / a "perf" project.** Projects have no per-project `workers` setting. A project with `fullyParallel: false` only serializes tests within one file; its tests still run alongside the other projects' workers, which is exactly the CPU sharing that broke the budgets. A separate invocation with `--workers=1` is the only form that guarantees nothing else runs during a budget.
  - **One build, two server starts.** `E2E_PREBUILT=1` (set by the script for both passes) makes the webServer command `npm run start …` only. Without it (`npx playwright test`, `test:e2e:ui`, filtered runs by hand) the config still builds first, as today. Each pass starts and stops its own `next start` on 6130 (`reuseExistingServer: false` unchanged), about 2 s each.
  - **Output and reports.** Playwright empties each invocation's output folder at start. The parallel pass owns `test-results/` (all screenshots: `test-results/screenshots/`, 40 files today) and `playwright-report/`. The @perf pass writes to `test-results/perf/` and `playwright-report/perf/`, so it empties only its own subfolders and the first pass's screenshots and report survive (verified after every full run: 40/40 screenshots). The next run's parallel pass clears both. No `.gitignore`, ESLint or Prettier change: both subfolders sit inside already-ignored folders.
  - **Filtered runs (QA spec issue 2).** `npm run test:e2e -- <args>` now works directly (npm appends the args after `-- scripts/e2e.ts`, and `scripts/emulators-exec.ts` passes them on unquoted). They go to both passes. **Supported:** file filters (`tests/e2e/starfield.spec.ts`, `starfield.spec.ts:42`) and `--project=<name>` (other Playwright flags are passed through untested). **Refused,** before the build, with exit 1 and a message naming the flag and what is supported: `--grep`, `-g`, `--grep-invert`, `--workers`, `-j`, `--output`, in the `--flag value`, `--flag=value` and short `-j4`/`-g@tag` forms. Each pass sets these itself: a user `--grep` would replace `--grep @perf`, `--workers=N` would make the serial pass parallel, and `--output` would put both passes in one folder, emptied by the second. Anything else needs a hand-run `npx playwright test …` under `emulators:exec`. With arguments, both passes add `--pass-with-no-tests` (a filter may leave one pass empty). The full run does not, so a pass that finds no tests (e.g. lost tags) still fails.
  - **Budgets: all unchanged.** Every `@perf` assertion keeps its number. The per-attempt test keeps `if (test.info().config.workers === 1) expect(median).toBeLessThanOrEqual(4)`; in `npm run test:e2e` the @perf pass always has one worker, so the 4 ms median is now always asserted there. A hand-run parallel `npx playwright test` still skips only that one line, as before.
  - **`test:e2e:ui` unchanged** (one interactive invocation, for humans).
- **Test 12 "demo: launches…" no longer depends on wall-clock bounds (QA fix 2; rewrite, not a tag).** It stays in the parallel pass, so it keeps covering the streak's behaviour under the same load as every other functional test. The `≤ 800 ms` bound is replaced:
  - (b)/(c) The mid-flight sample is taken at the first frame at or after 600 ms (`≥ 600` kept). It must fall **before the fade-out starts**: `effect.getComputedTiming().progress` ≤ the plateau end, read from the keyframes (the largest `computedOffset` of a keyframe with opacity 1; 0.55 today, i.e. 770 ms of 1400). Opacity > 0.5 and connected are kept. A late frame is not a fault of the streak, so the sample is **retaken on the next streak** (the demo relaunches every 3 s), at most 3 streaks. **Every** streak watched must animate only `opacity` and `transform`, stay connected at its sample, resolve `finished` (an `AbortError` from a cancel still fails) and be removed at its end. The samples are annotated.
  - "`data-sf-streaks` then increments again at the next 3 s attempt" is counted in `sf-attempt` measures (one per check), not in seconds: the number of measures between the streak's end and the next launch must be exactly 3 (the first attempt to run after the end launches in its third check). Counts are read as `getEntriesByName("sf-attempt").length` at both moments, never compared by timestamp: Chromium coarsens `performance.now()` and a mark can equal the observer's time (a timestamp version failed exactly that way in the prototype, 4 instead of 5 in the test below).
  - (d) The streak is found and the 1 px scroll made **in one `evaluate`** (the old `waitForSelector` + `evaluate` could see the streak end in between: prototype run 1 failed with `null.getAnimations`).
  - (a) "within 4 s of animating" is kept as specified (it passed in every run).
  - Why the rewrite and not `@perf`: the test checks behaviour (no cancel, removal, relaunch), not a CPU budget. Tagging it would hide it from load, and a "budget" of 800 ms would still be a guess about frame timing.
- **The same robustness for the two other streak tests that failed in the prototype's first parallel run** (they were not in QA's list, but they failed the same way under load):
  - **"12. demo refused then clear"**: the page records the sequence instead of the runner timing it. The in-page observer counts text refusals and launches **until the first launch after the refusal**, and stores the `sf-attempt` count at the refusal and at that launch. Asserted: no launch before the refusal, exactly one `text` refusal (checks 2–3 were clear), exactly **5** measures between them (checks 2–3 of the refused attempt, then the next attempt's three checks, the third launching), and the launch sets `before + 1`. The old version read `data-sf-streaks` after a 500 ms runner wait and saw 3 instead of 1 when the runner stalled. The `refused` carry mutation still fails it (it would launch after 2 measures).
  - **Screenshot `dev-starfield-streak`**: one in-page loop (15 s readiness deadline) finds exactly one running streak and freezes it at 700 ms (twinkles at 0) in the same task; still asserts `{ streaks: 1, time: 700 }`. The old `waitForSelector(…, 4000)` timed out under load.
  - In-page waits for a streak or a launch are **readiness waits** (10–15 s deadlines), not budgets: a stall only makes them slower, never wrong.
- **CLS: no slack (QA fix 3).** `support/layout-shift.ts` gains `layoutShifts(page)`, returning `{ total, shifts }`, each shift with `value`, `startTime` and `sources` (`node`: a short `tag#id[data-*]` path of the node and up to three ancestors, `""` if the node is gone; `previousRect`, `currentRect`). `layoutShift(page)` stays (returns `total`), so the four other callers are unchanged. Test 15 "no layout shift" uses `layoutShifts`, annotates the shifts (`none (CLS 0)` when empty) and asserts `total === 0`; `shiftsInSlot === 0` and the LCP check are unchanged. It runs in the serial pass, where it was 0 in every run (§3), so no cause had to be fixed.
- **`waitForState` default timeout 10 s → 20 s (QA fix 4),** documented as a readiness wait.
- **Retries: not added (QA fix 5, optional).** The serial pass showed no flake: 15/15 in each of the 3 full runs and 30/30 with `--repeat-each=2`. Retries stay 0 everywhere.
- **`.env.example`**: documents `E2E_PREBUILT` and `EMULATORS_EXEC_DIR` as commented lines (never set by hand), which also puts them in `check:client-bundle`'s server-name scan (verified: passes, both listed). The `ENABLE_DEV_PAGES` comment names scripts/e2e.ts as the second setter.

### 1.1 Exit code: firebase-tools usage tracking (QA spec issue 1)

**Finding (source-verified in `node_modules/firebase-tools/lib`, 15.32.1).** After the command's runner resolves, `lib/command.js:112-129` sends usage events and awaits them as `withTimeout(5000, Promise.all([trackGA4(...), trackEmulator(...)]))` before `process.exit()`. `withTimeout` (`lib/utils.js:296-305`) rejects with `Error("Timed out.")` when the GA4 `fetch` to `www.google-analytics.com` is slow; the rejection lands in the same chain's `.catch` (line 131), which calls `errorOut` (line 155, `lib/errorOut.js`): a non-`FirebaseError` becomes "An unexpected error has occurred." with **exit 2**. So `emulators:exec` exits 2 after a script that exited 0 (QA: 2 of 9 runs; m-d.firebase-debug.log shows the `utils.js:298` stack 5 s after "Stopping Logging Emulator"). The error path (script failed) awaits the same timeout but then still exits non-zero, so failures were never masked.

**Per-process opt-out: none that is fit for use.** Tracking runs only if `usageEnabled()` (`lib/track.js:34-36`): `(IS_FIREBASE_CLI || isFirebaseMcp()) && configstore.get("usage")`. `IS_FIREBASE_CLI` is set unconditionally by `lib/bin/cli.js:52`; `usage` is the user's global consent, written only by `firebase login` (`commands/login.js:77,88`) and deleted by logout (`auth.js:511`). No environment variable, flag, CI detection or `--non-interactive` affects it (`--non-interactive` only changes the `interactive` event parameter; no `process.env.*` name in `lib/` mentions usage, analytics, tracking or telemetry besides the GA4 measurement-ID/secret overrides and `FIREBASE_CLI_MP_VALIDATE`, which only adds logging). The one indirect lever is `XDG_CONFIG_HOME`: configstore 5 (`node_modules/configstore/index.js` via `xdg-basedir`) would read an empty config from a redirected folder, so `usage` is unset. Rejected: it relies on a dependency's internal path, hides the whole user config (login, update-notifier state) rather than one setting, is inherited by Next and Playwright, and is not an opt-out firebase-tools documents. The user's global config is not touched (orchestrator constraint).

**Fix: invert the harness (option ii), `scripts/emulators-exec.ts` (new, §4).** `tsx scripts/emulators-exec.ts --only <emulators> -- <tsx arguments…>`:
1. writes the tsx arguments to `command.json` in a fresh temp folder (`os.tmpdir()/starflames-emulators-exec-<pid>-*`, its own pid in the name);
2. spawns `node <firebase-tools/lib/bin/firebase.js> emulators:exec --project demo-starflames --only <emulators> "<node> <tsx cli> <this script> --inner"` (absolute, double-quoted paths: firebase runs the inner line through a shell, and `C:\Program Files\nodejs\node.exe` has a space; verified in the "Running script" log line), with `EMULATORS_EXEC_DIR` pointing at the folder;
3. the inner run (`--inner`) spawns `node <tsx cli> …command.json` with no shell, writes `result.json` `{ status }` (a signal counts as 1) and exits with it;
4. back outside, it removes the folder and exits with the **recorded** status. Firebase's own exit code counts only when nothing was recorded (emulators failed to start, bad `--only`, the script never ran or was killed before writing): then it exits with firebase's code (1 if that was 0). When firebase exits non-zero after a recorded 0, it prints `[emulators-exec] the command passed; firebase exited 2 after it (its usage-tracking timeout, …), so that exit is ignored` under firebase's "unexpected error" line, so the log explains itself.
- Arguments travel in the file, not on the inner command line, so no quoting rules apply on any shell. `--project demo-starflames` is fixed in the script (never a real project).
- **Applied to:** `test:e2e` and `test:rules` (both run `firebase emulators:exec` and hit the same path; QA's first `test:rules` run in this round showed it, §3). **Not needed:** `smoke:firebase` (plain `tsx`, no firebase-tools process; it needs `npm run emulators` already running) and `npm run emulators` (interactive, exit code not consumed). **Left as is:** `test:e2e:ui` (interactive, for humans; a spurious 2 after closing the UI is harmless).
- Cost: one more Node process (the inner tsx); in the 5 s timeout case the run still takes those 5 s, as before.

**Interrupted runs (QA spec-review minor 1).** The fix-round-1 script died inside `spawnSync` on Ctrl+C and left its temp folder (reproduced: folder left, exit 3221225786). Why no-op listeners alone were not enough (source-verified, tsx 4.23.15 `dist/cli.mjs` `relaySignals`, `dist/preflight.cjs`): the script runs as the child of tsx's own CLI process. On SIGINT that process waits 30 ms for the child's event loop to report the signal over IPC, and kills the child when no report comes, which is always the case while the child is blocked in `spawnSync`. And firebase does not stop at once on Ctrl+C: it starts a clean shutdown (its hub and `processKillSignal` listeners), so the outer has to stay alive until firebase exits. The fix:
- **Ctrl+C (SIGINT):** both modes install no-op `SIGINT` and `SIGBREAK` listeners, and every spawn is async (`spawn` + a promise), so the event loop answers tsx's check and the script survives. Firebase stops its emulators and exits; the script then removes the folder and exits with the first non-zero of the recorded code and firebase's, else 1: **an interrupted run never exits 0** (firebase itself exits 0 after a Ctrl+C shutdown). It logs `[emulators-exec] interrupted (SIGINT); command <code|unrecorded>, firebase <code>`. Firebase may finish before the inner command does (it does not wait for the script on Ctrl+C); the inner then finds the folder gone and skips writing `result.json` silently.
- **Ctrl+Break (SIGBREAK): not survivable on Windows, so swept instead.** tsx's CLI and npm have no SIGBREAK listener and die at once, and libuv puts every child it spawns in a kill-on-close job, so their descendants, this script included, are killed with them (observed: the script received SIGBREAK, then died without its `exit` event). So each outer run first removes every `starflames-emulators-exec-<pid>-*` folder whose pid is no longer running (`process.kill(pid, 0)`; `EPERM` counts as running). A folder left by a killed run (Ctrl+Break, a closed terminal, Task Manager) lives until the next `test:rules` / `test:e2e`; a concurrent run's folder is kept. The exit code of a Ctrl+Break run is the dead parent's (non-zero, `STATUS_CONTROL_C_EXIT`). **Known limit, firebase-tools' own:** `emulators:exec` has no SIGBREAK handler, so Ctrl+Break can leave the Firestore emulator (Java) running on 6104–6105 (Java turns Ctrl+Break into a thread dump); it keeps those ports busy until stopped, which the next run reports as "port taken". Use Ctrl+C.
- In `scripts/e2e.ts` (unchanged): on Ctrl+C its tsx CLI process kills it, since it waits in `spawnSync`, so the @perf pass does not start after an interrupted parallel pass (verified below).

**scripts/emulators-exec.ts** (new):
```ts
// Runs a tsx command under `firebase emulators:exec` and exits with that command's own code
// (M1.20b). Usage: tsx scripts/emulators-exec.ts --only <emulators> -- <tsx arguments...>
// e.g. `--only firestore,storage -- --test tests/rules/a.test.ts` runs `tsx --test ...`.
//
// Why: firebase-tools 15 awaits its usage tracking with a 5s timeout after the script has
// exited (lib/command.js, utils.withTimeout); when that times out it reports "An unexpected
// error has occurred" and exits 2, even though every test passed. So the inner command records
// its exit code in a file, and this script exits with the recorded code. Only a firebase failure
// with no recorded code (the emulators did not start, or the script never ran) fails as itself.
// The command and the result travel in a temp folder (EMULATORS_EXEC_DIR), not on the inner
// command line, which firebase runs through a shell: no quoting on any platform.
//
// Interrupts. Ctrl+C reaches every process in the console: this script then waits for firebase
// to stop its emulators (no-op listeners, and an async spawn: tsx's own CLI process kills a child
// whose event loop cannot answer the signal), removes the folder and exits non-zero. Ctrl+Break
// kills tsx's and npm's processes, and Windows takes their children with them, this one included:
// so each run first removes the folders of runs whose process is gone (the pid is in the name).
import { spawn } from "node:child_process";
import {
  mkdtempSync,
  readdirSync,
  readFileSync,
  rmSync,
  writeFileSync,
} from "node:fs";
import { createRequire } from "node:module";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { fileURLToPath } from "node:url";

const root = join(import.meta.dirname, "..");
const require = createRequire(import.meta.url);
const tsxCli = require.resolve("tsx/cli");
const self = fileURLToPath(import.meta.url);
const tag = "[emulators-exec]";

let interrupted: string | undefined;
for (const signal of ["SIGINT", "SIGBREAK"] as const) {
  process.on(signal, () => {
    interrupted ??= signal;
  });
}

function spawnNode(
  args: string[],
  env: NodeJS.ProcessEnv = process.env,
): Promise<number> {
  return new Promise((resolve) => {
    const child = spawn(process.execPath, args, {
      cwd: root,
      stdio: "inherit",
      env,
    });
    child.on("error", (error) => {
      console.error(`${tag} ${error.message}`);
      resolve(1);
    });
    // A signal (code null) counts as a failure.
    child.on("exit", (code) => resolve(code ?? 1));
  });
}

function isRunning(pid: number): boolean {
  try {
    process.kill(pid, 0); // signal 0: an existence check, nothing is sent
    return true;
  } catch (error) {
    // EPERM: it exists but belongs to someone else.
    return (error as NodeJS.ErrnoException).code === "EPERM";
  }
}

async function main(): Promise<number> {
  const dir = process.env.EMULATORS_EXEC_DIR;
  const args = process.argv.slice(2);

  if (args[0] === "--inner" && dir) {
    // Inside emulators:exec: run the command, record its code, exit with it.
    const command = JSON.parse(
      readFileSync(join(dir, "command.json"), "utf8"),
    ) as string[];
    const status = await spawnNode([tsxCli, ...command]);
    try {
      writeFileSync(join(dir, "result.json"), JSON.stringify({ status }));
    } catch {
      // The folder is gone: firebase stopped on Ctrl+C without waiting for this command, and
      // the outer run has already cleaned up and exited non-zero.
    }
    return status;
  }

  const split = args.indexOf("--");
  const onlyAt = args.indexOf("--only");
  const only = onlyAt >= 0 && onlyAt < split ? args[onlyAt + 1] : undefined;
  if (split < 0 || !only || split === args.length - 1) {
    console.error(
      `${tag} usage: tsx scripts/emulators-exec.ts --only <emulators> -- <tsx arguments...>`,
    );
    return 1;
  }

  // Folders left by a killed run: starflames-emulators-exec-<pid>-*, that pid no longer running.
  const prefix = "starflames-emulators-exec-";
  for (const name of readdirSync(tmpdir())) {
    const pid = Number(new RegExp(`^${prefix}(\\d+)-`).exec(name)?.[1]);
    if (pid && !isRunning(pid)) {
      rmSync(join(tmpdir(), name), { recursive: true, force: true });
    }
  }
  const work = mkdtempSync(join(tmpdir(), `${prefix}${process.pid}-`));
  writeFileSync(
    join(work, "command.json"),
    JSON.stringify(args.slice(split + 1)),
  );
  // Absolute, quoted paths: firebase runs this line through a shell (cmd.exe on Windows),
  // and the Node path may contain spaces.
  const inner = `"${process.execPath}" "${tsxCli}" "${self}" --inner`;
  const firebase = await spawnNode(
    [
      require.resolve("firebase-tools/lib/bin/firebase.js"),
      "emulators:exec",
      "--project",
      "demo-starflames",
      "--only",
      only,
      inner,
    ],
    { ...process.env, EMULATORS_EXEC_DIR: work },
  );

  let recorded: number | undefined;
  try {
    const result = JSON.parse(
      readFileSync(join(work, "result.json"), "utf8"),
    ) as { status: number };
    recorded = result.status;
  } catch {
    recorded = undefined; // the command never finished
  }
  rmSync(work, { recursive: true, force: true });

  if (interrupted) {
    // The first non-zero of the recorded code and firebase's; never 0.
    const status = [recorded, firebase].find((s) => s !== undefined && s !== 0);
    console.error(
      `${tag} interrupted (${interrupted}); command ${recorded ?? "unrecorded"}, ` +
        `firebase ${firebase}`,
    );
    return status ?? 1;
  }
  if (recorded === undefined) {
    console.error(
      `${tag} firebase exited ${firebase} before the command recorded a result`,
    );
    return firebase === 0 ? 1 : firebase;
  }
  if (firebase !== 0 && recorded === 0) {
    console.log(
      `${tag} the command passed; firebase exited ${firebase} after it ` +
        "(its usage-tracking timeout, see this script's header), so that exit is ignored",
    );
  }
  return recorded;
}

main().then(
  (status) => process.exit(status),
  (error: unknown) => {
    console.error(`${tag} ${String(error)}`);
    process.exit(1);
  },
);
```

import type { Page } from "@playwright/test";

type Rect = { x: number; y: number; width: number; height: number };

/** One layout-shift entry and the nodes that moved (layout-shift `sources`). */
export type Shift = {
  value: number;
  startTime: number;
  sources: { node: string; previousRect: Rect; currentRect: Rect }[];
};

/**
 * Every layout-shift entry without recent input, once the fonts have settled,
 * with its sources: a short selector path for each moved node ("" if the node
 * is gone) and its rects. layout-shift entries are only exposed to a buffered
 * PerformanceObserver.
 */
export async function layoutShifts(
  page: Page,
): Promise<{ total: number; shifts: Shift[] }> {
  return page.evaluate(async () => {
    await document.fonts.ready;
    // tag#id[data-*] for the node and up to three ancestors, nearest last.
    const describe = (node: Node | null | undefined): string => {
      const parts: string[] = [];
      let el: Element | null =
        node instanceof Element ? node : (node?.parentElement ?? null);
      if (node && !(node instanceof Element)) parts.push(node.nodeName);
      for (let depth = 0; el && depth < 4; depth++, el = el.parentElement) {
        const data = [...el.attributes]
          .filter((a) => a.name.startsWith("data-"))
          .map((a) => `[${a.name}]`)
          .join("");
        parts.unshift(
          `${el.tagName.toLowerCase()}${el.id ? `#${el.id}` : ""}${data}`,
        );
      }
      return node ? parts.join(" > ") : "";
    };
    const rect = (r: DOMRectReadOnly): Rect => ({
      x: r.x,
      y: r.y,
      width: r.width,
      height: r.height,
    });
    return new Promise<{ total: number; shifts: Shift[] }>((resolve) => {
      const shifts: Shift[] = [];
      new PerformanceObserver((list) => {
        for (const entry of list.getEntries() as (PerformanceEntry & {
          value: number;
          hadRecentInput: boolean;
          sources: {
            node?: Node | null;
            previousRect: DOMRectReadOnly;
            currentRect: DOMRectReadOnly;
          }[];
        })[]) {
          if (entry.hadRecentInput) continue;
          shifts.push({
            value: entry.value,
            startTime: entry.startTime,
            sources: entry.sources.map((s) => ({
              node: describe(s.node),
              previousRect: rect(s.previousRect),
              currentRect: rect(s.currentRect),
            })),
          });
        }
      }).observe({ type: "layout-shift", buffered: true });
      setTimeout(
        () =>
          resolve({
            total: shifts.reduce((sum, s) => sum + s.value, 0),
            shifts,
          }),
        500,
      );
    });
  });
}

/** Sum of layout-shift values (without recent input) once the fonts have settled. */
export async function layoutShift(page: Page): Promise<number> {
  return (await layoutShifts(page)).total;
}

  // first frame at or after 600ms, and it must fall before the fade-out starts:
  // getComputedTiming().progress at most the end of the opacity-1 plateau, read
  // from the keyframe offsets. A frame that lands late is no failure of the
  // streak, so the sample is retaken on the next streak (the demo relaunches
  // every 3s), at most 3 streaks. Every streak watched must survive to its end
  // and be removed. "Increments again at the next 3s attempt" is counted in
  // sf-attempt measures (one per check, read by count, not by timestamp): the
  // first attempt to run after the streak's end launches in its third check.
  const result = await page.evaluate(async () => {
    const slotEl = document.querySelector("[data-starfield]")!;
    const frame = () => new Promise((r) => requestAnimationFrame(r));
    const measures = () => performance.getEntriesByName("sf-attempt").length;
    // At the next change of data-sf-streaks: the measures so far (null after `ms`).
    const nextLaunch = (ms: number) =>
      new Promise<number | null>((resolve) => {
        const timer = setTimeout(() => {
          observer.disconnect();
          resolve(null);
        }, ms);
        const observer = new MutationObserver(() => {
          clearTimeout(timer);
          observer.disconnect();
          resolve(measures());
        });
        observer.observe(slotEl, { attributeFilter: ["data-sf-streaks"] });
      });
    const runs: {
      props: string[];
      plateauEnd: number;
      time: number;
      progress: number;
      opacity: number;
      connected: boolean;
      removed: boolean;
    }[] = [];
    let previous: Element | null = null;
    let measuresAtEnd = 0;
    for (let round = 1; round <= 3; round++) {
      // A streak in flight that has not reached 600ms yet, new each round.
      let el: HTMLElement | undefined;
      let anim: Animation | undefined;
      const deadline = performance.now() + 10_000;
      while (!el || !anim) {
        const found = slotEl.querySelector<HTMLElement>(
          ":scope > [data-sf-streak]",
        );
        const a = found?.getAnimations()[0];
        if (found && a && found !== previous && Number(a.currentTime) < 600) {
          el = found;
          anim = a;
        } else if (performance.now() > deadline) {
          throw new Error(`no fresh streak within 10s (round ${round})`);
        } else await frame();

      previous = el;

      const keyframes = effect.getKeyframes();

          .map((k) => k.computedOffset),

      if (sample.progress <= plateauEnd) break;

    const checks =

    const slotEl = document.querySelector("[data-starfield]")!;
    const frame = () => new Promise((r) => requestAnimationFrame(r));

    for (;;) {
      const el = slotEl.querySelector<HTMLElement>(":scope > [data-sf-streak]");
      const anim = el?.getAnimations()[0];
      if (el && anim?.playState === "running") {
        anim.finished.catch(() => {});
        window.scrollBy(0, 1);
        await frame();
        return {
          playState: anim.playState,
          hidden: !el.isConnected || getComputedStyle(el).opacity === "0",
        };
      }
      if (performance.now() > deadline) return null;
      await frame();
    }
  });
  expect(after).toEqual({ playState: "idle", hidden: true });

      width: `${r.width}px`,
      height: `${r.height}px`,
      margin: "0",
      zIndex: "2147483647",
    });
    // sf-attempt measures so far (one per check, in order; never timestamps).
    const measures = () => performance.getEntriesByName("sf-attempt").length;
    const probe = {
      texts: 0,
      removed: false,
      launched: false,
      measuresAtRefusal: 0,
      measuresAtLaunch: 0,
      streaks: 0,
      earlyLaunches: 0,
    };
    (window as unknown as { __sfProbe: typeof probe }).__sfProbe = probe;
    new MutationObserver((records) => {
      for (const rec of records) {
        if (probe.launched) return;
        if (rec.attributeName === "data-sf-streaks") {
          // A launch before the refusal would mean the cover was missed.
          if (!probe.removed) probe.earlyLaunches += 1;
          else {
            probe.launched = true;
            probe.measuresAtLaunch = measures();
            probe.streaks = Number(slotEl.getAttribute("data-sf-streaks"));
          }
        } else if (slotEl.getAttribute("data-sf-last-skip") === "text") {
          probe.texts += 1;
          if (!probe.removed) {
            cover.remove();
            probe.removed = true;
            probe.measuresAtRefusal = measures();
          }
        }
      }
    }).observe(slotEl, {
      attributeFilter: ["data-sf-last-skip", "data-sf-streaks"],
    });
    document.body.append(cover);
    return {
      streaks: Number(slotEl.getAttribute("data-sf-streaks")),
      skip: slotEl.getAttribute("data-sf-last-skip"),
    };
  });
  expect(before.skip).toBeNull();
  // The next attempt (every 3s) hits the cover on its first check; the attempt
  // after it, with the cover gone, launches again. A readiness wait.
  await page.waitForFunction(
    () =>
      (window as unknown as { __sfProbe: { launched: boolean } }).__sfProbe
        .launched,
    undefined,
    { timeout: 15_000 },
  );
  const probe = await page.evaluate(() => {
    const p = (
      window as unknown as {
        __sfProbe: {
          texts: number;
          earlyLaunches: number;
          streaks: number;
          measuresAtRefusal: number;
          measuresAtLaunch: number;
        };
      }
    ).__sfProbe;
    // sf-attempt measures (one per check) after the refused check, up to the launch.
    return { ...p, checks: p.measuresAtLaunch - p.measuresAtRefusal };
  });
  test.info().annotations.push({
    type: "refused then clear",
    description: JSON.stringify(probe),
  });
  expect(probe.earlyLaunches).toBe(0);
  expect(probe.texts).toBe(1); // only check 1 was refused
  // Checks 2-3 of the refused attempt (no launch), then the next attempt's
  // three checks, which launch: the refusal stopped that attempt.
  expect(probe.checks).toBe(5);
  expect(probe.streaks).toBe(before.streaks + 1);
});

test("screenshot dev-starfield-streak", async ({ page }, testInfo) => {
  await page.goto(SF.demo);
  await waitForState(page, "animating");
  // Freeze a repeatable frame: the streak at 700ms, every twinkle at 0. The
  // streak is found and frozen in one task, so it cannot end in between; the
  // wait for it is a readiness wait (M1.20b).
  const frozen = await page.evaluate(async (sel) => {
    const slotEl = document.querySelector("[data-starfield]")!;
    const deadline = performance.now() + 15_000;
    for (;;) {
      const all = slotEl.getAnimations({ subtree: true });
      const streaks = all.filter(
        (a) =>
          (a.effect as KeyframeEffect).target?.matches(sel) &&
          a.playState === "running",
      );
      if (streaks.length === 1) {
        for (const a of all) {
          a.pause();
          a.currentTime = a === streaks[0] ? 700 : 0;
        }
        const s = streaks[0]!;
        return {
          streaks: 1,
          time: s.playState === "paused" ? Number(s.currentTime) : null,
        };
      }
      if (performance.now() > deadline) {
        return { streaks: streaks.length, time: null };
      }
      await new Promise((r) => requestAnimationFrame(r));
    }
  }, "[data-starfield] > [data-sf-streak]");
  expect(frozen).toEqual({ streaks: 1, time: 700 });
  await captureRoute(page, SF.demo, testInfo, {
    name: "dev-starfield-streak",
    fullPage: false,
    animations: "allow",
  });
});
