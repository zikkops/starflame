## 1. Decisions

**Layout.** Four files in `lib/firebase/repositories/`:
- `catalog-reads.ts` (`server-only`): the uncached reads `read*(src, …)`, the query builders `catalogQueries` and their `QUERY_SHAPES`. `src` is `{ db, imageUrl }`, so tests inject an emulator Firestore. A new ESLint pattern stops `app/`, `components/` and other `lib/` code from importing it.
- `catalog.ts` (`server-only`): the public, cached `get*` functions. This is the only module pages import.
- `cache-codec.ts` (Date-safe JSON for the cache) and `cache-tags.ts` (`CACHE_TAGS`): plain modules.

**Return types (lib/types).** Lists return `ProductCard`, never full documents. The card gains the four fields the M3 shop still lacks for its in-memory filters and sorts (`collectionSlugs`, `scentFamilies`, `sortOrder`, `publishedAt`; it already had `type`, `sizeKeys`, `priceFrom` and `priceTo`). So one cached payload of about 1 KB per product serves the shop's filters and its grid. `cardImage` becomes a `ResolvedImage` (`ProductImage` + `src`). The product page gets a `ProductDetail` (the full `Product`, with resolved images). Gift-set contents come back as `GiftSetContentLine { sku, quantity, variantLabel, product: ProductCard }`. Collections are small and stay `Collection`. `toProductCard`, `toProductDetail`, `resolveImage` and `giftSetLines` stay pure in `lib/domain/derive-product.ts`; the URL resolver is injected.

**Functions, queries and indexes.** Every query filters `status == "published"`. Every document is also re-checked in memory (a `getAll` or doc read has no filter), the slug lists included: they read `status` only. The index test (§4) rebuilds each query from its shape and compares it with `Query#isEqual`, and a source scan fails if `.where(` or `.orderBy(` appears in `lib/firebase/repositories` outside `catalogQueries`, so an inline query can't escape the coverage check.

| Function (`catalog.ts`) | Firestore | Index (firestore.indexes.json) | Tag |
|---|---|---|---|
| `getProducts()` → `ProductCard[]` | `products` `status ==` `orderBy sortOrder` | composite `products (status, sortOrder)` | products |
| `getProductBySlug(slug)` → `ProductDetail \| null` | `doc(slug).get()` (one read); null unless published | none (document read) | products |
| `getProductsByCollection(slug)` → cards | `collectionSlugs array-contains` + `status ==` + `orderBy sortOrder` | composite `products (collectionSlugs CONTAINS, status, sortOrder)` | products |
| `getBestsellers(limit)` → cards | `badges array-contains "bestseller"` + `status ==` + `orderBy sortOrder` + `limit` | composite `products (badges CONTAINS, status, sortOrder)` | products |
| `getRelatedProducts(product, limit)` → cards | products listed in the product's primary collection (primary or alsoIn): the collection query on `product.collection`, `limit + 1`, then drops the product itself: **one query** | composite `products (collectionSlugs CONTAINS, status, sortOrder)` | products |
| `getProductCardsBySlugs(slugs)` → cards | **one `getAll`** (≤100 distinct slugs, first-seen order) | none (document reads) | products |
| `getGiftSetContents(product)` → lines | `getProductCardsBySlugs(content slugs)`: **one `getAll`**; lines joined in memory | none | products |
| `getCollections()` → `Collection[]` | `collections` `status ==` `orderBy sortOrder` | composite `collections (status, sortOrder)` | collections |
| `getCollectionBySlug(slug)` → `Collection \| null` | `doc(slug).get()` | none | collections |
| `getPublishedProductSlugs()` / `getCollectionSlugs()` → sorted slugs | `status ==` + `select("status")`; status re-checked in memory (`publishedIds`) | automatic single-field `status` (not exempted) | products / collections |

`getAll` is one round trip whatever the count, so no `in` batching (≤30) is needed. Gift sets and a future cart (M5) both use `getProductCardsBySlugs`. Route params are checked against `SLUG_PATTERN` (≤80 characters) before any read, so `a/b` or `../x` never becomes a document path. Limits are integers from 1 to 50; anything else throws `RangeError`. `getProductsByCollection` doesn't check the collection's own status: the collection page calls `getCollectionBySlug` first and 404s.

**Caching.** With `cacheComponents` off (M1.1), Next 16.4 has no `"use cache"` (its docs: "`use cache` is a Cache Components feature"). So the cache for non-fetch data is `unstable_cache`, deprecated in favour of `use cache` but supported (docs `caching-without-cache-components.md`).
- Each `get*` = React `cache()` (dedupes within one render: `generateMetadata` + page, footer + page) around `unstable_cache(read, ["starflames-catalog", name], { tags: [tag], revalidate: false })`.
- **Names are the keys.** `unstable_cache` keys on the callback's source text, the key parts and `JSON.stringify(args)`. The callback is the same text in every wrapper, so `name` is the only separator: `cachedRead` throws when a name is used twice (at module load). For the same reason, a change to a read's code doesn't change its key.
- **Tags:** only `products` and `collections`. A product write can change any list, card, related row or gift set, so per-slug tags would be wrong or redundant. A full refresh costs at most about 200 + 6 reads, done lazily per entry. M7 calls `updateTag(tag)` in Server Actions (read-your-writes) or `revalidateTag(tag, "max")` in Route Handlers. Pages inherit the tags (verified: after `revalidateTag("products","max")` the next request is served stale and the one after is fresh).
- **Date codec (found in the source and verified):** `unstable_cache` returns the raw value on a miss but `JSON.parse(body)` on a hit, so a `Date` would turn into a string on the second call. The cached function stores `encodeForCache(value)` (Dates become `{ "$date": iso }`; Maps, NaN and invalid dates are refused), and callers get `decodeFromCache(...)`. Both paths return real Dates (shown on a cache-hit build).
- **Builds start with an empty data cache.** `next build` reuses `.next/cache/fetch-cache` entries from an earlier build or `next start`. Verified: after a data change, a second build baked the old product name. `prebuild` (and `scripts/e2e.ts` before its own `next build`) runs `scripts/clear-data-cache.mjs`. So **always build through `npm run build` (or `npm run test:e2e`), never `npx next build`**, which skips `prebuild`.
- **Dev:** `next dev` also keeps entries (`.next/dev/cache/fetch-cache`). **After reseeding or changing repository code, hard-reload or delete `.next/dev/cache/fetch-cache`** (Ctrl+Shift+R sends `Cache-Control: no-cache`, which bypasses the entries; verified). Recommended for M1.8: the seed clears both `fetch-cache` folders after writing.

**Images.** `storage-url.ts` is unchanged; repositories resolve every image URL on the server (`storageObjectUrl`). `next.config.ts` gets `images.remotePatterns` built from env (`http`, the `NEXT_PUBLIC_STORAGE_EMULATOR_HOST` host and port, `pathname: /v0/b/<projectId>.appspot.com/o/**`, `search: "?alt=media"`) plus **`images.dangerouslyAllowLocalIP: true`**. Both are set only when the project ID is `demo-*` and `NEXT_PUBLIC_USE_FIREBASE_EMULATORS === "true"`; otherwise `images` is `{}`. The option name was checked in `next/dist/shared/lib/image-config.d.ts` and the image docs ("v16.0.0 … `dangerouslyAllowLocalIP` config added"). Next loads `.env*` before `next.config.ts` (`build/index.js`). Verified on `next start`: `/_next/image?url=<emulator URL of cat-moonrise.png>` → 200 image/png. Another bucket → 400, and a URL without `?alt=media` → 400.

**Errors.**
- A missing, draft or archived document, or a non-slug ID, gives `null` (single reads) or is left out (lists). That's never a throw.
- Lists log and skip an invalid document (M1.4 policy) with `[repositories] skipped invalid document products/x (field variants[0].price)`: the path and the field, never values.
- Single reads **throw** `DocumentValidationError`. This refines M1.4's "detail pages log and call notFound()": on an SSG page a bad document fails the build loudly instead of 404ing silently, and during a revalidation Next keeps the last good page. A page may still catch it and call `notFound()`.
- Infrastructure errors (emulator down, env) propagate unchanged.
- A gift-set content that can't be shown is dropped and logged by slug and SKU.

**Client boundary.** `catalog.ts` and `catalog-reads.ts` import `server-only`. Verified: a `"use client"` import fails `next build` with the server-only error. `check:client-bundle` also fails on the repositories' two literals, `[repositories]` (the log prefix) and `starflames-catalog` (the cache key). Both are present in the server chunks and absent from `.next/static`; a planted file trips the check.

**Tests (§4).**
- The new `npm run test:repos` (`emulators-exec --only firestore`) runs 19 tests against the Firestore emulator. `tests/repos/fixtures.ts` seeds the whole catalog through the Admin converters, with a draft product, an archived product (a bestseller and a gift-set content), a draft and an archived collection, and one invalid "published" document.
  - `catalog.test.ts` (15): the uncached reads, plus `publishedIds` on a `select("status")` query with no status filter (drafts and archived documents reach it, so only the in-memory check removes them).
  - `catalog-cache.test.ts` (4): the cached `catalog.ts`, through a fake `globalThis.__incrementalCache` (the store Next uses when no request is active) and `globalThis.AsyncLocalStorage` (Next's shim reads it when it loads, so the test imports `catalog.ts` after setting both). It checks Dates on a miss and on a hit, one entry per function and argument list (a product and a collection with the same slug stay apart), and the arguments `getRelatedProducts` and `getGiftSetContents` pass to their reads. The env comes from `.env.example` (`process.loadEnvFile`, which never overrides a variable that is already set).
- `test:unit` gains the static index-coverage test (21, the source scan included) and the codec test (2), and the domain tests are updated (+2).

**No UI change.**
- **Footer:** footer.md §3.4 needs `slug`, `name` and `sortOrder` from `getCollections()`. That's what it returns, sorted. Leaving out `gift-sets`, the 6-item cap and the "omit the group on error" try/catch stay the footer's job in M3.7 (the repository throws only on infrastructure errors).
- **Header:** the header registry (`site-routes.ts`) reads no data; no change.

**Forward notes (for the orchestrator; none blocks M1.6).** Notes 2–5 come from the spec review.
1. **Build-time data.** From the first page that calls a repository (M2.4 bestsellers, M3), `next build` needs the Firestore emulator running and seeded, and the `NEXT_PUBLIC_*` env, because `storage-url` and `next.config` inline it at build time. The repo has no `.env.local`, and `scripts/e2e.ts`' build doesn't load `.env.example`, unlike `playwright.config.ts`. Proposed for M1.8:
   - the e2e build loads `.env.example` when `.env.local` is absent, and seeds before building (it already runs under `emulators:exec`);
   - a plain `npm run build` without emulators fails loudly, and the CLAUDE.md "plain build" note changes to match.
2. **M7, new products vs `dynamicParams = false`.** A product created in M7 has no page until the next build, because unknown slugs 404 and `revalidateTag` refreshes only existing pages. `dynamicParams = true` is now safe: `getProductBySlug` returns null for drafts, archived products and non-slugs, so the page calls `notFound()`. So M7 can switch to it (revisiting PUSHBACK 2), and new products then appear via ISR with no rebuild.
3. **M7, prompt invalidation.** `revalidateTag(tag, "max")` serves one stale response before the fresh one. For price and stock changes from Route Handlers or webhooks, use `revalidateTag(tag, { expire: 0 })`. Server Actions keep `updateTag(tag)`.
4. **Production setup, the cache store.** Next's default `FileSystemCache` keeps revalidated tags in memory only, so a restart between `revalidateTag` and the next request loses the invalidation; and `revalidateTag` clears only the local instance's cache. A shared `cacheHandler` fixes both, but it keeps entries across deploys, and a code change doesn't change a key (§1 Caching). So the keys then need a version or build-ID part, e.g. `[REPOSITORY_CACHE_KEY, CACHE_VERSION, name]`.
5. **M5, cart size.** `getProductCardsBySlugs` throws above 100 unique slugs, so the cart's line cap must be ≤100, or the cart chunks its reads.
6. CLAUDE.md "Commands" gains `npm run test:repos` and the `prebuild` data-cache clearing, with the build and dev stale-data notes (orchestrator's file).

**Carried (AC9).** In `design/tech/M1.20b-e2e-reliability.md` line 53, the Ctrl+Break sentence becomes "…can leave the Firestore emulator (Java) running on 6104–6105 (Java turns Ctrl+Break into a thread dump); it keeps those ports busy until stopped…". The patch is in §3.

```ts
import "server-only";

import { unstable_cache } from "next/cache";
import { cache } from "react";

import type {
  Collection,
  CollectionSlug,
  GiftSetContentLine,
  Product,
  ProductCard,
  ProductDetail,
  ProductSlug,
} from "../../types";
import { getAdminFirestore } from "../admin";
import { storageObjectUrl } from "../storage-url";
import { decodeFromCache, encodeForCache } from "./cache-codec";
import { CACHE_TAGS, type CacheTag } from "./cache-tags";
import * as reads from "./catalog-reads";

/**
 * The catalog repositories for Server Components, generateStaticParams and Route Handlers
 * (design/tech/M1.6-repositories.md). Each one is cached in two layers:
 *   - unstable_cache: the result is kept across requests until its tag is revalidated (CACHE_TAGS;
 *     M7's admin writes), and each build starts empty (scripts/clear-data-cache.mjs). Next 16.4
 *     without cacheComponents (off since M1.1) has no "use cache", so this is the cache for
 *     non-fetch data. Pages that read it inherit its tags.
 *   - React cache(): calls with the same arguments in one render share one promise (for
 *     example generateMetadata and the page, or the footer and a collection page).
 * Only published documents come back; a missing or unpublished one is null or left out.
 */

/** The first cache key part. scripts/check-client-bundle.mjs fails a build whose client chunks hold it. */
const REPOSITORY_CACHE_KEY = "starflames-catalog";

const source = (): reads.CatalogSource => ({
  db: getAdminFirestore(),
  imageUrl: (storagePath) => storageObjectUrl(storagePath),
});

/** The names in use. Every wrapper below has the same source text, so its name is its key. */
const cacheNames = new Set<string>();

/**
 * Wraps a read. `name` is part of the cache key: unstable_cache keys on the function's source
 * text, the key parts and JSON.stringify(arguments), so arguments must be JSON values. The
 * source text is the same for every wrapper, so a reused name would share entries with another
 * read: it throws when the module loads.
 */
function cachedRead<Args extends (string | number)[], R>(
  name: string,
  tag: CacheTag,
  read: (src: reads.CatalogSource, ...args: Args) => Promise<R>,
): (...args: Args) => Promise<R> {
  if (cacheNames.has(name)) {
    throw new Error(`[repositories] cache name "${name}" is used twice`);
  }
  cacheNames.add(name);
  const stored = unstable_cache(
    async (...args: Args) => encodeForCache(await read(source(), ...args)),
    [REPOSITORY_CACHE_KEY, name],
    { tags: [tag], revalidate: false },
  );
  return cache(async (...args: Args) =>
    decodeFromCache<R>(await stored(...args)),
  );
}

/** Every published product as a card, by sortOrder (the shop, M3.5, filters these in memory). */
export const getProducts: () => Promise<ProductCard[]> = cachedRead(
  "products",
  CACHE_TAGS.products,
  reads.readProducts,
);

/** The published product, or null (then the page calls notFound()). One document read. */
export const getProductBySlug: (slug: string) => Promise<ProductDetail | null> =
  cachedRead("product", CACHE_TAGS.products, reads.readProductBySlug);

/** The published products a collection lists (primary or alsoIn), by sortOrder. */
export const getProductsByCollection: (slug: string) => Promise<ProductCard[]> =
  cachedRead(
    "products-in-collection",
    CACHE_TAGS.products,
    reads.readProductsByCollection,
  );

/** Published products with the bestseller badge, by sortOrder; limit 1–50. */
export const getBestsellers: (limit: number) => Promise<ProductCard[]> =
  cachedRead("bestsellers", CACHE_TAGS.products, reads.readBestsellers);

const relatedProducts = cachedRead(
  "related",
  CACHE_TAGS.products,
  reads.readRelatedProducts,
);

/**
 * Up to `limit` (1–50) other published products listed in the product's primary collection
 * (primary or alsoIn), by sortOrder.
 */
export function getRelatedProducts(
  product: Pick<Product, "slug" | "collection">,
  limit: number,
): Promise<ProductCard[]> {
  return relatedProducts(product.slug, product.collection, limit);
}

// Slugs never contain a comma (SLUG_PATTERN), so a joined list is a stable cache argument.
const cardsBySlugs = cachedRead(
  "cards-by-slugs",
  CACHE_TAGS.products,
  (src, joined: string) =>
    reads.readProductCardsBySlugs(src, joined.split(",")),
);

/** Published products as cards, in first-seen order (one getAll, at most 100 slugs). */
export function getProductCardsBySlugs(
  slugs: readonly string[],
): Promise<ProductCard[]> {
  if (slugs.length === 0) return Promise.resolve([]);
  return cardsBySlugs(slugs.join(","));
}

/** A gift set's contents with their cards, in contents order (one getAll); [] for other types. */
export async function getGiftSetContents(
  product: Pick<Product, "slug" | "giftSetContents">,
): Promise<GiftSetContentLine[]> {
  const slugs = reads.giftSetContentSlugs(product);
  if (slugs.length === 0) return [];
  return reads.giftSetContentLines(
    product,
    await getProductCardsBySlugs(slugs),
  );
}

/** Every published collection, by sortOrder (nav, footer "Our collections", collection index). */
export const getCollections: () => Promise<Collection[]> = cachedRead(
  "collections",
  CACHE_TAGS.collections,
  reads.readCollections,
);

/** The published collection, or null. One document read. */
export const getCollectionBySlug: (slug: string) => Promise<Collection | null> =
  cachedRead("collection", CACHE_TAGS.collections, reads.readCollectionBySlug);

/** For the product page's generateStaticParams (dynamicParams = false, M1.13 PUSHBACK 2). */
export const getPublishedProductSlugs: () => Promise<ProductSlug[]> =
  cachedRead(
    "product-slugs",
    CACHE_TAGS.products,
    reads.readPublishedProductSlugs,
  );

/** For the collection page's generateStaticParams. */
export const getCollectionSlugs: () => Promise<CollectionSlug[]> = cachedRead(
  "collection-slugs",
  CACHE_TAGS.collections,
  reads.readCollectionSlugs,
);
```

```ts
  DocumentSnapshot,
  Firestore,
  Query,

import {
  giftSetLines,
  toProductCard,
  toProductDetail,
  type ImageUrlResolver,

import {
  asCollectionSlug,
  asProductSlug,

import { ValidationError } from "../../domain/validate";
import type {
  Collection,
  CollectionSlug,
  GiftSetContentLine,
  Product,
  ProductCard,
  ProductDetail,
  ProductSlug,
  PublishStatus,
} from "../../types";
import { DocumentValidationError } from "../converter-utils";
import { adminCollections } from "../converters.admin";
import { COLLECTIONS } from "../paths";

/**
 * Uncached catalog reads (design/tech/M1.6-repositories.md). Pages use the cached wrappers in
 * ./catalog.ts; tests and scripts call these with their own Firestore. The Admin SDK skips the
 * security rules, so every read here returns published documents only: each query filters
 * `status == "published"`, and every document is checked again in memory.
 */

export type CatalogSource = {
  readonly db: Firestore;
  readonly imageUrl: ImageUrlResolver;
};

const PUBLISHED: PublishStatus = "published";
const BESTSELLER = "bestseller";

/** Upper bounds for caller-supplied sizes; a value outside them is a programming error. */
export const READ_LIMITS = { list: 50, slugs: 100 } as const;

/** The queries the reads run. The index-coverage test rebuilds each one from QUERY_SHAPES. */
export const catalogQueries = {
  products: (db: Firestore) =>
    adminCollections(db)
      .products.where("status", "==", PUBLISHED)
      .orderBy("sortOrder"),
  productsInCollection: (db: Firestore, slug: string) =>
    adminCollections(db)
      .products.where("collectionSlugs", "array-contains", slug)
      .where("status", "==", PUBLISHED)
      .orderBy("sortOrder"),
  bestsellers: (db: Firestore) =>
    adminCollections(db)
      .products.where("badges", "array-contains", BESTSELLER)
      .where("status", "==", PUBLISHED)
      .orderBy("sortOrder"),
  collections: (db: Firestore) =>
    adminCollections(db)
      .collections.where("status", "==", PUBLISHED)
      .orderBy("sortOrder"),
  productIds: (db: Firestore) =>
    db
      .collection(COLLECTIONS.products)
      .where("status", "==", PUBLISHED)
      .select("status"),
  collectionIds: (db: Firestore) =>
    db
      .collection(COLLECTIONS.collections)
      .where("status", "==", PUBLISHED)
      .select("status"),
};

export type QueryName = keyof typeof catalogQueries;

/** One query's shape. `{ param: true }` is the value the caller passes (the argument after db). */
export type QueryShape = {
  readonly collectionGroup: "products" | "collections";
  readonly where: readonly {
    readonly field: string;
    readonly op: "==" | "array-contains";
    readonly value: string | { readonly param: true };
  }[];
  readonly orderBy: readonly string[];
  /** The fields select() keeps (`status` for the slug lists), or null for whole documents. */
  readonly select: readonly string[] | null;
};

export const QUERY_SHAPES: Readonly<Record<QueryName, QueryShape>> = {
  products: {
    collectionGroup: "products",
    where: [{ field: "status", op: "==", value: PUBLISHED }],
    orderBy: ["sortOrder"],
    select: null,
  },
  productsInCollection: {
    collectionGroup: "products",
    where: [
      {
        field: "collectionSlugs",
        op: "array-contains",
        value: { param: true },
      },
      { field: "status", op: "==", value: PUBLISHED },

    orderBy: ["sortOrder"],
    select: null,
  },
  bestsellers: {
    collectionGroup: "products",
    where: [
      { field: "badges", op: "array-contains", value: BESTSELLER },
      { field: "status", op: "==", value: PUBLISHED },

    orderBy: ["sortOrder"],
    select: null,
  },
  collections: {

    select: null,
  },
  productIds: {

    where: [{ field: "status", op: "==", value: PUBLISHED }],

/** Route params arrive unchecked; a non-slug (e.g. with "/") never becomes a document path. */
const isSlug = (value: string): boolean =>
  value.length <= 80 && SLUG_PATTERN.test(value);

function checkLimit(limit: number, max: number): void {
  if (!Number.isInteger(limit) || limit < 1 || limit > max) {
    throw new RangeError(
      `limit must be an integer from 1 to ${max}, got ${limit}`,
    );
  }
}

/** Logs the document path and the failing field only, never document data. */
function logSkipped(error: DocumentValidationError): void {
  const field =
    error.cause instanceof ValidationError ? error.cause.path || "(root)" : "?";
  console.error(
    `[repositories] skipped invalid document ${error.docPath} (field ${field})`,
  );
}

/** The decoded, published documents of a list. An invalid one is logged and skipped (M1.4 §1). */
function publishedOf<T extends { readonly status: PublishStatus }>(
  snapshots: readonly DocumentSnapshot<T>[],
): T[] {
  const out: T[] = [];
  for (const snapshot of snapshots) {
    let doc: T | undefined;
    try {
      doc = snapshot.data();
    } catch (error) {
      if (!(error instanceof DocumentValidationError)) throw error;
      logSkipped(error);
      continue;
    }
    if (doc?.status === PUBLISHED) out.push(doc);
  }
  return out;
}

async function listOf<T extends { readonly status: PublishStatus }>(
  query: Query<T>,
): Promise<T[]> {
  const snapshot = await query.get();
  return publishedOf(snapshot.docs);
}

/**
 * Published products by slug, in first-seen order without duplicates: one getAll round trip
 * whatever the count (no N+1). Missing, unpublished and invalid documents are left out.
 */
export async function readProductCardsBySlugs(
  src: CatalogSource,
  slugs: readonly string[],
): Promise<ProductCard[]> {
  const unique = [...new Set(slugs)].filter(isSlug);
  if (unique.length > READ_LIMITS.slugs) {
    throw new RangeError(
      `at most ${READ_LIMITS.slugs} slugs per read, got ${unique.length}`,
    );
  }
  if (unique.length === 0) return [];
  const products = adminCollections(src.db).products;
  // Firestore#getAll is typed DocumentSnapshot<DocumentData>, but each snapshot decodes with its
  // reference's converter (the repository tests check this); the cast restores that type.
  const snapshots = (await src.db.getAll(
    ...unique.map((slug) => products.doc(slug)),
  )) as DocumentSnapshot<Product>[];
  return cardsOf(src, publishedOf(snapshots));
}
```

```ts
/**
 * unstable_cache stores a result with JSON.stringify and returns JSON.parse(body) on a cache hit,
 * but the original value on a miss (next/dist/server/web/spec-extension/unstable-cache.js), so a
 * Date would be a Date on the first call and a string after it. The cached repositories store
 * encodeForCache(value) and return decodeFromCache(...), which gives the same result on both
 * paths. Dates travel as { "$date": ISO string }.
 */

export type CacheJson =
  null | boolean | number | string | CacheJson[] | { [key: string]: CacheJson };

const DATE_KEY = "$date";

export class CacheCodecError extends Error {
  override name = "CacheCodecError";
}

function isPlainObject(value: object): boolean {
  const proto: unknown = Object.getPrototypeOf(value);
  return proto === Object.prototype || proto === null;
}

export function encodeForCache(value: unknown, path = "(root)"): CacheJson {
  if (value === null) return null;
  if (value instanceof Date) {
    if (Number.isNaN(value.getTime())) {
      throw new CacheCodecError(`${path}: invalid Date`);
    }
    return { [DATE_KEY]: value.toISOString() };
  }
  if (Array.isArray(value)) {
    return value.map((item, i) => encodeForCache(item, `${path}[${i}]`));
  }
  switch (typeof value) {
    case "string":
    case "boolean":
      return value;
    case "number":
      if (!Number.isFinite(value)) {
        throw new CacheCodecError(`${path}: non-finite number`);
      }
      return value;
    case "object":
      if (isPlainObject(value)) {
        const out: { [key: string]: CacheJson } = {};
        for (const [key, v] of Object.entries(value)) {
          if (key === DATE_KEY) {
            throw new CacheCodecError(
              `${path}: the key "${DATE_KEY}" is reserved`,
            );
          }
          if (v !== undefined) out[key] = encodeForCache(v, `${path}.${key}`);
        }
        return out;
      }
      break;
  }
  throw new CacheCodecError(`${path}: ${typeof value} is not cacheable`);
}

function decode(json: CacheJson): unknown {
  if (Array.isArray(json)) return json.map(decode);
  if (json === null || typeof json !== "object") return json;
  const keys = Object.keys(json);
  const tagged = json[DATE_KEY];
  if (keys.length === 1 && typeof tagged === "string") return new Date(tagged);
  const out: Record<string, unknown> = {};
  for (const key of keys) {
    const v = json[key];
    if (v !== undefined) out[key] = decode(v);
  }
  return out;
}

/** The inverse of encodeForCache. T is the type the encoded value had. */
export function decodeFromCache<T>(json: CacheJson): T {
  // The cast restores the static type that encodeForCache erased; the value's shape is unchanged.
  return decode(json) as T;
}
```

```ts
  readonly isOnDemandRevalidate = false;
  readonly entries = new Map<string, unknown>();
  hits = 0;
  misses = 0;

  // The invocation key is kept as is, so the tests can read it.
  generateSimpleCacheKey(key: string): Promise<string> {
    return Promise.resolve(key);
  }

  get(key: string): Promise<{ value: unknown; isStale: false } | null> {
    const value = this.entries.get(key);
    if (value === undefined) {
      this.misses += 1;
      return Promise.resolve(null);

    this.hits += 1;

    return Promise.resolve();
```

```ts
/**
 * Index coverage (M1.6): every repository query either has a composite index in
 * firestore.indexes.json or is a single-field query Firestore indexes automatically (and that
 * field isn't exempted in fieldOverrides). The emulator doesn't enforce indexes, so this is the
 * check that a production deploy won't fail with FAILED_PRECONDITION. Each shape is also rebuilt
 * as a query and compared with Query#isEqual to the one the repository builds, so the list below
 * can't drift from the code, and a source scan checks that no repository builds a filter or an
 * order anywhere else. No emulator needed: building a query makes no request.
 */

type IndexField = {
  fieldPath: string;
  order?: "ASCENDING" | "DESCENDING";
  arrayConfig?: "CONTAINS";
};
type IndexFile = {
  indexes: {
    collectionGroup: string;
    queryScope: string;
    fields: IndexField[];
  }[];
  fieldOverrides: {
    collectionGroup: string;
    fieldPath: string;
    indexes: unknown[];
  }[];
};
const indexFile = JSON.parse(
  readFileSync("firestore.indexes.json", "utf8"),
) as IndexFile;

const SAMPLE_PARAM = "moonlit-terrace";

/** The composite index a shape needs: equality and array-contains fields (any order), then orderBy. */
function compositeFor(shape: QueryShape) {
  return indexFile.indexes.find((index) => {
    if (
      index.collectionGroup !== shape.collectionGroup ||
      index.queryScope !== "COLLECTION"
    ) {
      return false;
    }
    const filters = index.fields.slice(0, shape.where.length);
    const orders = index.fields.slice(shape.where.length);
    const filtersMatch =
      filters.length === shape.where.length &&
      shape.where.every((w) =>
        filters.some(
          (f) =>
            f.fieldPath === w.field &&
            (w.op === "array-contains"
              ? f.arrayConfig === "CONTAINS"
              : f.order !== undefined),
        ),
      );
    const ordersMatch =
      orders.length === shape.orderBy.length &&
      shape.orderBy.every(
        (field, i) =>
          orders[i]?.fieldPath === field && orders[i]?.order === "ASCENDING",
      );
    return filtersMatch && ordersMatch;
  });
}

/** One filter and no orderBy on another field: served by the automatic single-field index. */
function singleFieldOk(shape: QueryShape): boolean {
  const [only, ...rest] = shape.where;
  if (!only || rest.length > 0) return false;
  if (shape.orderBy.some((field) => field !== only.field)) return false;
  return !indexFile.fieldOverrides.some(
    (o) =>
      o.collectionGroup === shape.collectionGroup &&
      o.fieldPath === only.field &&
      o.indexes.length === 0,
  );
}

        w.op,

    }

  }
```
