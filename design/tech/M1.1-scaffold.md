## 2. Scaffold approach (non-destructive)

The repo root is not empty, and CNA's `--agents-md` default may write agent files. So we scaffold **outside the repo** and copy a whitelist in:

1. From the scratchpad/temp dir, run:
   `npx create-next-app@16.4.0 starflames --ts --tailwind --eslint --app --empty --no-src-dir --no-react-compiler --no-cache-components --import-alias "@/*" --use-npm --skip-install --disable-git --no-agents-md --no-agent-feedback --yes`
   Every prompted option is passed explicitly, so `--yes` takes nothing from this machine's saved CNA preferences and the run can be reproduced on another machine. Do not pass `--rspack` or `--biome`. 16.4 has no `--webpack`/`--turbopack` flag; Turbopack is the default bundler. Do not use `--reset-preferences`: in 16.4 it opens an interactive prompt and exits without scaffolding.
   - `--no-cache-components`: with `--yes`, CNA 16.4 defaults to `cacheComponents: true` + `partialPrefetching: true` in next.config.ts. That changes how pages render and cache data, so we decide it when the data layer lands, not in the scaffold.
   - Verified against the packed 16.4.0 CLI: with `--tailwind` + Turbopack, CNA does **not** copy `postcss.config.mjs`. It adds devDep `@tailwindcss/turbopack: ^4` and writes a `turbopack.rules["*.css"]` loader block into next.config.ts. Step 3 undoes this.
2. Copy **only** these into `C:\Projects\starflame`: `package.json`, `tsconfig.json`, `next.config.ts`, `eslint.config.mjs`, `app/layout.tsx`, `app/page.tsx`, `app/globals.css`. (CNA emits no `postcss.config.mjs` here; step 3 writes it.) Do not copy README, biome.json, AGENTS.md/CLAUDE.md, next-env.d.ts, the template gitignore, or any SVGs/fonts. Check that `CLAUDE.md`, `TASKS.md`, `PROGRESS.md`, `.claude/` and `design/` are byte-identical afterwards. Delete the temp folder.
3. In the root, switch Tailwind to PostCSS before installing:
   - `next.config.ts`: replace with the exact contents in section 4, so no `turbopack` block remains.
   - Create `postcss.config.mjs` with the exact contents in section 4.
   - `package.json`: remove the devDep `@tailwindcss/turbopack` and add `@tailwindcss/postcss`. Apply the rest of the section 1 versions and section 5 edits.
4. Run `npm install`, then `npm install -D -E prettier@3.9.9` plus the other dev deps at the versions in the table. Keep `package-lock.json`; the orchestrator commits it in the `feat: M1.1 scaffold` commit.
5. `git init -b main`. Do not commit. The orchestrator makes the `feat: M1.1 scaffold` commit at loop step 7.

## 4. Config

**Tailwind integration: PostCSS (decision).** We use `@tailwindcss/postcss` with a root `postcss.config.mjs` and no `turbopack.rules` block, instead of CNA's `@tailwindcss/turbopack` loader. Why: it is the path that the Next 16.4 docs (`docs/01-app/01-getting-started/11-css.md`) and Tailwind document. It also works with tools that process CSS outside Next, and it doesn't depend on which bundler is in use. Turbopack supports it natively: the bundled `docs/01-app/03-api-reference/08-turbopack.md` says it "automatically processes PostCSS config files (`postcss.config.js`, `.mjs`, …)". Verified on 2026-10-08 with a throwaway `next build` in the scratchpad (Next 16.4.0, "(Turbopack)" in the build banner, tailwindcss + @tailwindcss/postcss 4.3.3, this exact postcss.config.mjs, no turbopack block). The emitted CSS contained the generated `text-amber-400` and `tracking-widest` utilities.

**next.config.ts** (exact):

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // Stop `next dev` from generating AGENTS.md in the repo root.
  agentRules: false,
};

export default nextConfig;
```

`agentRules: false` is the **only** allowed key. Why: Next 16.4 `next dev` auto-generates `AGENTS.md` at the project root when it detects an AI coding agent (`agentRules` defaults to `true`; see `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/agentRules.md` and the `agentRules?: boolean` type in `next/dist/server/config-shared.d.ts`). This repo's agent instructions live in `CLAUDE.md` and `.claude/`, so a generated AGENTS.md is unwanted. `turbopack`, `cacheComponents`, `reactCompiler` and `experimental` stay forbidden.

Prettier note: Prettier keeps comments as written. It does not convert a `//` line comment to a `/* */` block comment or the reverse, so either style is Prettier-clean. The CNA 16.4 template emits `// config options here`; this spec uses a `//` line comment to match that style.

**postcss.config.mjs** (exact; identical to the CNA 16.4.0 `app-tw-empty/ts` template file that CNA skips under Turbopack):

```js
const config = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};

export default config;
```

**tsconfig.json**: keep the template (`strict`, `moduleResolution: bundler`, `noEmit`, `isolatedModules`, `paths`, `next` plugin, include list). Add these options:
- `noUncheckedIndexedAccess`: Firestore records, route params, cart arrays and `Record` lookups can be undefined at runtime. This option forces the checks.
- `noImplicitOverride`, `noFallthroughCasesInSwitch`, `noImplicitReturns`: cheap checks that catch real bugs (order-status switches).
- `forceConsistentCasingInFileNames`: Windows is case-insensitive but CI/Linux is not.
- `target: "ES2022"`.
- `exclude: ["node_modules", "functions"]`, because Functions gets its own tsconfig in a later task.
- Rejected: `exactOptionalPropertyTypes` fights the Firebase SDK and Next prop types. `noUnusedLocals`/`noUnusedParameters` are left to ESLint as warnings so that work in progress doesn't fail tsc.

**eslint.config.mjs** (flat config, `defineConfig` from `eslint/config`): `...nextVitals`, `...nextTs`, then a rules block that sets `@typescript-eslint/no-explicit-any: "error"`, then **`eslint-config-prettier/flat` last**. Prettier is **not** run as an ESLint rule (no eslint-plugin-prettier); the two tools run separately, so they never conflict. Global ignores: `.next/**`, `out/**`, `build/**`, `next-env.d.ts`, `coverage/**`, `playwright-report/**`, `test-results/**`, `functions/lib/**`.

**Prettier**: `.prettierrc.json` = `{ "plugins": ["prettier-plugin-tailwindcss"], "tailwindStylesheet": "./app/globals.css" }`. The `tailwindStylesheet` option is required for v4. Everything else uses Prettier defaults (double quotes, semicolons, LF), which match the template. `.prettierignore` lists `.next`, `out`, `node_modules`, `package-lock.json`, `coverage`, `playwright-report`, `test-results`, `functions/lib`, `emulator-data`, plus `design/`, `.claude/`, `CLAUDE.md`, `TASKS.md` and `PROGRESS.md`. Those docs are not tech-owned, so the format scripts must not rewrite them.

**.gitattributes**: `* text=auto eol=lf`. This keeps Prettier's `--check` stable on Windows when `core.autocrlf` is on.
