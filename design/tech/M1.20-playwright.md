## 1. Decisions

- **Dependency: `@playwright/test` `1.63.0` (exact) devDep.** **Not 1.64.0 (`latest`)**: it came out 2026-10-07, two days ago (same rule as M1.2/M1.3). 1.63.0 shipped 2026-09-04 and has no patch release. It pulls in `playwright` and `playwright-core` 1.63.0 (no peers, engines `node >=20`). **Install scripts:** none. After the install, `npm approve-scripts --allow-scripts-pending` prints "No packages with unreviewed install scripts", so `allowScripts` is unchanged. Browsers are not an install script. They come from an explicit `npm run test:e2e:install`. The lockfile gains only the three playwright packages. Log it in PROGRESS.md as stack tooling.
- **Browsers: Chromium only** (Chrome for Testing 153 + headless shell, revision 1243; about 430 + 270 MB unpacked in `%LOCALAPPDATA%\ms-playwright`, shared by every project on this machine). `--no-remove` is **required**: without it, `playwright install` deletes browser revisions that it thinks are unused, and another local project uses `chromium-1234`. **WebKit: not now.** Its download is small (63 MB), but Playwright's WebKit on Windows is not iPhone Safari. Its font rendering, compositing and iOS behaviour (dynamic toolbar, safe areas) differ, so its screenshots would mislead QA more than help, and it would double the run time. Real Safari checks belong on a device at the milestone gates. If we want it later, add a `mobile-webkit` project to the config (one line) plus `webkit` to the install script.
- **Projects** (4; each project's `use` is spread from these devices):
  - `mobile-390`: `devices["iPhone 14"]` = 390×664, DPR 3, `isMobile`, `hasTouch`, iPhone Safari UA, forced to `browserName: "chromium"`. Verified in the page: `devicePixelRatio` 3, `maxTouchPoints` 1, `(pointer: coarse)` true.
  - `desktop-1440`: `devices["Desktop Chrome"]` with a 1440×900 viewport, DPR 1.
  - `mobile-390-reduced-motion` and `desktop-1440-reduced-motion`: the same devices plus `reducedMotion: "reduce"`, with `grep: /@motion/`. They run only tests tagged `@motion`. So a motion test gets both variants for free. For a one-off, use `test.use({ reducedMotion: "reduce" })` in a describe block; it is a built-in option, so no custom fixture is needed.
- **webServer: production build on port `6130`, loopback only.** The command is `npm run build && npm run start -- --hostname 127.0.0.1 --port 6130`. Port 6130 avoids 3000 (another project), 3001 (the orchestrator's dev server), 3002 (the orchestrator's mockup server), 6100–6119 (emulators) and Chrome's unsafe-port list, and it is free now. `reuseExistingServer: false`: Playwright never attaches to a server it did not start, and it only kills its own process tree (`taskkill /T` on Windows). If 6130 is taken, the run fails with "is already used" and leaves the occupant alone (verified). `next build` alongside a running `next dev` is supported in Next 16 because dev writes to `.next/dev` (bundled docs `06-cli/next.md`, `upgrading/version-16.md` "Concurrent dev and build"). The config loads `.env.example` when there is no `.env.local`, as the smoke script does. Variables already set in the environment win.
- **Emulators: `test:e2e` runs under `firebase emulators:exec --only auth,firestore,storage`.** That is the data stack later pages need. Functions are skipped (no build step, faster) until checkout lands (M5), when we add `functions` to `--only`. exec exports the emulator hosts to Playwright, and through it to `next start`. It propagates the exit code (pass gives 0, a failing test gives 1; both verified). It starts no UI and writes `firestore-debug.log` (git-ignored). **Windows quirks:** npm runs scripts through `cmd.exe`, so the inner command uses escaped double quotes (`\"playwright test\"`), never single quotes. Arguments after `npm run test:e2e --` go to firebase, not to Playwright. For a filtered run, use `npx firebase emulators:exec --project demo-starflames --only auth,firestore,storage "playwright test --project=mobile-390"`, or plain `npx playwright test …` for pages that need no data. `npm run emulators` must not be running at the same time, because the emulator ports would clash.
- **Smoke checks** (`smoke.spec.ts`): status 200, `<html lang>` is a BCP-47-shaped tag, exactly one `h1`, and a non-empty title. **No console errors and no failed requests** are checked for *every* test by an auto fixture (`fixtures.ts`). It fails the test on `console.error`, `pageerror`, `requestfailed` or any response ≥ 400. Console errors carry their source URL in brackets, because Chrome's "Failed to load resource" message has the URL only in its location. **Not bugs, never recorded:** `net::ERR_ABORTED` (the browser cancelled the request itself; Next aborts prefetch and RSC fetches when a navigation supersedes them), and the `/favicon.ico` 404. Full Chrome (headed, UI mode, `channel: "chromium"`) asks for the icon, the headless shell doesn't, and the 404 surfaces only as a console error (verified). Removed in M1.11 (app/icon.svg). **Rule: links on a tested page point only to built routes.** Next prefetches every visible `<Link>`, and an unbuilt route's 404 fails the test. The M1.15 header must follow this (link only built pages, or render the rest as non-links until they exist). **Opting out**, for a test that provokes an error on purpose: `test.use({ expectedIssues: [/\/missing\b/] })` drops every issue that matches a pattern (match the URL, because a 404 gives both an `HTTP 404: <url>` line and a console line; no `g` flag), or clear the list mid-test with `pageIssues.length = 0`. Specs import `test` and `expect` from `./fixtures`, not from `@playwright/test`. The fixture's callback parameter is named `provide`, because ESLint's React Hooks rule flags a function named `use`.
- **Screenshot harness** (`support/screenshot.ts`, driven by `screenshots.spec.ts`): `captureRoute()` waits for `load` and `document.fonts.ready`, then saves a full-page shot with `animations: "disabled"` (CSS animations, transitions and Web Animations) and `caret: "hide"` to `path.join(testInfo.project.outputDir, "screenshots", "<route>-<project>.png")`, so the location doesn't depend on the cwd. `outputDir` is `test-results`, resolved against the config file, so the final path is **`C:\Projects\starflame\test-results\screenshots\<route>-<project>.png`**, e.g. `home-mobile-390.png`. The route `/` gives `home`, and `/shop/gift-sets` gives `shop-gift-sets`. It saves at `scale: "css"`, so the image is 390 or 1440 px wide and maps 1:1 to spec pixels. Pass `{ scale: "device" }` for a DPR-3 detail shot. Playwright clears `test-results/` at the start of each run, so stale shots never linger, and a partial run keeps only its own shots. Future pages add one entry to `ROUTES`. **Limits for later:** `animations: "disabled"` does not freeze GSAP (it is driven by rAF), and ScrollTrigger reveals stay hidden in a full-page shot. M1.19 must define a test hook (e.g. jump the timelines to their end state) or a "motion settled" signal. The harness's job is not to hide that.
- **No `toHaveScreenshot` baselines yet.** The design changes in every M1 task, so baselines would be re-approved on every build and would catch nothing. They are also platform-specific (Windows font rendering ≠ Linux CI), so they would need a snapshot set per OS. QA compares against the spec, not against yesterday's build. Revisit after the M2 gate, for stable components only, with a tolerance.
- **Accessibility helpers** (`support/keyboard.ts`): `tabOrder(page)` returns `tag:name` for each Tab stop. `hasVisibleFocus(locator)` reads the computed outline and box-shadow layers while the element is blurred and again while it is focused (after its CSS transitions finish). It returns true only if focus adds a visible layer. A layer is visible if its colour isn't transparent or zero-alpha (`rgba(…, 0)`, `oklch(… / 0)`) and it has a non-zero width (outline) or a non-zero offset, blur or spread (shadow). So Tailwind's resting `0 0 #0000`, `ring-0`, a transparent outline and a `shadow-*` that doesn't change on focus all read false. A ring drawn with a border or a pseudo-element also reads false, so check the screenshot. Call it before any mouse interaction in the test, because `:focus-visible` may not match a scripted focus after a click. Verified on a scratch page: the order was as expected; the UA ring, a Tailwind-style `focus-visible` ring (oklch, with a 150 ms transition), a ring added on top of a resting shadow and a solid outline read true; `outline: none`, a fake `0 0 #0000` ring, `ring-0`, a transparent outline, an unchanged `shadow-*`, and zero-alpha `oklch`/`rgba` rings read false. Pages adopt them from M1.13 on. **Option for the orchestrator to ask the user about:** `@axe-core/playwright` (automated WCAG scan per route). It is a new dependency, so it is not added here.
- **Scripts:** `test:e2e`, `test:e2e:ui` (Playwright UI mode, for humans; it opens a window), and `test:e2e:install` (Chromium only, `--no-remove`). There is no headed variant: UI mode covers that, and agents can't watch a window anyway. HTML reporter: `open: "never"`. The default opens a report server on failure, which would hang `emulators:exec`. **.gitignore: no change.** It already has `/test-results/`, `/playwright-report/`, `/blob-report/` and `/playwright/.cache/`. ESLint and Prettier already ignore the first two. The root tsconfig already includes `playwright.config.ts` and `tests/**`, so tsc and `next build` type-check them.

**tests/e2e/fixtures.ts**
```ts
import { test as base, expect } from "@playwright/test";

// Not a bug, so never recorded: net::ERR_ABORTED, the browser cancelling a
// request itself (Next aborts prefetch and RSC fetches when a navigation
// supersedes them).
const IGNORED_FAILURE = /net::ERR_ABORTED/;

/**
 * Every test fails if the page logs a console error, throws an uncaught error,
 * or has a failed request or an HTTP status >= 400 (same origin or not).
 * Links on a tested page must point only to routes that are built: Next
 * prefetches each link, and an unbuilt route's 404 fails the test (M1.15 header).
 *
 * Opting out, for a test that provokes an error on purpose:
 * - `test.use({ expectedIssues: [/\/missing\b/] })` drops each issue that
 *   matches one of the patterns (no `g` flag). Match the URL: a 404 gives both
 *   an "HTTP 404: <url>" line and a "Failed to load resource … [<url>]" line;
 * - or clear the list mid-test with `pageIssues.length = 0`.
 */
export const test = base.extend<{
  expectedIssues: RegExp[];
  pageIssues: string[];
}>({
  expectedIssues: [[], { option: true }],
  pageIssues: [
    // The second parameter is not named `use`: the React Hooks lint rule would flag it.
    async ({ page, expectedIssues }, provide) => {
      const issues: string[] = [];
      page.on("console", (message) => {
        // For "Failed to load resource" the URL is only in the location.
        const source = message.location().url;
        if (message.type() === "error") {
          const where = source ? ` [${source}]` : "";
          issues.push(`console error: ${message.text()}${where}`);
        }
      });
      page.on("pageerror", (error) => {
        issues.push(`page error: ${error.message}`);
      });
      page.on("requestfailed", (request) => {
        const reason = request.failure()?.errorText ?? "unknown";
        if (!IGNORED_FAILURE.test(reason)) {
          issues.push(`request failed: ${request.url()} (${reason})`);
        }
      });
      page.on("response", (response) => {
        const status = response.status();
        if (status >= 400) {
          issues.push(`HTTP ${status}: ${response.url()}`);
        }
      });
      await provide(issues);
      const unexpected = issues.filter(
        (issue) => !expectedIssues.some((pattern) => pattern.test(issue)),
      );
      expect(unexpected, "console errors and failed requests").toEqual([]);
    },
    { auto: true },
  ],
});

export { expect };
```

```ts
import { join } from "node:path";

import type { Page, TestInfo } from "@playwright/test";

/** "/" -> "home", "/shop/gift-sets" -> "shop-gift-sets". */
export function routeSlug(route: string): string {
  const slug = route
    .replace(/[?#].*$/, "")
    .split("/")
    .filter(Boolean)
    .join("-")
    .toLowerCase()
    .replace(/[^a-z0-9-]/g, "_");
  return slug || "home";
}

/**
 * Saves a full-page screenshot to <outputDir>/screenshots/<route>-<project>.png
 * (C:\Projects\starflame\test-results\screenshots\ in this repo) for QA to
 * compare against the spec. Waits for load and web fonts; freezes CSS
 * animations, transitions and the caret. Saved at CSS-pixel size (390 px or
 * 1440 px wide). Pass { scale: "device" } for a DPR-sized image.
 * Playwright clears test-results/ at the start of every run.
 */
export async function captureRoute(
  page: Page,
  testInfo: TestInfo,
  route: string,
  options: { scale?: "css" | "device" } = {},
): Promise<string> {
  await page.waitForLoadState("load");
  await page.evaluate(async () => {
    await document.fonts.ready;
  });
  const file = join(
    testInfo.project.outputDir,
    "screenshots",
    `${routeSlug(route)}-${testInfo.project.name}.png`,
  );
  await page.screenshot({
    path: file,
    fullPage: true,
    animations: "disabled",
    caret: "hide",
    scale: options.scale ?? "css",
  });
  return file;
}
```

**tests/e2e/support/keyboard.ts**
```ts
import type { Locator, Page } from "@playwright/test";

/**
 * Presses Tab up to `max` times and returns a short label for each element that
 * receives focus (tag plus aria-label, text or id), stopping when focus leaves
 * the page or comes back to the first element. Wrap-around is detected by element
 * identity (two controls may share a label); the label is for display only.
 */
export async function tabOrder(page: Page, max = 50): Promise<string[]> {
  const labels: string[] = [];
  for (let i = 0; i < max; i += 1) {
    await page.keyboard.press("Tab");
    const label = await page.evaluate((isFirst) => {
      const w = window as Window & { __tabOrderFirst?: Element };
      const el = document.activeElement;
      if (!el || el === document.body) return null;
      if (isFirst) w.__tabOrderFirst = el;
      else if (el === w.__tabOrderFirst) return null;
      const name =
        el.getAttribute("aria-label") ??
        (el.textContent ?? "").trim().replace(/\s+/g, " ").slice(0, 40);
      return `${el.tagName.toLowerCase()}:${name || el.id}`;
    }, i === 0);
    if (label === null) break;
    labels.push(label);
  }
  await page.evaluate(() => {
    delete (window as Window & { __tabOrderFirst?: Element }).__tabOrderFirst;
  });
  return labels;
}

/**
 * Visible outline and box-shadow layers of the element, once its CSS
 * transitions have finished. Transparent or zero-alpha colours and zero widths
 * don't count, so Tailwind's resting `0 0 #0000` shadows are ignored.
 */
async function ringLayers(locator: Locator): Promise<string[]> {
  return locator.evaluate(async (el) => {
    await Promise.all(
      el
        .getAnimations()
        .filter((animation) => animation instanceof CSSTransition)
        .map((animation) => animation.finished.catch(() => undefined)),
    );
    const alpha = (color: string): number => {
      if (color === "transparent") return 0;
      const slash = /\/\s*([\d.]+)(%?)\s*\)$/.exec(color);
      if (slash) return Number(slash[1]) / (slash[2] ? 100 : 1);
      const rgba = /^rgba\([^,]+,[^,]+,[^,]+,\s*([\d.]+)\)$/.exec(color);
      return rgba ? Number(rgba[1]) : 1;
    };
    const style = getComputedStyle(el);
    const layers: string[] = [];
    if (
      style.outlineStyle !== "none" &&
      parseFloat(style.outlineWidth) > 0 &&
      alpha(style.outlineColor) > 0
    ) {
      layers.push(
        `outline ${style.outlineStyle} ${style.outlineWidth} ${style.outlineColor}`,
      );
    }
    if (style.boxShadow !== "none") {
      // Split the layer list on top-level commas (colours contain commas too).
      let depth = 0;
      let current = "";
      const shadows: string[] = [];
      for (const char of style.boxShadow) {
        if (char === "(") depth += 1;
        if (char === ")") depth -= 1;
        if (char === "," && depth === 0) {
          shadows.push(current.trim());
          current = "";
        } else {
          current += char;
        }
      }
      shadows.push(current.trim());
      for (const shadow of shadows) {
        const color =
          /(?:[a-z-]+\([^)]*\)|#[0-9a-f]+|transparent)/i.exec(shadow)?.[0] ??
          "currentcolor";
        const [x = 0, y = 0, blur = 0, spread = 0] = (
          shadow.replace(color, "").match(/-?[\d.]+px/g) ?? []
        ).map(parseFloat);
        const drawn = x !== 0 || y !== 0 || blur > 0 || spread > 0;
        if (drawn && alpha(color) > 0) layers.push(`shadow ${shadow}`);
      }
    }
    return layers;
  });
}

/**
 * True if focusing the element adds a visible outline or box-shadow layer that
 * it doesn't have while blurred. A ring drawn with a border or a pseudo-element
 * reads false: check the screenshot. Call it before any mouse interaction in the
 * test, since `:focus-visible` may not match a scripted focus after a click.
 */
export async function hasVisibleFocus(locator: Locator): Promise<boolean> {
  await locator.evaluate((el) => (el as HTMLElement).blur());
  const blurred = new Set(await ringLayers(locator));
  await locator.focus();
  const focused = await ringLayers(locator);
  return focused.some((layer) => !blurred.has(layer));
}
```
