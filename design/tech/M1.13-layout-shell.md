## 1. Decisions

- **Route structure.** `app/page.tsx` moves to `app/(site)/page.tsx` (no `<main>` of its own: its h1 in a plain `Section` + `Container`). `app/(site)/layout.tsx` renders `<SiteShell>`. `/dev` stays outside the group. The root layout adds the `viewport` export (`width=device-width, initial-scale=1, viewport-fit=cover`, `themeColor #0b0f24`, `colorScheme dark`; never `maximumScale`/`userScalable`) and renders `<SkipLink />` first in `<body>`, then the sprite. The dev token page's `<main>` gets `id="main" tabIndex={-1}` (and `w-full`, since `<body>` is now a flex column and `mx-auto` would shrink it to its content).
- **Components (`components/layout/`, all Server Components except where noted).** `SiteShell` (fragment: `StarfieldSlot`, `SiteHeader`, `<main id="main" tabIndex={-1} class="relative z-(--z-content) flex-[1_0_auto]">`, `SiteFooter`), `SkipLink`, `StarfieldSlot`, `Container` (`content` | `prose`), `Section` (`band`, `labelledBy`), `SectionHeading`, placeholder `SiteHeader` / `SiteFooter`, and three shared content pieces: `PageMessage` (one plain section, prose container, h1 styled `type-h2`, paragraph, actions 24px below), `NotFoundContent` (+ the shared `NOT_FOUND_TITLE` constant) and `ErrorContent` (no server-only code, so the client error boundaries can import it).
- **Skip link.** A plain `<a href="#main" class="skip-link …">`: its visible styles are ordinary utilities (fixed, `top: calc(env(safe-area-inset-top) + 8px)`, `inset-inline-start: --page-inline-start`, `z-(--z-skip-link)`, 44px min height, padding 12/24, `type-button`, bg-overlay, 1px border-ghost, pill, shadow-overlay) and `not-focus:sr-only` hides it whenever it is **not** `:focus` (variant utilities sort after base ones, so `position: absolute` from `sr-only` wins at rest and `fixed` applies on focus). No motion. `.skip-link` is also the print hook.
- **Tokens and base (`globals.css`).** Section 4 adds `--header-h` (4 / 4.5 / 4.5 / 5rem), `--scroll-offset`, `--page-inline-start/-end` exactly as tokens.md §9.1, plus `@custom-variant short (@media (max-height: 28rem))`, used as `@variant short { --scroll-offset: 0px }` in `:root` and as `short:relative` on the header. Base: `html { scroll-padding-top: var(--scroll-offset) }`; `body` flex column with `min-height: 100svh` only. **No `100vh` fallback:** Tailwind 4 builds with Lightning CSS targeting Safari 16.4+, Chrome 111+ and Firefox 128+, which all support `svh`, so the optimizer removed the `100vh` line from the output anyway (the prototype's built CSS had only `min-height:100svh`); the source no longer pretends otherwise; `#main:focus, #main:focus-visible { outline: none }` and `#main { scroll-margin-top: 0 }`.
- **Layout recipes.** `@utility page-container` (width 100%, auto margins, `--page-inline-*` padding, `max-width: calc(--container-content + both paddings)`, so the content box caps at 1280) is used by `Container` and the header/footer bars. `@utility page-grid` (4 / 8 / 12 columns of `minmax(0, 1fr)`, `--grid-gap`, children `min-width: 0`) is the grid recipe; a `@utility` is emitted only once used, so it costs nothing until a page uses it (verified working in the prototype: 4/8/12 columns at 390/768/1440). `@source not inline("container")` stops comment prose ("page container") from emitting Tailwind's unused `.container` (181 B).
- **Container widths (fix round 1, QA issue 1).** `Container variant="prose"` wraps its children in `mx-auto max-w-(--container-prose)`, which emits `max-width: var(--container-prose)` and pulls `--container-prose: 42.5rem` into `:root`. **Never `max-w-prose`:** Tailwind 4 keeps a built-in static `max-w-prose` = `max-width: 65ch` that beats the `--container-prose` theme key, and `ch` follows the font (702px with Jost, 624.7px with the fallback). Checked every container key against `w-`, `min-w-` and `max-w-` with Tailwind's own compiler and this theme: only `max-w-prose` collides; `max-w-content`, `max-w-wide` and `max-w-measure-{prose,intro,heading}` (and every `w-`/`min-w-` form, `w-prose` included) resolve to `var(--container-*)`. The shell uses only `max-w-(--container-prose)`, `max-w-measure-prose`, `max-w-measure-intro` and the `page-container` recipe (`var(--container-content)`); the dev page uses `max-w-content`. Comments don't spell the colliding class either (the scanner would emit it from a comment); the built CSS has no `.max-w-prose{`.
- **Bands** live in `@layer components` as `[data-band]` rules (relative, `isolation: isolate`, `overflow: clip`, `padding-block: --section-y`; solid/sunken/haze backgrounds; dusk = `--gradient-haze-dusk`), so a page's utilities still override them (a hero's own top spacing). **Padding collapse (post-pass minor 7):** `:is(plain, solid) + :is(plain, solid)` and `sunken + sunken` drop `padding-block-start`. Haze-family bands are never adjacent, so no rule. A dusk band that wants veil/blush layers passes them via `className` (page specs).
- **SectionHeading (minor 1).** DOM order hgroup, link, intro. Row: `flex flex-col items-start gap-2` → `md:flex-row md:flex-wrap md:justify-between md:items-baseline-last md:gap-x-6`; intro `mt-4` below the row; wrapper `mb-12`. **One addition:** the hgroup gets `md:flex-[1_1_20rem]`. With `flex-wrap` and the default `flex-basis: auto`, the hgroup's hypothetical width is the h2's max-content, so **any heading long enough to wrap pushed the link onto its own line** (measured at 768: link 8px below the h2). With a 20rem basis the hgroup grows to fill, the link stays on the row and wraps only when the row can't hold 320px + 24px + the link. Measured with zero-size baseline markers: h2 last-line baseline = link baseline (372.0 / 372.0 at 768 with a two-line h2; 459.4 / 459.4 at 1440); base: link 8px under the h2, intro 16px under the row. The link: `type-nav`, `text-link`, underline 1px at 0.2em offset, 44px min height, 16px inline arrow SVG (`aria-hidden`, currentColor), hover `link-hover`; eyebrow gold-400 (`tone="dusk"`: gold-300).
- **Header placeholder (M1.15 replaces the content).** `<header class="sticky top-0 z-(--z-header) pt-[env(safe-area-inset-top)] short:relative">` with a `page-container` bar of `h-(--header-h)` holding the wordmark home link (`text-wordmark`, hover text-primary, 44px). The scrolled surface (bg-raised, shadow-raised, 1px border-divider) is a `::before` at `inset: 0; z-index: -1` (out of flow, so it never changes the 64/80px box). **Until M1.15's scroll-state island exists it is always on**: without the island the header could never turn opaque, and content scrolls under it. M1.15 changes it to `opacity: 0` + `data-scrolled`. Forced colors: `body > header { background-color: Canvas }`.
- **Footer placeholder (M1.17 replaces the content).** `relative z-(--z-content) bg-bg-sunken`, 48px top padding, 48px + `env(safe-area-inset-bottom)` bottom; footer-size wordmark (gold-300) and `© {build year} Starflames` (type-body-sm, text-secondary 11.78:1). Static, so the year is the build's.
- **Starfield slot.** `<div data-starfield="" data-decorative="" aria-hidden="true" class="pointer-events-none fixed inset-x-0 top-0 z-(--z-starfield) h-lvh">`, empty (empty strings, so the markup matches §8.1; React would print `"true"` for a bare boolean).
- **Not found (minor 3).** `app/not-found.tsx` wraps `NotFoundContent` in `SiteShell` and exports `metadata = { title: NOT_FOUND_TITLE }`. `app/(site)/not-found.tsx` renders `NotFoundContent` only and sets **no** title: per the amended §10 the calling page's `generateMetadata` returns `NOT_FOUND_TITLE` (no M1.13 route calls `notFound()`). The unmatched URL serves the shell with `<title>Page not found · Starflames</title>` (status 404). **The plain-build `/dev/tokens` gate does not:** `requireDevPages()` calls `notFound()` inside the `/dev` segment, a nested not-found, so (as in §4.2) the prerendered `tokens.html` is Next's `<html id="__next_error__">` document with an empty body (status 404, `<title>Page not found · Starflames</title>`, no token-page content); the shell and the not-found text exist only in the RSC payload and appear after hydration. Acceptable for a dev-only gate: it hides the page, which is its job.
- **Errors (minor 2).** `app/(site)/error.tsx` and `app/error.tsx` (`'use client'`) render `ErrorContent` and set **no** title (the layout's stays). `app/error.tsx` brings its own `<main id="main" tabIndex={-1}>`. `app/global-error.tsx` imports `globals.css` and `{ jost, cormorant, cormorantItalic }` from `./fonts`, renders `<html lang="en" className={…three .variable classes}>`, a React `<title>Something went wrong · Starflames</title>` and `<main id="main" tabIndex={-1}>`, no skip link. The `app/fonts.ts` comment now names both importers. "Try again" calls Next's **`retry`** prop (see §4.1). Verified with prototype-only probes (removed): an in-page throw renders inside the shell (banner + contentinfo, title "Starflames", status 500); a root-layout throw renders global-error with Jost/Cormorant resolved, bg-page, one `<title>` "Something went wrong · Starflames".
- **Print (minor 8)** is new section 9: hide `[data-decorative]`, `.skip-link`, `[data-print="hide"]`; `color-scheme: light`; `color: #000; background: transparent; box-shadow: none; text-shadow: none` (all `!important`) on everything; `body { display: block; min-height: 0 }`; header `position: static` and its `::before` surface removed; `main` and the footer `z-index: auto`; links underlined; `img, svg { max-width: 100% }`.
- **Screenshot harness (fix round 1, QA issue 2; header.md §3.4, starfield.md §13.2).** The single definition: `captureRoute(page, route, testInfo, options?: { scale?: "css" | "device", name?: string, fullPage?: boolean, animations?: "disabled" | "allow" })`. `name` replaces `routeSlug(route)` in the file name (`<name>-<project>.png`); `fullPage` defaults to `true` and `animations` to `"disabled"` (today's behaviour). ## 4. Notes and pushback

1. **PUSHBACK (minor): `reset()` → `retry()`.** layout-shell.md §10 says "Try again calls `reset()`". In Next 16.4 `retry` is the stable prop (16.3+) that re-fetches and re-renders the segment; the bundled docs say "In most cases, you should use `retry()`", and `reset()` only re-renders the same (failed) server payload, so it can't recover a Server Component error. The build uses `retry`. design-agent: change the word in §10.
2. **Finding for M3/M4 (design-agent, §10 (b)).** In Next 16.4 a `notFound()` thrown by a `(site)` page **at request time** is not server-rendered into the shell: the response is 404 with Next's `<html id="__next_error__">` document (empty body) and the not-found UI appears only after hydration. With `app/(site)/not-found.tsx` present, that HTML's `<title>` is the layout's "Starflames"; the `generateMetadata` title shows only client-side (checked in a browser: one `<title>`, correct after hydration). Without JavaScript the visitor sees an empty page. **Verified alternative:** product/collection routes that use `generateStaticParams` with `export const dynamicParams = false` serve unknown slugs the static root 404, fully server-rendered with the shell and "Page not found · Starflames". Recommend that pattern (plus a re-seed rebuild) for M3/M4; nothing in M1.13 calls `notFound()`.
3. The header placeholder's surface is always opaque until M1.15 (§1); the footer wordmark is a plain image, not a link (M1.17 decides).
   **The same mechanism covers the plain-build `/dev/tokens` gate** (fix round 1, QA issue 4): its 404 is the empty `__next_error__` document, not the server-rendered shell (§1 Not found). Fine for a dev-only gate; no change.
4. Unchanged and not touched: `app/hero-pending.ts`, `<html suppressHydrationWarning>`, the dev gate and `dev.css`.

```tsx
import type { Metadata, Viewport } from "next";

import { WordmarkSprite } from "@/components/brand/Wordmark";
import { SkipLink } from "@/components/layout/SkipLink";

import { cormorant, cormorantItalic, jost } from "./fonts";
import { HERO_PENDING_SCRIPT } from "./hero-pending";
import "./globals.css";

export const metadata: Metadata = {
  title: "Starflames",
};

// layout-shell.md §6.4: edge to edge on notched phones (the shell pads every edge
// with the safe-area insets); the browser chrome matches bg-page. Never
// maximumScale or userScalable: zoom must always work.
export const viewport: Viewport = {
  width: "device-width",
  initialScale: 1,
  viewportFit: "cover",
  themeColor: "#0b0f24",
  colorScheme: "dark",
};

// Every route under this layout, /dev included, gets the skip link, so every
// layout or page below renders exactly one <main id="main" tabIndex={-1}>.
export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    // suppressHydrationWarning: the head script adds `hero-pending` to <html>
    // before React hydrates (motion.md §5.1). It applies to <html>'s own
    // attributes only, not to its children.
    <html
      lang="en"
      className={`${jost.variable} ${cormorant.variable} ${cormorantItalic.variable}`}
      suppressHydrationWarning
    >
      <head>
        <script dangerouslySetInnerHTML={{ __html: HERO_PENDING_SCRIPT }} />
      </head>
      <body>
        <SkipLink />
        <WordmarkSprite />
        {children}
      </body>
    </html>
  );
}
```

**tests/e2e/support/layout-shift.ts**
```ts
import type { Page } from "@playwright/test";

type Rect = { x: number; y: number; width: number; height: number };

/** One layout-shift entry and the nodes that moved (layout-shift `sources`). */
export type Shift = {
  value: number;
  startTime: number;
  sources: { node: string; previousRect: Rect; currentRect: Rect }[];
};

/**
 * Every layout-shift entry without recent input, once the fonts have settled,
 * with its sources: a short selector path for each moved node ("" if the node
 * is gone) and its rects. layout-shift entries are only exposed to a buffered
 * PerformanceObserver.
 */
export async function layoutShifts(
  page: Page,
): Promise<{ total: number; shifts: Shift[] }> {
  return page.evaluate(async () => {
    await document.fonts.ready;
    // tag#id[data-*] for the node and up to three ancestors, nearest last.
    const describe = (node: Node | null | undefined): string => {
      const parts: string[] = [];
      let el: Element | null =
        node instanceof Element ? node : (node?.parentElement ?? null);
      if (node && !(node instanceof Element)) parts.push(node.nodeName);
      for (let depth = 0; el && depth < 4; depth++, el = el.parentElement) {
        const data = [...el.attributes]
          .filter((a) => a.name.startsWith("data-"))
          .map((a) => `[${a.name}]`)
          .join("");
        parts.unshift(
          `${el.tagName.toLowerCase()}${el.id ? `#${el.id}` : ""}${data}`,
        );
      }
      return node ? parts.join(" > ") : "";
    };
    const rect = (r: DOMRectReadOnly): Rect => ({
      x: r.x,
      y: r.y,
      width: r.width,
      height: r.height,
    });
    return new Promise<{ total: number; shifts: Shift[] }>((resolve) => {
      const shifts: Shift[] = [];
      new PerformanceObserver((list) => {
        for (const entry of list.getEntries() as (PerformanceEntry & {
          value: number;
          hadRecentInput: boolean;
          sources: {
            node?: Node | null;
            previousRect: DOMRectReadOnly;
            currentRect: DOMRectReadOnly;
          }[];
        })[]) {
          if (entry.hadRecentInput) continue;
          shifts.push({
            value: entry.value,
            startTime: entry.startTime,
            sources: entry.sources.map((s) => ({
              node: describe(s.node),
              previousRect: rect(s.previousRect),
              currentRect: rect(s.currentRect),
            })),
          });
        }
      }).observe({ type: "layout-shift", buffered: true });
      setTimeout(
        () =>
          resolve({
            total: shifts.reduce((sum, s) => sum + s.value, 0),
            shifts,
          }),
        500,
      );
    });
  });
}

/** Sum of layout-shift values (without recent input) once the fonts have settled. */
export async function layoutShift(page: Page): Promise<number> {
  return (await layoutShifts(page)).total;
}
```

```ts
  route: string,
  testInfo: TestInfo,
  options: CaptureOptions = {},

    animations: options.animations ?? "disabled",
```
