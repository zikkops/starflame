## 1. Decisions

**Default deny and no admin client paths.** Neither rules file has a catch-all: any path that isn't matched is refused (tested for `misc/x` and `users/alice/wishlist/x`). The Admin SDK (server code, the M1.8 seed, Functions) bypasses the rules. **No Firestore rule reads the `admin` claim.** Admin work (M7) runs in server code that verifies the ID token's `admin` claim, then writes with the Admin SDK, because derived fields need `deriveProductFields`. So the M1.4 §3 line "drafts too with `admin == true`" is dropped: no client reads drafts (M7 previews go through the server). The claim appears only in the Storage write rule, read as `request.auth.token.get('admin', false) == true`. A missing claim is then `false` instead of an evaluation error (a plain `token.admin` logged "Property admin is undefined" on every non-admin request), and the string `"true"` is refused (tested).

| Path | Client read | Client write | Validation |
|---|---|---|---|
| `products/{slug}`, `collections/{slug}` | anyone, when `resource.data.status == 'published'` | none, admin included | — |
| `users/{uid}` | owner: `get` only (no list) | owner: create and update; no delete (account deletion is server-side, M5) | exact key set `displayName, defaultShippingAddress, createdAt, updatedAt`; `displayName` null or 1–80; the address has exactly the 8 keys, sized like `addressParser`, and `country` matches `^[A-Z]{2}$`; `createdAt == request.time` on create and unchanged on update; `updatedAt == request.time` on every write |
| `users/{uid}/cart/{sku}` | owner: get and list | owner: create, update, delete | exact keys; `sku == {sku}`; slug-pattern `sku` (≤100) and `productSlug` (≤80); `quantity` is an int from 1 to 10; `addedAt` as `createdAt`; `updatedAt == request.time`; **then** one `get()` of `products/{productSlug}`: `status == 'published'` and `sku in skus` |
| `orders/{orderId}` | signed in and `resource.data.userId == request.auth.uid` | none | — |
| `newsletterSignups/{emailHash}` | none | create only, by anyone (signed in or not) | exact keys; `email` a string of ≤254 characters, `== email.trim().lower()`, matching `EMAIL_PATTERN`; `{emailHash} == hashing.sha256(email).toHexString().lower()`; `source in ['home','footer']`; `consentVersion` 1–40; `createdAt == request.time` |
| Storage `products/**` | anyone: `get` only (download and metadata); no list, at any level | admin claim only, at `products/{slug}/{file}` (one level) | `slug` `^[a-z0-9-]+$`; `file` `^[a-z0-9-]+[.](png|jpe?g|webp|avif)$`; `contentType` in png/jpeg/webp/avif; `size < 10 × 1024 × 1024` B. Delete: admin only |

- **Published-only catalog reads, in both layers.** The rules enforce `status == 'published'`. A client list must carry `where("status", "==", "published")`, or the whole query is denied (tested both ways). The Admin SDK bypasses the rules, so **M1.6 repositories must still filter** (M1.4 §3, with a test there). A `get` of a missing product is denied, because there is no `resource` to check. No client relies on it: the client converters don't read the catalog at all.
- **Orders.** A list must filter `where("userId", "==", uid)` (the `orders (userId, createdAt desc)` index). A guest order has `userId == null`, which can never equal a uid, so guest orders are never client-readable: not by `get`, and not by a `where("userId", "==", null)` list (tested). Guests read through the M6 server route (token hash, Admin SDK).
- **Newsletter.** It is create-only. A second signup of the same address targets an existing document, so it is an *update*, which no rule allows: `PERMISSION_DENIED`, the same error as every other refusal. The UI shows its success message for it (M2.6/M2.7). The rules' SHA-256 of the UTF-8 email equals `emailHash()` (Web Crypto) for a non-ASCII address too (tested with "zoë"). **NFC accepted risk, now documented by a test:** the NFD form of a stored NFC address passes trim and lowercase, hashes differently, and is stored as a second document. Our client normalises first, so the same NFD input typed into our form maps to the NFC hash and is denied as a duplicate (tested).
- **Storage.** `products/**` is public `get` (any depth, so the M1.8 layout can't lock itself out), and **not list**. A list of `products/` would reveal every slug folder, drafts included, and from there their images (QA P108/P109). With `get` only, `listAll` of `products/`, of a product folder or of the bucket root is denied for every persona, admin included (tested); M7 lists through the Admin SDK. An image is still served to anyone who has its exact path, a draft's too (tested): that is what `next/image` needs. A draft's image path can be guessed, since names follow `products/<slug>/<id>.<ext>`. So an image uploaded for an unannounced product is effectively public. This is accepted and noted for M7: upload such images only when early exposure is acceptable, or keep draft previews out of `products/` and serve them through the server. Everything else is denied, for reads too (tested with `_private/notes.txt`). The allowlist adds `image/avif` (acceptance criterion 2). So that the stored data can use it, the `storagePath` guard in `lib/domain/schemas.ts` gains `avif` (one regex change; the guard and the rules then accept the same file names). Extension–type pairing isn't enforced: the uploader is the admin, and the type is what Storage serves.

**Cart: the 20-line limit and the `get()` budget.** Each cart rule makes exactly one document access, `get(/products/$(productSlug))`, and only after every cheap check has passed (`&&` short-circuits). Delete and read make none. A batched write may make 20 document accesses, and repeated `get()`s of one document count once. So a sign-in merge of 20 lines over 20 distinct products passes. A 21st distinct product is denied, although each line is valid on its own: both 20-line halves of the same 21 pass (tested). An extra `exists()` in the cart rules makes the 20-line test fail (mutation run). Rules can't count a subcollection, so I rejected a **counter on `users/{uid}`**. Each line rule would need `getAfter(/users/$(uid))`, which takes the 20-line merge to 21 accesses. It would also put a profile write into the merge batch (M1.4 §1 forbids that), and keeping it exact would need a transaction for every quantity change. **Approach:** the limit is enforced where the lines are made and used:
1. The client cart state (M5.4) refuses a 21st distinct SKU. The sign-in merge (M5.5) **reads the server cart first** and merges the guest lines into it, to at most `CART_LIMITS.maxLines` lines. For a line that already exists on the server, it keeps the stored `addedAt` (or writes only `quantity` and `updatedAt`), because the update rule refuses a changed `addedAt`. It clamps every merged quantity to `CART_LIMITS.maxQuantityPerLine` (10). It also drops unknown or unpublished SKUs before committing, because one invalid line makes the whole atomic batch fail. Then it commits **one batch of cart-line writes only**.
2. The checkout Function (M6) refuses more than 20 lines (`parseOrder` already caps `lines` at 20).
3. The rules check every write: each line is a real, published SKU with a quantity of 1–10, and one batch can't touch more than 20 distinct products.

A raw-API caller can still write more lines, one batch at a time, but only into their own cart and only for real published SKUs, so the total is bounded by the catalog (≤200 products × ≤10 SKUs, about 100 B each). A test records this: 21 lines over 20 products pass the rules. **For M5:** read the cart with `orderBy("addedAt")` and `limit(CART_LIMITS.maxLines)` (a single-field order, so no composite index), so extra lines never reach the UI.

**Indexes.** These are the five composite indexes from M1.4 §1, plus the optional single-field exemptions it suggested (`"indexes": []`) for large or deep fields that no query uses: `products.longDescription, variants, images, cardImage, scentNotes` and `orders.lines, statusHistory, shippingAddress`. No M3 query, and none in the scale-out plan (`collectionSlugs`, `type`, `priceFrom`, `scentFamilies`, `sizeKeys`), touches an exempted field. The Firestore emulator neither loads nor enforces `firestore.indexes.json`; only a deploy uses it, and deploys need user approval. So the file is checked offline with firebase-tools' own validator, as `firebase deploy` runs it (§5.1 step 5). It passes (5 indexes, 8 overrides), and a deliberately bad `order` is rejected.

**Rules tests.** They use `node:test` + tsx, as `test:unit` does, under `firebase emulators:exec --only firestore,storage`, which loads both rules files from `firebase.json`. The tests don't pass rules themselves, so they check exactly what the emulator loaded. `--test-concurrency=1` is needed because the files share one emulator and each clears it in `before()`. There are six files plus `support/env.ts`. Each collection is tested with four personas: `anonymous`, `owner` (alice), `other` (bob) and `admin` (`{ admin: true }` claim). Catalog fixtures are the real derived catalog (`deriveCatalog`), so the rules run against the real `skus[]`. **Exit:** `after()` calls `testEnv.cleanup()`, which deletes every app and closes the gRPC streams, so each file's process exits by itself with code 0. There is no forced exit, and the 0xC0000409 crash from M1.4 never appeared in any of the 23 prototype runs. `setLogLevel("error")` silences the SDK's log line for each expected denial.

**Carried M1.4 QA minors.** (a) In the `lib/types` + `lib/domain` ESLint block, `no-restricted-syntax` bans `ImportExpression` (dynamic `import()`, any specifier, relative too) and `TSImportType` (`import("x").T` types, which `no-restricted-imports` also misses). `require()` is already an error through `@typescript-eslint/no-require-imports`. (b) M1.4 §6.1 step 6 now reads "232 passed / 30 skipped". (c) The `app`/`components`/`lib` block (everything outside `lib/firebase`) had the same gap for Firebase, because `no-restricted-imports` doesn't see a dynamic `import("firebase/firestore")`. Its `no-restricted-syntax` now bans `ImportExpression` and `TSImportType` whose specifier matches `^(firebase|firebase-admin)(\/|$)|^@firebase\/|^@google-cloud\/`, the same specifiers as its static pattern. Other dynamic imports, such as `next/dynamic` targets and relative modules, stay allowed. For `lib/types` and `lib/domain`, the later block's rule options replace this one (flat config doesn't merge them), so their full `ImportExpression` ban stays. A template-literal or computed specifier isn't matched (there is no string to test). Code review covers that case. No such import exists today, so the rule changes no current lint result.

**Not in scope / follow-ups.** App Check and a newsletter Function (the M2.7 upgrade path); `orders (status, createdAt desc)` (M7); Storage paths for anything besides product images (none yet).

**firestore.rules**
```js
rules_version = '2';

// Starflames Firestore rules (M1.5, design/tech/M1.5-security-rules.md).
// Default deny: any path not matched below is refused. The Admin SDK (server code, seed,
// Cloud Functions) bypasses these rules. No client path uses the `admin` claim: admin work
// runs in server code that checks the claim, then writes with the Admin SDK (M7).
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() {
      return request.auth != null;
    }

    function isOwner(uid) {
      return signedIn() && request.auth.uid == uid;
    }

    // Mirrors SLUG_PATTERN (lib/domain/ids.ts).
    function isSlug(value, maxSize) {
      return value is string && value.size() <= maxSize
        && value.matches('^[a-z0-9]+(-[a-z0-9]+)*$');
    }

    // A string of 1..maxSize characters (the guards' str({ max })).
    function isText(value, maxSize) {
      return value is string && value.size() >= 1 && value.size() <= maxSize;
    }

    function isNullableText(value, maxSize) {
      return value == null || isText(value, maxSize);
    }

    function hasExactly(data, fields) {
      return data.keys().hasAll(fields) && data.keys().hasOnly(fields);
    }

    // ---- Catalog: public read of published documents, never client-written ----
    // A list query must filter on status == "published", or the whole query is denied.

    match /products/{slug} {
      allow read: if resource.data.status == 'published';
    }

    match /collections/{slug} {
      allow read: if resource.data.status == 'published';
    }

    // ---- users/{uid}: the owner's profile (UserProfile, lib/types/user.ts) ----

    // Mirrors addressParser (lib/domain/schemas.ts).
    function isAddress(a) {
      return a is map
        && hasExactly(a, ['fullName', 'line1', 'line2', 'city', 'region', 'postalCode',
                          'country', 'phone'])
        && isText(a.fullName, 100)
        && isText(a.line1, 100)
        && isNullableText(a.line2, 100)
        && isText(a.city, 80)
        && isNullableText(a.region, 80)
        && isText(a.postalCode, 20)
        && a.country is string && a.country.matches('^[A-Z]{2}$')
        && isNullableText(a.phone, 30);
    }

    function isProfile(data) {
      return hasExactly(data, ['displayName', 'defaultShippingAddress', 'createdAt', 'updatedAt'])
        && isNullableText(data.displayName, 80)
        && (data.defaultShippingAddress == null || isAddress(data.defaultShippingAddress))
        && data.updatedAt == request.time;
    }

    match /users/{uid} {
      allow get: if isOwner(uid);
      allow create: if isOwner(uid)
        && isProfile(request.resource.data)
        && request.resource.data.createdAt == request.time;
      allow update: if isOwner(uid)
        && isProfile(request.resource.data)
        && request.resource.data.createdAt == resource.data.createdAt;
      // No list, no delete (account deletion runs on the server).

      // ---- users/{uid}/cart/{sku}: one CartLine per document ----
      // get() budget (M1.4 §1): exactly one get(), of the line's product, and only after the
      // cheap checks pass. No other get()/exists() in any cart rule, so a 20-line sign-in merge
      // over 20 distinct products fits the 20-document-access limit of one batched write.
      // Rules can't count a subcollection: the 20-line limit lives in the client and the
      // checkout Function (spec §1 Cart limit).
      function isCartLine(data, sku) {
        return hasExactly(data, ['productSlug', 'sku', 'quantity', 'addedAt', 'updatedAt'])
          && data.sku == sku
          && isSlug(data.sku, 100)
          && isSlug(data.productSlug, 80)
          && data.quantity is int && data.quantity >= 1 && data.quantity <= 10
          && data.updatedAt == request.time;
      }

      function isPublishedSku(data) {
        let product = get(/databases/$(database)/documents/products/$(data.productSlug)).data;
        return product.status == 'published' && data.sku in product.skus;
      }

      match /cart/{sku} {
        allow read: if isOwner(uid);
        allow create: if isOwner(uid)
          && isCartLine(request.resource.data, sku)
          && request.resource.data.addedAt == request.time
          && isPublishedSku(request.resource.data);
        allow update: if isOwner(uid)
          && isCartLine(request.resource.data, sku)
          && request.resource.data.addedAt == resource.data.addedAt
          && isPublishedSku(request.resource.data);
        allow delete: if isOwner(uid);
      }
    }

    // ---- orders: written only by Cloud Functions (Admin SDK) ----
    // A signed-in customer reads only their own orders; a list query must filter on
    // userId == their uid. Guest orders (userId == null) are never readable from a client.

    match /orders/{orderId} {
      allow read: if signedIn() && resource.data.userId == request.auth.uid;
    }

    // ---- newsletterSignups/{emailHash}: create-only, anyone ----
    // The ID must be the SHA-256 of the normalised email, so dedupe can't be bypassed; a
    // duplicate arrives as an update and is denied. NFC is not enforced (accepted risk, M1.4 §1).

    match /newsletterSignups/{emailHash} {
      allow create: if hasExactly(request.resource.data, ['email', 'source', 'consentVersion', 'createdAt'])
        && request.resource.data.email is string
        && request.resource.data.email.size() <= 254
        && request.resource.data.email == request.resource.data.email.trim().lower()
        && request.resource.data.email.matches('^[^\\s@]+@[^\\s@]+[.][^\\s@]+$')
        && emailHash == hashing.sha256(request.resource.data.email).toHexString().lower()
        && request.resource.data.source in ['home', 'footer']
        && isText(request.resource.data.consentVersion, 40)
        && request.resource.data.createdAt == request.time;
    }
  }
}
```

**storage.rules**
```js
rules_version = '2';

// Starflames Storage rules (M1.5, design/tech/M1.5-security-rules.md).
// Default deny: any path not matched below is refused. The Admin SDK (the M1.8 seed, M7
// server code) bypasses these rules.
service firebase.storage {
  match /b/{bucket}/o {

    function isAdmin() {
      return request.auth != null && request.auth.token.get('admin', false) == true;
    }

    // Product images (art-direction §9.2): products/<productSlug>/<imageId>.<ext>.
    // get only: a list would reveal every product folder, drafts included, and their images.
    match /products/{allPaths=**} {
      allow get: if true;
    }

    // Writes: admin claim only, one level deep, names as the storagePath guard
    // (lib/domain/schemas.ts) allows, an image type from the allowlist, under 10 MB.
    match /products/{slug}/{file} {
      allow create, update: if isAdmin()
        && slug.matches('^[a-z0-9-]+$')
        && file.matches('^[a-z0-9-]+[.](png|jpe?g|webp|avif)$')
        && request.resource.contentType in ['image/png', 'image/jpeg', 'image/webp', 'image/avif']
        && request.resource.size < 10 * 1024 * 1024;
      allow delete: if isAdmin();
    }
  }
}
```

**tests/rules/support/env.ts**
```ts
import {
  initializeTestEnvironment,
  type RulesTestContext,
  type RulesTestEnvironment,
} from "@firebase/rules-unit-testing";
import { setLogLevel, type Firestore } from "firebase/firestore";
import type { FirebaseStorage } from "firebase/storage";

/**
 * Shared set-up for the rules tests. `npm run test:rules` runs them under
 * `firebase emulators:exec --only firestore,storage`, which loads firestore.rules and
 * storage.rules from firebase.json and sets the emulator hosts; the library finds them
 * through the hub. Rules are not passed here, so the tests check what the emulator loaded.
 */
export const PROJECT_ID = "demo-starflames";

/** The four personas every collection is tested with. */
export type Persona = "anonymous" | "owner" | "other" | "admin";
export const PERSONAS: readonly Persona[] = [
  "anonymous",
  "owner",
  "other",
  "admin",
];
/** The owner persona's uid; "other" is a second customer, "admin" carries the claim. */
export const OWNER_UID = "alice";
export const OTHER_UID = "bob";
export const ADMIN_UID = "admin-1";

export type RulesEnv = {
  readonly env: RulesTestEnvironment;
  readonly as: (who: Persona) => RulesTestContext;
};

export async function setUpRulesEnv(): Promise<RulesEnv> {
  if (!process.env.FIREBASE_EMULATOR_HUB) {
    throw new Error(
      "Run the rules tests with `npm run test:rules` (firebase emulators:exec).",
    );
  }
  // Denied writes are the point of most tests; keep the SDK from logging each one.
  setLogLevel("error");
  const env = await initializeTestEnvironment({ projectId: PROJECT_ID });
  const contexts: Record<Persona, RulesTestContext> = {
    anonymous: env.unauthenticatedContext(),
    owner: env.authenticatedContext(OWNER_UID),
    other: env.authenticatedContext(OTHER_UID),
    admin: env.authenticatedContext(ADMIN_UID, { admin: true }),
  };
  return { env, as: (who) => contexts[who] };
}

/**
 * The library hands out compat instances. Each wraps a modular instance (`_delegate`), which
 * the modular functions (doc, setDoc, ref, uploadBytes...) unwrap with getModularInstance.
 * The casts only bridge the two type families; the runtime objects are the documented usage.
 */
export function firestoreOf(ctx: RulesTestContext): Firestore {
  return ctx.firestore() as unknown as Firestore;
}
export function storageOf(ctx: RulesTestContext): FirebaseStorage {
  return ctx.storage() as unknown as FirebaseStorage;
}

/**
 * Deletes every app the environment created. Call it in `after()`: it closes the client SDK's
 * streams, so the test process exits on its own (a forced exit with an open gRPC stream crashed
 * with 0xC0000409 in the M1.4 probe).
 */
export async function tearDown(rules: RulesEnv): Promise<void> {
  await rules.env.cleanup();
}
```
